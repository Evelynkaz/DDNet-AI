Код исходника (коммит `c3c619d`, совпадает с upstream) остаётся в репозитории до прохождения паритета Rust-заменой.

## 1. Общая картина

- **Размер:** ~23,2k строк TS в `src/` + `start.mjs` (22 КБ) + Electron `app/`. Комментариев и тестов нет, tsconfig нет:
  Node 24 запускает `.ts` напрямую (type stripping). Зависимости: `teeworlds` 2.6.1 (MIT, сеть), `ink`/`react` (TUI).
- **Процесс:** `run.sh` → `node start.mjs` (мастер-вопросы, `settings.json`, авто-сервер, веб-UI на 127.0.0.1:7777,
  дамми, автообновление) → `DdnetBot` (`src/bot/bot.ts`, 5004 строки, «божественный класс»). Код выхода 75 =
  перезапуск (смена сервера, обновление). `src/bot/main.ts` — упрощённый CLI-вход.
- **Такт:** сервер DDNet — 50 тиков/с, снапшоты — 25 Гц (каждые 2 тика). Бот принимает **одно решение на собранный
  снапшот**; пачку снапшотов схлопывает (`setImmediate`).

```
UDP (teeworlds 0.6+DDNet) ─► снапшот ─► LiveWorld (мир из снапшота, reckoning)
                                          │
                     эхо-замер лага ◄─────┤
                                          ▼
     pickTarget ─► режим (fight / nav / WB / trek / wander / unstick)
                                          │
        planAction: SimWorld «прокручен» на lag тиков с летящими вводами ─► Planner.decide (CEM)
                                          │                                  └─ shield / edgeHold / polishRope
                                          ▼
                              applyInput ─► NETMSG_INPUT (+ переотправка библиотекой каждые 50 мс)
```

## 3. Физика (`src/core`)

- Логически верный порт `CCharacterCore` + DDRace-логики персонажа: гравитация, контроль, трение, прыжки, хук (стена,
  игрок, no-hook, длина, 60 тиков на игроке), столкновения игроков, velocity ramp, `MoveBox`, `IntersectLine`,
  hook-through, стопперы (game+front), телепорты (in/evil/check), фриз/анфриз/deep на game-слое, молоток,
  квантование в конце тика, `sv_no_weak_hook`. Порядок тика повторяет сервер.
- **Главное:** всё в float64 (нет `Math.fround`), а DDNet — float32. Эксперимент фазы 0: TS расходится с настоящим
  C++ уже на **2–5 тике**, даже одношагово ~40% мировых шагов отличаются на ±1 px / ±1/256. Та же C++-логика,
  пересобранная в double, совпадает с TS бит-в-бит → ошибок логики нет, всё дело в точности.
- **Нет механик, важных для блок-карт:** фриз/deep/смерть на **front-слое** (BlmapChill: 161 тайл), switch-слой
  (двери, таймеры, switch-freeze, TILE_JUMP), tune-зоны, endless hook (флаг хранится, но не действует), live freeze,
  NPC/NPH/HIT-тайлы, solo и **команды** (/team не сталкиваются и не хукаются), пикапы (сердце = фриз), драггеры/плазма,
  хук-телепорты, спидап типа 29. Порядок персонажей (strong/weak, `m_StrongWeakId`) не берётся из снапшота.
- Полный список отличий с оценкой важности — `research/ddnet-physics.md` §3.

## 4. Сеть (npm `teeworlds` 2.6.1 + `netPatch.ts`)

- Протокол Teeworlds **0.6 + DDNet**: токен `TKEN`, UUID-сообщения (`NETMSG_EX`), ex-объекты снапшота, версия клиента
  19000 (`--protocol-version`). Карта: HTTP по `map_details` или чанками по UDP; парсит свой `loadMap.ts`.
- `netPatch.ts` чинит три дыры библиотеки: бесконечный цикл huffman, отсутствие `NETMSG_REDIRECT`, квадратичный
  декодер дельт снапшота; плюс глобальный перехват исключений декодирования.
- **Проблемы, которые не переносим:** библиотека шлёт `i-am-npm-package@swarfey.gitlab.io` и URL npm в версии, плюс
  `rcon crashmeplx`; тюнинг сервера (`Sv_TuneParams`) **игнорируется**; `NETMSG_INPUTTIMING` игнорируется
  (PredTick — счётчик по таймеру 20 мс); SHA256 карты не проверяется; несовпадение CRC роняет процесс.
- При подключении бот пишет в чат `/showall 1` — **в Rust заменяется** сообщением `Cl_ShowDistance`
  (см. DECISIONS D-007).

## 5. Конвейер решения (`bot.ts:2352-2604`, `4695-4864`)

1. Обновить `LiveWorld` из снапшота (Character + DDNetCharacter + PlayerInfo/ClientInfo, снаряды, лазеры).
2. **Лаг по эху прицела** (`bot.ts:4509-4563`): бот помнит 8 последних отправленных прицелов, берёт те, где прицел
   повернулся > ~11,5°, для задержки d = 1..10 тиков считает средний промах (≥40 выборок, порог 0,3, допуск 0,05),
   берёт наименьшее подходящее d минус шаг снапшота. Фоллбэк — `latency/20`. Максимум 6 тиков. Статистика не
   сбрасывается даже при реконнекте.
3. `pickTarget` (`bot.ts:3020-3123`): фильтры (friend/ignore, AFK, дальше 1600 px, «запечатанные»/замороженные), затем
   сумма весов: war +900, держит нас хуком +1000, мы держим +800, добивание +600, агрессор +500, атаковал друга +450,
   приближается +200, удержание текущей +400, −0,25·d, недостижим −700, в зоне WB +300.
4. Режим: fight / nav (goto) / WB (Copy Love Box) / trek / wander / unstick (/kill при зависании во фризе).
5. `planAction`: плановый `SimWorld` (свой ти + цель), ввод соперника угадан по снапшоту («держит те же кнопки»,
   без прыжка и огня), мир прокручен на `lag` тиков с уже отправленными вводами → `Planner.decide`.
6. `applyInput`: ввод уходит сразу; библиотека ещё переотправляет его каждые 50 мс.

## 6. Планировщик (`src/plan/planner.ts`)

- План: **9 шагов × 3 тика = 27 тиков** (~0,5 с); шаг = направление, прыжок, хук, огонь, прицел (относительно пеленга на
  соперника, `trackAim`). `decodeAction` сглаживает поворот прицела на 75% за шаг и округляет цель до целых на
  радиусе 300 px — роллауты симулируют именно это.
- **CEM:** популяция 20, элита 6, 2 итерации; на итерации 0 — дебютная книга (5 фиксированных планов + до 2 «hook
  seeds» + до 3 «frozen-throw» линий). ≈48 оценок планов и ≈1340 шагов мира на решение.
- **Оценка** `evaluate`/`scoreTick`: плюс за соперника во фризе / рядом с фризом (BFS-поля) / «запечатанного»; минус за
  свою близость к фризу, угрозы вылета от молота и стаскивания хуком, пустые хуки и удары, дёрганье. Все члены и
  константы — `research/orig-plan.md` §1.7–1.9.
- После поиска: маржа 0,6 против смены направления, `edgeHold` (не поворачивать в 96 px от фриза), `polishRope`
  (держать хук 2/4/9 шагов), **щит** (`shield.ts`: после хода должен оставаться путь спасения, иначе ввод подменяется;
  срабатывает в 10–17% решений против скриптового бота).
- Режимы: обычный (бюджет 18 мс), `--low-cpu` (6 мс, решение раз в 2 снапшота), `--strong` (только в зале WB: 40×3,
  30 мс), WB-пресеты.
- **Детерминизм:** RNG xoshiro128** (сид через splitmix32), Box–Muller с кэшем «запасного» значения между решениями.
  Недетерминизм живого режима — **только** дедлайн по часам (`Date.now() + budgetMs`). Конструктор с
  `{budgetMs: 0, hardMs: 0}` даёт фиксированное число итераций и полную воспроизводимость (проверено 20/20 игр).
  Скрытое состояние между решениями (scratch-мир anti-thaw с мемо, `warm`, запасное гауссово, плановый мир,
  `SimWorld.order`) нужно дампить для паритета.
- Модель соперника по умолчанию — «держит кнопки». Опции `react` (скриптовый), GRU, `opponent.json` (MLP 224→192→96→10,
  предсказывает только направление; загружается, но по умолчанию не используется).

## 7. Скриптовый бот (`src/env/scripted.ts`, 57 строк)

Простой агрессор: идёт к сопернику (`dx > 5` → вправо), целится в него с шумом ±0,1 рад, прыгает при стене впереди
или если соперник выше на 80 px, хукает при 80 < dist < 380 и прямой видимости, вблизи (< 60 px) берёт молот, иначе
пистолет, и **кликает огнём каждый вызов**. Один вызов RNG на решение. Точный алгоритм — `research/orig-plan.md` §5.
Основной «слабый» соперник лиги.

## 9. Прочее, что важно для порта

- **Клипы:** кольцевой буфер 750 кадров (30 с), клип — JSON со всем массивом тайлов карты; поле `events` вживую всегда
  пустое (часть детекторов инцидентов мертва).
- **FreezeMemory:** по имени карты без CRC, затухание ×0,97 на каждое сохранение.
- **Списки friend/war:** сравнение по подстроке ника (`bot.ts:283`) — баг, в Rust точное сравнение.
- **Авто-выбор сервера:** `master1..4.ddnet.org/ddnet/15/servers.json`, блок — по регэкспу имени/карты/типа, +6 за
  `:ru`, файл-чёрный список на 10/30/60 минут.
- **WB** захардкожен под «Copy Love Box» (387×250) и «Copy Love Box JoniTee» (сдвиг +182/+212), зеркало x' = 234 − x.
- **Веб:** `node:http` на 127.0.0.1:7777 без входа и TLS, опрос `/api/live` каждые 40 мс (~125–390 КиБ/с). Отрисовка —
  Canvas 2D в браузере, код отрисовки портирован из DDNet (zlib). Графика — из установленного DDNet или с
  `raw.githubusercontent.com/ddnet/ddnet/20.0/data/`, скины — `skins.ddnet.org`.
- Мёртвый код: `OpponentProfile` (вес 0), `routeDistance` в скоринге, `bandCost=0`, распаковщик демок, 7 полей конфига.
