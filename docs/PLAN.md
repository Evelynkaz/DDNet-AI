# План: DDNet-AI на Rust + «муха»

Документ фазы 0. Основан на исследовании (`docs/research/*`), решениях (`docs/DECISIONS.md`) и замерах на этом VPS.
Меняется по ходу работ: каждое изменение плана — отдельный коммит с причиной.

## 0. Цели и вехи

| Веха | Критерий «готово» (с доказательством) |
|---|---|
| **R1** Физика Rust = сервер DDNet | 0 расхождений целых/квантованных полей с C++-оракулом на ≥ 1000 последовательностей реальных блок-карт |
| **R2** Rust-клиент играет | полный цикл «вход → игра → смена карты → реконнект → редирект» на локальном ddnet-server, логи |
| **R3** Rust-планировщик = TS-планировщик | 100% совпадение решений при тех же сидах (≥ 10k решений) + кросс-матч ≈ 50% |
| **R4** Бот целиком на Rust | все функции из scope, 1 ч без падений и роста памяти на локальном сервере |
| **R5** Веб вместо Electron | Playwright-тесты по HTTPS (вход, live-кадр, команды), Electron и TS-рантайм удалены |
| **F1** Муха ≥ 90% против скриптового бота | ≥ 1000 игр, отложенные карты, фикс. сиды, 95% ДИ Уилсона, нижняя граница ≥ 90% |
| **F2** Муха ≥ 40% против планировщика | то же, нижняя граница ДИ ≥ 40% |
| **F3** Муха ≥ 50% против планировщика | то же, точечная оценка ≥ 50% и ДИ не ниже 45% |
| **F4** Муха блокирует живых игроков | локально → сервер владельца/разрешённый сервер; клипы, счёт блоков, самозаморозки/мин |

Сопутствующие метрики мухи на каждом замере: самозаморозки в минуту, время до первой заморозки соперника, доля
«запечатанных», ошибка предсказания физики (пробник), инференс p50/p99, память.

Правило игры в оценке (как в стенде фазы 0, `research/orig-run.md` §3): эпизод до первого фриза/смерти одного из
участников; выиграл другой; оба в один тик — ничья; 30 с без фриза — таймаут-ничья. Дополнительно считаются «credited»
(победитель хукал/бил жертву ≤ 50 тиков до фриза) и «held» (жертва ещё заморожена через 3 с). Винрейт = W / (W + L + D)
по всем играм, отдельно публикуются W:L:D:timeout.

### 1.2 Ключевые интерфейсы (эскиз, уточняется в задачах)

```rust
// ddai-physics
pub trait Real: Copy + PartialOrd + core::ops::{Add, Sub, Mul, Div, Neg} + ... {
    fn sqrt(self) -> Self; fn powf(self, e: Self) -> Self; fn sin(self) -> Self; fn cos(self) -> Self;
    fn atan(self) -> Self; fn atan2(self, x: Self) -> Self; fn from_f64(v: f64) -> Self; fn to_f64(self) -> f64; ...
}                                                    // impl для f32 (glibc через std) и f64
pub enum Profile { Ddnet, TsCompat }                 // флаги механик; TsCompat повторяет квирки TS
pub struct Input { direction, target_x, target_y, jump, fire, hook, player_flags,
                   wanted_weapon, next_weapon, prev_weapon: i32 }
pub struct World<R: Real> { /* тик, персонажи в порядке сервера, switch-состояния, снаряды */ }
impl<R: Real> Clone for World<R>                     // save/restore = clone_from, без аллокаций в горячем цикле
impl<R: Real> World<R> {
    pub fn new(map: Arc<MapData>, tuning: TuningSet, profile: Profile) -> Self;
    pub fn spawn(&mut self, id: ClientId, pos: Vec2<R>, team: Team);
    pub fn set_input(&mut self, id: ClientId, input: Input);
    pub fn step(&mut self, events: &mut Vec<Event>);  // один серверный тик
    pub fn character(&self, id: ClientId) -> Option<&Character<R>>;
}

// ddai-brain
pub trait Brain: Send {
    fn name(&self) -> &str;
    fn on_map(&mut self, map: &MapData);
    fn decide(&mut self, ctx: &DecisionContext) -> Decision;   // 25 Гц
}
pub struct DecisionContext<'a> { world: &'a World<f32>, own: ClientId, target: Option<ClientId>,
                                  lag_ticks: u8, prev_input: Input, bystanders: &'a [ClientId], ... }
pub struct Decision { input: Input, telemetry: Telemetry /* план/нейроны для веба и клипов */ }
```

### 1.3 Процессы на VPS

- **`ddnet-ai play`** — долгоживущий процесс бота (systemd): клиент + мозг + веб на `127.0.0.1:<port>`. Поток
  инференса мухи закреплён на своём ядре (хост режет непрерывный счёт паузами ~10 мс, `research/rust-stack.md` §4).
- **Caddy** (systemd) — HTTPS на `89-58-7-133.sslip.io` → `127.0.0.1:<port>`.
- **Обучение/оценка** — отдельные процессы (`screen`/systemd, `nice 19`, не на ядре инференса), пишут
  `~/aiddnet/data/runs/<exp>/{config.toml, metrics.jsonl, status.json, checkpoints/}`; веб читает эти файлы.
- **Локальный ddnet-server 20.1** (systemd) — для тестов и соперников.

## 4. Размер мухи и бюджет обучения (замеры фазы 0)

Бенчмарк (`research/rust-stack.md` §4; случайный граф — худший случай для кэша), реальный цикл 25 Гц на одном ядре:

| Синапсы | Подшаги | median | p99 | > 5 мс |
|---|---|---|---|---|
| 0,3M | 4 | 1,6 мс | 2,8 мс | 0/500 |
| **0,5M** | **4** | **2,2 мс** | **3,6 мс** | **0/500** |
| 1,0M | 2 | 2,2 мс | 3,6 мс | 0/500 |
| 1,0M | 4 | 3,6 мс | 5,7 мс | 35/500 |
| 0,9M (N = 30k) | 4 | 5,0 мс | 7,4 мс | 243/500 |

- **Бюджет инференса ≈ 2M обновлений синапсов на решение** при N ≤ 10–15k. Значит: **S** (2–3k нейронов, ≤ 0,2M) —
  с большим запасом; **M** (10–15k, ≤ 0,5M при 4 подшагах или ≤ 1M при 2) — на пределе; **L** (45k, ~2M) — только с
  событийным проходом и/или 1–2 подшагами (не планируем без доказательства).
- **Обучение** (8 потоков): BPTT ≈ 13–18k сэмпл-шагов/с при 0,5M синапсов (43k при 0,2M). Эпоха по 1 ч игры (90k
  решений × 4 подшага) ≈ 20–30 с; по 1M решений ≈ 4–5 мин. ES: поколение 64 эпизода × 60 с ≈ 30 с + физика →
  1000 поколений ≈ 8–10 ч. Память BPTT: ~25,6 КБ на нейрон на (T = 100, B = 64) → 256 МБ при N = 10k на поток ×
  подшаги — держать T·B·потоки в рамках 12 ГБ.
- **Разметка учителем:** цель Rust-планировщика ≤ 2 мс/решение (TS: 7,7 мс p50) → ~4–8k меток/с на 8 ядрах →
  1M меток за 2–4 мин.
- **Итог:** обучение S и M помещается в 8 ядер и 12 ГБ; начинаем с S, растём до M по метрикам.
