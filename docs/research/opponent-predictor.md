# Предсказатель ввода соперника для окна лага: пилот (задача 3.15, E-028, D-107)

> **Поправка 3.16 (D-115, `docs/research/lag-shave.md` §1):** живой лаг бота в смысле арены — **2**, а не 3 («lag N» в строках навигации = лаг первого слота + 1). Ячейки «3/x» ниже на тик выше живых; живому боту отвечают ячейки 2/x. Прирост и критерий «3/0 + 3/1 + 3/2» этой заметки — на тик выше живого лага; перемерить при 2/x.

наборы партий `data/`, `*.oppnet`, `*.jsonl`, `*.txt`), скрипты — `~/aiddnet/data/scratch/t315/`. Код — крейт `ddai-oppnet` (README рядом), `HybridConfig::window_model`
и `ddai_planner::hybrid::window`, примеры `ddai-env`: `opp_record`, `opp_eval`, `opp_clips`, `opp_arena`. Исследование, из которого задача выросла, — `docs/research/own-nn.md` §1–2, §7;

## 1. Вопрос и ставка

Решение гибрида на тике `T` при лаге `L` действует со шага `T + L`; мир до него гибрид прокручивает по нашим вводам «в полёте» (они известны) и по вводу соперника, которого
не знает: **«соперник держит то, что показывает снапшот»**. В дуэли на joniTee лаг решает всё (E-026: 0/0 — 50,5%, 3/0 — 30,0%, потолок +20,5 п.п.), оракул, знающий только **очередь
уже отправленных** вводов соперника, берёт примерно треть потолка, остальное — его **решения** (реакции на состояние, которых в окне ещё не видно). Ставка пилота: маленькая сеть
(≈ 77 тыс. параметров, ≈ 8 мкс на вызов) учится по партиям арены предсказывать эти решения и заменяет «держит» в окне.

Критерии (из задачи): **go** — засчитанные ≥ +4 п.п. на 600 парных играх вместе при лагах 3/0, 3/1, 3/2, McNemar p < 0,05; 3/3 не хуже −2 п.п.; p99 работы +≤ 0,1 мс; то же знаком на другом
свежем наборе сидов; одна итерация при +2…+4; no-go ниже +2.

## 2. Что построено

- **Модель.** `ddai-oppnet`: вход 305 чисел (8 кадров пары с шагом 2 тика, 16 лучей геометрии, наши вводы в полёте, длина окна), `305 → 160 → 128 → 56`, ReLU, 76 792 параметра;
  выход на каждый из 8 тиков: направление (3 класса), прыжок, хук, **свежее нажатие огня**, изменение прицела. Прямой проход — ручной, побитно детерминированный, без аллокаций
  (подробности — README крейта). Вход — **только то, что есть в живом снапшоте**; сырого ввода соперника в нём нет.
- **Подключение.** `HybridConfig::window_model` (по умолчанию выкл.) + `HybridBrain::set_window_model`; в окне лага вместо `enemy_input_from_tee` соперник играет предсказанный ввод,
  цена вызова — 16 ти-тиков на часах работы (`work.units` телеметрии). Без ключа, без модели или без окна решения побитно прежние (тесты, золотые наборы).
- **Данные.** `opp_record`: на тик до первой заморозки — кадры обоих ти, применённые вводы, лучи вокруг соперника. Партии: гибрид по умолчанию (4 мс работы) против `live-v2` — настоящей
  живой конфигурации конкурента.

На отложенных 200 партиях test при нашем лаге 3 (`test-m1-lag3.txt`) то же: направление k = 0…3 — 90,1 / 80,7 / 75,8 / 72,5 против 90,2 / 80,5 / 74,6 / 68,9; направление+прыжок+хук — 72,3 / 56,6 / 51,9 / 49,3 против 76,4 / 52,5 / 46,8 / 41,2 (true).

**Что видно.** (1) Первый блок решения соперника (тики 0–1: решение, принятое на `T` из мира `T`) модель **не угадывает лучше «держит»**: доля угаданных смен 2–8% при 20–25% смен. Это тот же потолок, что у «зеркала» (E-017 §7: 77,4% против 78,2%):
решение планировщика конкурента — стохастический CEM (20×2 выборки с генератором), из одного состояния он выдаёт разные вводы, и никакая функция состояния не знает его случайности. (2) Чем дальше от снапшота, тем больше выигрыш против «держит» (направление +5…+11 п.п., хук +7…+10, прицел −30…−40% ошибки при k ≥ 2), потому что «держит» стареет, а
тренд виден по истории. (3) Ворота уверенности (`--gates`, логит-запас 0,5 / 1 / 2) точность **не повышают**: чем строже ворота, тем ближе к «держит» (направление+прыжок+хук при k = 0: 64,0 / 62,8 / 61,4 против 64,4 без ворот).

## 5.1 Офлайн: события и решения против оракула (`opp_eval --decisions`, test, лаг 3, 160 партий, 25 009 окон)

Ошибка позиции усредняет по почти всем окнам, где ничего не происходит; решающие метрики из `own-nn.md` §2.5 — события и решения (`eval-m1-decisions.txt`).

| событие в окне лага, как его видит оракул (настоящие вводы) | метод | точность | точность прогноза события (precision) | полнота (recall) |
|---|---|---:|---:|---:|
| удар молотом соперника по нам внутри окна (1 200 окон, 4,8%) | «держит» гибрида (`snap`) | 85,5% | 17,5% | 54,8% |
| | модель m1 | 95,2% | 75,0% (4 срабатывания) | **0,2%** |
| хук соперника держит нас в конце окна (18 498 окон, 74%) | «держит» гибрида | 73,6% | 81,8% | 82,7% |
| | модель m1 | **77,5%** | 79,9% | **92,9%** |

Модель **не предсказывает удары молотом** (голова нажатия почти никогда не срабатывает: база 4,5% тиков), зато лучше угадывает, что хук удержит нас (+3,9 п.п. точности, +10 п.п. полноты). Высокие полнота и малая точность «держит» по молоту — артефакт арены (F5 ревью): `enemy_input_from_tee` кладёт `fire = 0`, а настоящий счётчик соперника ненулевой, поэтому в мире окна у соперника
**«фантомный» удар на шаге 0** (`count_input_presses(c, 0) > 0`); вживую `LiveWorld` ставит чужой `fire = 0` и такого нет. Нулевая модель (hold через тот же путь модели, счётчик ведётся честно) убирает фантом и в арене даёт +0,3 п.п. против базы (§7.1): фантом на результат не влияет. Отдельная задача: «держит» должно вести счётчик (отпустить, не нажать).

Решения: три теневых гибрида (окно крутится «держит» / моделью / оракулом; смотрят одни и те же виды, по порядку, сами не играют) — согласие с оракулом: направление **58,2% → 62,1%**, прыжок 85,0 → 86,0%, хук 67,4 → 69,4%, все три вместе **38,3 → 43,0%**. Абсолютные числа занижены: теневые гибриды независимы и расходятся и без разницы в окне (у решений планировщика своя случайность и тёплый старт; 61,7% решений
оракула не совпали с «держит»). Это относительная оценка: **модель ближе к оракулу, чем «держит», на 4–5 п.п.**
Работа на тех же видах (часы работы, мс, p50 / p90 / p99 / max): «держит» 3,74 / 3,88 / 8,15 / 10,86; модель 3,77 / 3,90 / 8,31 / 11,17 (25 009 решений).
