Дата: 2026-09-27. Все версии проверены через crates.io API, `cargo info`, docs.rs и GitHub в этот день; toolchain на VPS: rustc 1.98.1 / cargo 1.98.1 (stable).
Железо VPS: 8 vCPU «AMD EPYC-Rome Processor» (KVM), флаги `avx avx2 fma f16c bmi1 bmi2 sha_ni`, **AVX-512 нет** → целевой уровень `x86-64-v3`. L1d 32 КБ, L2 512 КБ на vCPU, L3 16 МБ на vCPU (lscpu: «128 MiB (8 instances)»), номинальная частота 1996 МГц, 15 ГБ RAM + 7 ГБ swap. Ubuntu 24.04.5 LTS.

## 1. Итоговые рекомендации

- **Web**: `tokio` 1.53 + `axum` 0.8.9 (feature `ws`) + `tower` 0.5.3 + `tower-http` 0.7.1 (`trace`, `timeout`, `limit`, `fs`, `set-header`, `csrf`) + `tower_governor` 0.8 (`default-features = false, features = ["axum"]`) за Caddy 2.11.
- **Сессии**: не `tower-sessions` (его `MemoryStore` не вычищает просроченные записи), а свой вариант: `axum-extra` `PrivateCookieJar` (фича `cookie-private`) со случайным id сессии, серверная таблица `id → {expires, csrf}` с TTL и периодической чисткой. Пароль хранится как хэш `argon2` 0.6 (Argon2id, явные `Params`), сравнение через `subtle`.
- **Сериализация**: `serde` + `postcard` для чекпойнтов и датасетов, сжатие `zstd` 0.14. **`bincode` не использовать**: RUSTSEC-2025-0141, крейт unmaintained, 3.0.0 — «надгробие» из `compile_error!`. `rkyv` 0.8.18 только для доверенных файлов.
- **RNG**: `rand` 0.10.3 (API сломан относительно 0.9, см. ниже), для воспроизводимости `rand_pcg` 0.10.2 (`Pcg64Mcg`) или `rand_xoshiro` 0.8.1 с явными сидами. Для ES-шума counter-based вариант: сид = hash(generation, worker, episode).
- **Численное ядро «мухи»**: **собственный CSR-код + ручной BPTT** (forward/backward по CSR/CSC, градиенты сразу сворачиваются в скейлы type-pair), проверка конечными разностями в f64. Фреймворки (candle 0.11, burn 0.21) sparse не поддерживают, dfdx заброшен (факты в §3). SIMD: `std::simd` на stable нет, но он и не нужен: скалярный код с развёрткой на 8 аккумуляторов и `-C target-cpu=x86-64-v3` оказался быстрее ручного AVX2 gather на целевых размерах (§4). Параллелизм через `rayon` 1.12 по эпизодам и шардам батча.
- **Размер мухи (по бенчмарку, реальный цикл 25 Гц на одном ядре)**: бюджет ≈ **2M обновлений синапсов на решение** (nnz × подшагов) при N ≤ ~10–15k: **0.5M рёбер × 4 подшага** (например N≈10k, K≈50; median 2.2 мс, p99 3.6 мс) или **1M × 2 подшага** (p99 3.6 мс). 1M × 4 уже не укладывается (p99 5.7 мс), сеть масштаба всего мозга (тест N=140k, K=20, 2.8M рёбер) не укладывается и с 1 подшагом (7.3 мс). Инференс в f32 с предумноженными весами. Обучение: BPTT при B=64 даёт ~13–18k сэмпл-шагов/с на 8 потоках для 0.5M рёбер; ES ~10–15k эпизодо-шагов/с. Подробности и таблицы в §4.
- **Хост**: у vCPU есть квота хоста ≈90 %. Непрерывный счёт получает паузы ~10 мс примерно 10 раз в секунду (в steal не видны). Поток инференса нужно держать на отдельном ядре без воркеров обучения, фон запускать с `nice 19`, §4.
- **Предобработка коннектома**: отдельный бинарник на `arrow` / `arrow-ipc` 60 (фича `ipc_compression`, иначе Feather с lz4 от pyarrow не прочитается) + `parquet` 60. `polars` избыточен.
- **Деплой**: Caddy 2.11.4 из официального apt-репозитория Cloudsmith, сайт `89-58-7-133.sslip.io` (HTTP-01 и TLS-ALPN-01 работают), WebSocket проксируется без настроек, `stream_close_delay` против обрыва при reload. Playwright 1.63 через Node (Node 24 уже стоит). gitleaks 8.30.1 бинарником (без EULA gitleaks-action). В CI: `actions/checkout@v7`, `Swatinem/rust-cache@v2`, `dtolnay/rust-toolchain@stable`.

### SIMD

- `std::simd` (portable_simd, tracking issue #86656) **по-прежнему только nightly**: в документации 1.98.1 помечен «nightly-only experimental API», стабилизации нет (Linebender, 2026-09-22: «would love to see std::simd stabilized»).
- На stable: `#[target_feature]` на safe-функциях (target_feature 1.1) стабилен с **Rust 1.86**; с 1.87 большинство интринсиков `std::arch` без указателей можно вызывать как safe внутри функции с нужными фичами.
- Крейты: `wide` 1.7.1 (2026-09-14; `f32x8`, `mul_add`; диспетчеризация только на этапе компиляции), `pulp` 0.22.3 (runtime-диспетчеризация, v3 по умолчанию, v4 отдельной фичей), `multiversion` 0.9.0 (мультиверсии функций), `fearless_simd` **1.0.0** (2026-09-21, Linebender; уровни SSE4.2/AVX2/AVX-512, `dispatch!`).
- **Вывод для нас**: бинарник собирается для одной машины, поэтому `-C target-cpu=x86-64-v3` в `.cargo/config.toml` (`native` тоже годится, но v3 переносим между хостами Rome/Milan/Intel). Ядро CSR-matvec упирается в память и задержки случайных чтений, а не в FMA. Ручной AVX2 `vgatherdps` на Zen 2 **медленнее** скалярного кода на целевых размерах (≤1M nnz, см. §4) и быстрее только на больших сетях. Батч-ядра (B=8/64) автовекторизуются компилятором по массивам `[f32; B]`. Отдельный SIMD-крейт на старте не нужен; при необходимости `wide` или `fearless_simd`.

### Рекомендация: ручной BPTT по собственной sparse-модели

1. **Нет sparse в фреймворках.** Dense W при N=10k — это 400 МБ и в 100 раз больше FMA, чем CSR при K=100. Эмуляция через gather/scatter по E рёбрам создаёт на каждом шаге промежуточные тензоры размера E×B, и autograd хранит их для backward: при T=100, E=1M и B=64 это порядка 25 ГБ. Ручной BPTT хранит только состояние `v_t` (T·N·B·4 байт = 256 МБ при N=10k, B=64, T=100), а градиенты по рёбрам сразу сворачиваются в `grad_scale[type_pair]`.
2. **Накладные расходы на граф.** Шаг сети при N=2–30k занимает десятки–сотни микросекунд. Фреймворк на каждом шаге строит узлы графа (Arc, аллокации, диспетчеризация), что сопоставимо с самой работой. Ручной цикл не аллоцирует ничего.
3. **Модель простая**: `v ← v + α⊙(−v + W·r + b + x)`, `r = clamp(v, 0, r_max)`, `W_ij = sign_ij·count_ij·scale[type_pair_ij]`. Backward полностью выписан и проверен в бенчмарке (§4):
   - `u = α⊙g` (g = ∂L/∂v_{t+1});
   - `∂L/∂v_t = g⊙(1−α) + relu'(v_t)⊙(Wᵀu)`;
   - `∂L/∂scale_p += Σ_{(i,j)∈p} u_i·sc_ij·r_j`;
   - `∂L/∂b_i += u_i`, `∂L/∂α_i += g_i·(−v_i + (Wr)_i + b_i + x_i)` (отсюда градиент по τ типа);
   - всё это делается за один проход по CSC (столбцы = пресинаптические нейроны). Молчащие нейроны (v_j ≤ 0) пропускаются целиком: у них r_j = 0 и relu' = 0.
   Итог: около 300–500 строк вместе с тестами.
4. **Проверка градиентов**: центральные конечные разности в f64 на малой сети (N≈200–500) по каждому классу параметров, `approx` и `proptest` в тестах. В бенчмарке аналитический градиент совпал с FD с относительной ошибкой ≤ 8·10⁻⁴ в f32. Опционально сверка с `std::autodiff` на nightly как отдельный эксперимент, не в основной сборке.
5. **Одно ядро для инференса и обучения**: один формат весов, никаких ~600 зависимостей burn и риска, что бэкенд объявят deprecated (ndarray и candle уже выведены из burn).
6. **Параллелизм**: data-parallel по шардам батча (у каждого потока свой B=64, градиенты суммируются) и по эпизодам ES через `rayon`. Параллелить один шаг по строкам имеет смысл только для инференса, если бюджет не сходится.

### Модель и методика
- Шаг: `r = clamp(v, 0, 10)`; `v_i += α_i·(−v_i + Σ_j W_ij r_j + b_i + x_i)`, α = dt/τ ∈ [0.1, 0.5] (по типу). В одном шаге: проход по N для r, CSR-проход (pull/gather) по строкам, обновление v.
- Граф: случайные пресинаптические индексы (равномерно; **худший случай для кэша**, у реального коннектома больше локальности), fan-in строки ~ U[1, 2K−1] (среднее K), дубликаты удалены. 128 типов → 16 384 type-pair (индекс u16). Закон Дейла (знак по пресинаптическому нейрону, 50 % тормозных), count 1..9. `W_ij = sc_ij·scale[tp_ij]`, масштаб 1/(5√K).
- Хранение CSR: `col: u32` + `val: f32` = 8 Б/ребро. Typed-вариант: `col: u32` + `meta: u32` (tp<<16 | sc as i16) = тоже 8 Б/ребро плюс таблица scale 64 КБ. f64: 12 Б/ребро. Для backward есть CSC-копия (ещё 12 Б/ребро).
- Ядра:
  - `premul_scalar`: скалярный dot по строке с 8 независимыми аккумуляторами и `mul_add`; автоматически становится `vfmadd` при target-cpu.
  - `avx2gather`: ручной `_mm256_i32gather_ps` через `#[target_feature(enable = "avx2,fma")]`.
  - `typed_onthefly`: вес считается на лету как `sc·scale[tp]`.
  - `push_csc`: event-driven, проход только по активным пресинаптическим нейронам (CSC) со scatter.
  - Backward (B=1):
    - `csr_scatter`: один проход по строкам, scatter в Wᵀu и в `grad_scale[tp]`;
    - `csc_gather`: один проход по столбцам, gather u; молчащие нейроны пропускаются целиком.
  - Batched (состояние `[N][B]`, `[f32; B]` автовекторизуется): `fwd_b::<B>` и `bwd_b::<B>` (CSC; на каждое ребро B FMA для Wᵀu и B FMA для скалярного произведения u_i·r_j → `grad_scale`).
- Замеры: прогрев ≥0.1 с, затем по-шаговые `Instant` до 0.8–1.5 с (не меньше 5 шагов); median, p90, p99, доля шагов > 2×median, число involuntary context switches. Одно ядро закреплено через `taskset`, FTZ/DAZ включены (денормалей не бывает).
- **Корректность** (`check`): все forward-ядра совпадают (max |Δ| ≤ 2.4e−7); CSR- и CSC-backward и batched-backward совпадают с B=1 (≤ 4.8e−7). Аналитический градиент по v_t и по scale совпадает с центральными конечными разностями: худшая относительная ошибка **7.8e−4** в f32.

### Важная находка: «дыры» гипервизора ~10 мс
`jitter` (чистый spin без обращений к памяти, одно ядро, 10 с): **9.9 пауз в секунду по ~9.8 мс (max 10.9 мс), теряется ≈99 мс/с (~10 % ядра)**, при этом involuntary context switches всего 13 за 10 с, а steal в `/proc/stat` не растёт. Картина соответствует CPU-квоте хоста на vCPU (~90 % физического ядра, CFS bandwidth: период 100 мс, после исчерпания квоты vCPU стоит ~10 мс).
Следствия:
1. Любой **непрерывный** счёт на ядре получает паузы ~10 мс примерно каждые 100 мс. Отсюда p99 ≈ 10–14 мс во всех «горячих» замерах со средними и крупными размерами ниже: это не ядро, а хост.
2. В **реальном цикле 25 Гц** (счёт 2–4 мс, потом sleep) квота не исчерпывается, и таких пауз нет (таблица `duty` ниже: max 3.7 мс при 0.5M×4).
3. Для обучения (ES/BPTT) пропускная способность ядра ≈ 90 % от «чистой»; в числах ниже это уже учтено (throughput считался по wall-clock/mean).
4. Поток инференса **нельзя** делить по ядру с воркерами обучения: съеденная ими квота обернётся паузами у бота.

### Выводы для выбора размера мухи
1. **Бюджет инференса** (одно ядро, 25 Гц, p99 < 5 мс с запасом): **≈ 2M обновлений синапсов на решение** (nnz × подшагов) при N ≤ ~10–15k. Варианты: **0.5M рёбер × 4 подшага** (например N≈10k, K≈50, или N≈5k, K≈100; p99 3.6 мс) либо **1M × 2 подшага** (N≈10k, K≈100; p99 3.6 мс). 1M × 4 и 30k×30 × 4 не укладываются (p99 5.7–7.4 мс). Сеть масштаба всего мозга FlyWire (~140k нейронов; в тесте K=20, 2.8M рёбер; реальное число рёбер после порога по синапсам уточнить в заметке по коннектому) не укладывается даже с 1 подшагом (7.3 мс), нужен подграф.
   Резервы, если понадобится больше:
   - push-ядро при активности ≤20–30 % (×1.5–4.7);
   - перенумерация нейронов для локальности (реальный граф не случайный);
   - второе ядро для инференса (rayon по строкам);
   - индексы `u16`, если N ≤ 65 536 (−25 % трафика).
2. **BPTT** (B=64, f32, ручной backward): для 0.5M рёбер ≈ 3–4k сэмпл-шагов/с на поток и ≈ 13–18k/с на 8 потоках (интерполяция между 10k×30, 10k×100 и 2k×300); для 1M рёбер ≈ 1.6k/с и ≈ 7.3k/с; для 0.2M ≈ 10.7k/с и ≈ 43k/с. При 4 подшагах на решение это ≈ 3.3–4.5k решений-сэмплов/с для 0.5M-мухи: час демонстраций (90k решений) проходится за ~20–30 с на эпоху. Imitation learning вполне реален.
3. **ES**: для 0.5M рёбер порядка 10–15k эпизодо-шагов/с на 8 потоках (B=1). Эпизод 60 с × 25 Гц × 4 подшага = 6000 шагов, то есть ~2 эпизода/с, и поколение из 64 эпизодов занимает ~30 с плюс симуляция игры. С батчем B=8 эпизодов на одно возмущение ×2.5–5 (оценка по forward-ядру). ES годится для дообучения (скейлы type-pair, τ, bias; тысячи параметров) на коротких эпизодах, но не как основной метод.
4. **Точность**: f32 везде; FD-проверка в f64 на малой сети в тестах.
5. **SIMD**: хватает автовекторизации при `target-cpu=x86-64-v3`; `std::simd` (nightly) и ручные gather не нужны.

### Caddyfile (reverse proxy + автоматический HTTPS + WebSocket)

- **WebSocket** настраивать не нужно: `reverse_proxy` сам делает upgrade и туннелирует соединение. По умолчанию при reload конфига открытые WS-потоки закрываются; `stream_close_delay` держит их открытыми, `stream_timeout` задаёт жёсткий предел. `flush_interval -1` нужен только для SSE.

## 7. Риски и открытые вопросы

1. **Реальная структура коннектома ≠ случайный граф.** Бенчмарк использует равномерно случайные столбцы (худший случай для кэша). Реальный граф локален (нейропили, типы), поэтому перенумерация нейронов (по типу/нейропилю или RCM) должна ускорить gather. Но тяжёлый хвост распределения fan-in (у некоторых нейронов тысячи входов) ухудшит балансировку при параллелизме по строкам. Измерить на реальном подграфе FlyWire сразу после предобработки.
2. **Активность сети.** Push-режим (итерация только по активным пресинаптическим нейронам) при 10–30 % активности в 2–4.6 раза быстрее pull-режима. Какая доля будет активна у обученной мухи, заранее неизвестно. Держать оба ядра и выбирать по измеренной доле активных нейронов.
3. **Хвост задержек (p99): гипервизор и соседи по CPU.**
   - У каждого vCPU есть квота хоста ≈90 % (spin-тест: 9.9 пауз/с по ~9.8 мс, в steal не видны). Любой непрерывный счёт на ядре получает паузы по 10 мс.
   - Цикл 25 Гц с короткой нагрузкой квоту не выбирает: в duty-тесте пауз нет. Но если на том же ядре крутится обучение, бот начнёт ловить 10-мс паузы.
   - Посторонние процессы на ядре бота поднимают p99 до 7–8 мс даже при `nice 19` у фона.
   - Нужно: изолировать ядро под поток инференса (cpuset / `AllowedCPUs=` у остальных юнитов, `CPUAffinity=` у бота), дать боту `CPUSchedulingPolicy=fifo` (или `Nice=-10`), воркеры обучения держать на других ядрах с `nice 19`.
   - Код управления должен переживать редкий пропуск дедлайна: действие предыдущего тика, watchdog. Провайдер может поменять квоты; на dedicated-ядрах проблема исчезла бы.
4. **Память BPTT.** Хранение T=100 шагов при B=64 стоит N·6.4 КБ·(подшагов): N=10k и 4 подшага дают около 1 ГБ. Решения: хранить только `v` (r и маску пересчитывать), bf16/f16 для хранения (−50 %), чекпойнтинг через каждые √T шагов, усечённый BPTT.
5. **Дрейф API.** `rand` 0.10 ломает API, `zstd` 0.14 сменил лицензию на BSD-3, `arrow`/`parquet` выпускают мажор ежемесячно (закрепить версию в утилите), axum 0.9 на горизонте, `tower_governor` сопровождается вяло (fallback: свой middleware на `governor` примерно в 50 строк).
6. **ES-бюджет.** При 8 потоках ES на сети в 1M рёбер даёт ~9k эпизодо-шагов/с, на 0.5M ~10–15k/с (§4). Эпизод 60 с × 25 Гц × 4 подшага = 6000 шагов, поэтому поколение из 64 эпизодов займёт 30–45 с плюс симуляцию игры. Батч из B=8 эпизодов на одно возмущение ускоряет в 2.5–5 раз (оценка по forward-ядру). ES реалистичен как дообучение небольшого числа параметров (скейлы type-pair, τ, bias) на коротких эпизодах. Основную работу должен делать BPTT/imitation.
7. **Детерминизм между машинами.** FMA и порядок суммирования фиксированы кодом, но `target-cpu=native` на другом хосте может сменить codegen. Для воспроизводимых чекпойнтов фиксировать `x86-64-v3`. FTZ/DAZ (использовались в бенчмарке) заметно меняют поведение только в денормалях.
