# Клипы, инциденты, консоль, выбор сервера: что исправлено относительно TS (задача 4.3)

Источники TS: `src/watch/recording.ts`, `src/watch/incidents.ts`, `src/bot/bot.ts` (`handleConsole` 1310–1666, `recordFrame` 3134, `maybeClip` 3173, `clipCrossFail` 3164,
`writeClip` 3188, `pruneClips` 3213), `src/bot/serverPick.ts`. Формат и устройство — `docs/formats.md` §24; решение — D-067.

## Ошибки TS, исправленные нарочно

| # | В TS | Здесь |
|---|---|---|
| 1 | `recordFrame` писал `events: []` (`bot.ts:3151`): вживую события не записывались никогда, поэтому `swing-at-air` не срабатывал, а «молот толкнул в фриз» (`incidents.ts:76`) всегда был ложью. | События выводятся из состояний тиев соседних снапшотов (хук, молот, фриз) и из `SV_KILLMSG` / своих `Cl_Kill`. |
| 2 | `death` определялся по `alive: false` в кадрах, а кадры писались только пока тий жив (`recording.ts:91,123`): вид был недостижим. | После исчезновения нашего тия пишется ещё `TAIL_FRAMES = 6` кадров; `death` берётся из сообщения о смерти, запасной вариант — исчезновение тия, один раз на смерть. |
| 3 | `pruneClips` разбирал имя регуляркой `^(.*)-\d+-s(\d+)\.json$` (`bot.ts:3218`), а `cross-fail-<тик>.json` ей не соответствовал: такие клипы копились вечно. | Имя `cross-fail-<тик>-s0.clip` разбирается, чистка берёт его наравне с остальными автоматическими (24 всего, 16 одного вида). |
| 4 | Строка без префикса уходила **в игровой чат** (`handleConsole`, `bot.ts:1314-1322`). | Отвергается разбором (`ParseError::NoPrefix`), в `BotCommand` нет такого варианта; `say`, `owner`, `llm`, `d` отказывают с причиной. |
| 5 | Списки `war/friend/ignore` сопоставлялись по подстроке (D-021). | Точное совпадение после нормализации; подстрока используется только чтобы дополнить введённое оператором имя до единственного игрока (`!target`, `!goto`, команды списков), а несколько совпадений — ошибка. |
| 6 | Клип — JSON (`*.json`, плюс `.html`) со всеми кадрами как текст. | Бинарный `postcard + zstd` с версией; без аллокаций в установившемся режиме. |
| 7 | `serverPick` соединялся с самым населённым публичным блок-сервером. | Только чтение мастер-списка; `--server auto` выбирает среди **разрешённых** (локальный + `ready` из `live-servers.toml`), иначе локальный. |

## Другие отличия (не ошибки)

- Кадр содержит **отправленный** ввод (на каждый тик с последнего кадра, с флагом «отчёт о времени получен»), а не принятое решение; он перечитывается на следующем кадре (`amend_last_sent`).
- Удар молотом, толкнувший нас во фриз, ищется во фриз-кадре **или предыдущем**: на 25 Гц удар и онсет фриза обычно в разных кадрах.
- «Идёт ход» для `goto-into-freeze` — метка хода в кадре или в предыдущем; состояние навигации (`crossing`, `plannedFreeze`) пишется всегда.
- Просмотр кольца (поиск инцидентов), запись и чистка — на потоке `clip-saver`; если он занят, скан повторяется на следующем кадре.
- Команды `duel`, `style`, `try`, `lang`, `log`, `yes/no/votes/vote`, `emote` не портированы (в Rust-боте нет дуэли, пресетов `TRY_SETTINGS`, голосов, эмоций; язык консоли — английский).
- `!low` меняет пресет только для мозга `planner` (поиск гибрида ограничен 5 мс по D-042); `!strong` — флаг навигации (WB-зал).
- `ddnet-ai clip replay` и `LiveWorld::export_own/import_own` — новое; в TS клипы не воспроизводились.
