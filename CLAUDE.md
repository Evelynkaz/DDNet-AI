# CLAUDE.md — правила проекта DDNet-AI (Rust + «муха»)

Этот файл читает любая новая сессия. После перезапуска: **сначала этот файл, потом `docs/STATUS.md`**, затем продолжай
с того места, где остановились. Всё важное живёт в репозитории, а не в контексте.

## Что за проект

Форк https://github.com/Wranked1/DDNet-AI (GPL-3.0, автор Wranked1) — бот для режима «блок» в DDNet (закидывает
соперников во фриз и не попадает туда сам). Исходник — TypeScript/Node 24 (~23k строк). Цели:

1. Переписать бота **полностью на Rust** (cargo workspace) с тестами и CI.
2. Решения в бою принимает **«муха»** — сеть на коннектоме дрозофилы (MaleCNS v1.0), обученная блокировать.
   Итог: муха сама, без планировщика, закидывает соперников во фриз и почти не замерзает.
3. Заменить Electron **веб-интерфейсом**, который отдаёт сам бот (axum + websocket, за Caddy с HTTPS и паролем).

Rust-планировщик переносится, но в живую игру не идёт: он учитель мухи, эталон для замеров и отладочный режим
`--brain planner`. Убираем: Electron, dummy, тиммейтов/дуэты, автообновление, все чат-фишки.
**Бот в игровой чат не пишет ничего** (даже `/showall` — вместо него сообщение протокола `Cl_ShowDistance`).

Подробно: `docs/PLAN.md` (фазы, критерии приёмки, риски), `docs/ORIGINAL.md` (как устроен исходник),
`docs/FLY.md` (муха), `docs/DECISIONS.md` (решения), `docs/SETUP.md` (сервер), `docs/EXPERIMENTS.md` (журнал обучения),
`docs/research/*` (сырые заметки исследования фазы 0 с file:line).

## Роли и процесс

- Главный агент — техлид: изучает, проектирует, режет задачи, **сам код не пишет**, принимает работу только по
  доказательствам, ведёт git/CI/документацию, отчитывается владельцу (по-русски, коротко).
- Реализация — через скилл **/duo**: `sonnet-builder` (Sonnet 5) пишет, `opus-reviewer` (Opus 5.5) ревьюит
  независимо. Большие исследования — субагентам (чтобы не забивать контекст).
- Задача для /duo самодостаточна (билдер не видит контекста главного агента):
  `<goal>` зачем и что; `<acceptance_criteria>` проверяемые пункты (какие тесты/замеры/команды должны пройти);
  `<constraints>` что нельзя трогать, стиль, производительность, что НЕ делать; `<context>` пути, интерфейсы,
  команды, ссылки на `docs/research/*` и file:line в `ref/ddnet`. Одна задача = один цикл «сделал → ревью → правки».
- «Готово» = есть доказательство (тест, замер, лог, скриншот). «Должно работать» не считается.
- Верь фактам, а не промпту: расхождение — в `docs/DECISIONS.md` и сказать владельцу.
- Застрял дважды на одной проблеме — остановись, опиши проблему и варианты.
- Мелкие решения принимай сам и записывай в `docs/DECISIONS.md`. Спрашивать владельца только: нужен доступ/данные
  (адреса его серверов, демки), необратимое/платное решение, развилка, меняющая цель.

## Git (работаем прямо в `main`)

- Цикл: /duo реализует → ревьюер одобряет → локально
  `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` (+ паритетные тесты, если задача их
  касается) → `git status`, `git diff --cached` (никаких секретов/данных/бинарников) → commit → `git push origin main`.
- Коммитить только зелёное. Упал CI после push — чинить сразу, до новых задач.
- Коммиты мелкие, на английском, Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `perf:`, `chore:`).
  Одна логическая правка — один коммит. Документация (README, docs/*) — на русском; код и комментарии — на английском.
- После фазы: `git tag -a phase-N -m "..."` и `git push origin phase-N`.
- **Запрещено:** `git push --force`, rebase/amend запушенного, `reset --hard` по удалённой ветке, удаление тегов и
  релизов. Ошибки — новым коммитом или `git revert`.
- Старый TS-код удалять только после того, как Rust-замена прошла паритет. Генератор эталонных трасс (TS) живёт в
  `tools/` до конца проекта.

## Никогда не коммитить

Данные коннектома, демки, клипы, карты, `settings*`, пароли, токены, секреты веба, большие веса (→ GitHub Releases),
графику DDNet (скачивается ботом по манифесту с sha256). В CI — gitleaks. `.gitignore` строгий.

## Железо и ресурсы

8 vCPU (гость видит **AMD EPYC-Rome: AVX2+FMA, без AVX-512**), 16 ГБ ОЗУ + 8 ГБ swap, 256 ГБ NVMe, без GPU.
Меряй скорость и память. Большие данные — потоково. Не запускать тяжёлую компиляцию одновременно с обучением, если не
влезает в память. Наружу открыты только 22, 80, 443 (ufw).

## Команды

```bash
source ~/.cargo/env
cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test   # обязательный прогон перед коммитом
cargo test -p ddai-physics --test parity_cpp -- --ignored                      # паритет физики с C++ (появится в фазе 1)
node ~/aiddnet/data/research/harness/run.mjs --help                             # офлайн-стенд старой TS-версии
```

Команды сборки/запуска бота, обучения и веба дописываются сюда по мере появления (фазы 1–8).

## Живая игра

Порядок: локальный ddnet-server → серверы владельца (адреса спросить) → публичные блок-серверы.
Уважать правила сервера; в чат не писать; **не обходить кики и баны** (ни прокси, ни VPN, ни смены ников) — если
кикнули/забанили: остановиться, записать случай в `docs/STATUS.md`, сообщить владельцу. Не больше одного бота на
сервере. Не больше 5 подключений за 20 с к одному серверу. Ники других игроков в публичные отчёты не выносить.
