# ddai-connectome

Утилита предобработки коннектома MaleCNS v1.0: скачивание и проверка «минимального набора» из
3 файлов Arrow Feather (docs/research/fly-data.md §6.1), потоковое чтение по батчам и сборка
компактных внутренних таблиц (нейроны, типы, нейромедиаторы, рёбра) + статистический отчёт
(задача 6.1); плюс выбор подграфа мухи из этих таблиц и сборка `.flyg` для модели мухи (задача
6.3, см. «Подграф мухи» ниже).

Отдельный крейт/бинарник, **не зависимость `ddnet-ai`**: тяжёлый `arrow` (≈100 транзитивных
пакетов) не должен линковаться в бота. Сеть нужна только команде `fetch`; `inspect`,
`build-tables`, `stats`, `build-subgraph` и `flyg-info` работают полностью офлайн.

## Почему `reqwest::blocking`

`fetch` скачивает ровно 3 файла последовательно (проверка HEAD → докачка Range → проверка md5 и
sha256 → атомарный rename). Конкурентности эксплуатировать негде, а больше никакая часть этого
бинарника не нуждается в асинхронном рантайме — блокирующий клиент даёт прямой, линейный код без
`tokio::main` и без ручного управления футурами. Другие бинарники проекта (веб-интерфейс бота,
D-012/rust-stack.md §1) используют `tokio`/`axum`; это не противоречит выбору здесь, так как это
разные бинарники с разными требованиями.

## Команды

```bash
# 1. Скачать и проверить (сеть). Второй запуск ничего не скачивает, если файлы уже верны.
ddai-connectome fetch --manifest manifests/connectome.toml --dest ~/aiddnet/data/connectome/raw

# то же самое, но дополнительно дописать в манифест sha256 файлов, для которых он ещё не известен
ddai-connectome fetch --manifest manifests/connectome.toml --dest ~/aiddnet/data/connectome/raw --update-sha256

# 2. Посмотреть схему/число строк/сжатие любого .feather (офлайн)
ddai-connectome inspect ~/aiddnet/data/connectome/raw/body-annotations-male-cns-v1.0-minconf-0.5.feather

# 3. Собрать компактные таблицы (офлайн; читает только --raw, сеть не нужна)
ddai-connectome build-tables --raw ~/aiddnet/data/connectome/raw --out ~/aiddnet/data/connectome/tables

# 4. Статистика по компактным таблицам, отчёт в Markdown на русском (офлайн)
ddai-connectome stats --tables ~/aiddnet/data/connectome/tables --out ~/aiddnet/data/connectome/tables/report.md

# 5. Выбрать подграф мухи и собрать .flyg (офлайн; см. "Подграф мухи" ниже)
ddai-connectome build-subgraph \
  --tables ~/aiddnet/data/connectome/tables/connectome.tables \
  --config configs/fly/S.toml \
  --out ~/aiddnet/data/connectome/compiled/fly-S-v1.flyg \
  --report ~/aiddnet/data/connectome/compiled/fly-S-v1.report.md

# 6. Посмотреть сводку по готовому .flyg (валидирует файл при загрузке)
ddai-connectome flyg-info ~/aiddnet/data/connectome/compiled/fly-S-v1.flyg
```

`build-tables` ожидает в `--raw` файлы с точными именами из `manifests/connectome.toml`:
`body-annotations-male-cns-v1.0-minconf-0.5.feather`, `body-neurotransmitters-male-cns-v1.0.feather`,
`connectome-weights-male-cns-v1.0-minconf-0.5-traced-only.feather`.

## Манифест (`manifests/connectome.toml`)

Каждая запись закрепляет файл по GCS `generation` (перезапись объекта = 404, а не молча новые
данные), размеру и md5 (из HEAD), плюс наш собственный sha256, посчитанный после первой
успешной проверенной загрузки. Пустая строка `sha256 = ""` означает «пока не закреплён» — именно
её заполняет `--update-sha256`, никогда не перезаписывая уже проставленное значение.

## Компактные таблицы

`build-tables` пишет один файл `<out>/connectome.tables` (postcard, сжатый zstd, версионированный
заголовок с sha256 всех трёх входных файлов): `neurons` (плотный индекс, отсортирован по
`bodyId`), `types`, `neuron_nt` (predicted_nt + уверенность на нейрон, параллельно `neurons`),
`edges` (только между `Traced`-нейронами, отсортированы по `(post_idx, pre_idx)`, автапсы
отброшены и посчитаны отдельно). Все словари строк и порядок вывода детерминированы (сортировка,
без зависимости от порядка обхода `HashMap`).

**v3 (задача 6.3):** `neurons` дополнительно хранит `ol_hex1`/`ol_hex2` — исходные
`assignedOlHex1/2` (гекс-координаты колонки оптической доли; заполнены только у колончатых
нейронов оптической доли, ≈23,7 тыс. из 211,6 тыс. тел). Нужны для рецептивных полей визуальных
входов подграфа мухи (см. ниже); `somaLocation` **не** добавлена — ничего в задаче 6.3 её не
использует (RF считается по гекс-координатам пресинаптических партнёров, не по позиции сомы), а
добавлять поле без потребителя — не оправдано.

## Подграф мухи (`build-subgraph`)

Выбирает подмножество полного коннектома («входы → центральный мозг → выходы», FLY.md §3) и
собирает его в файл `.flyg` (формат — крейт `ddai-flyg`, описание полей — `docs/formats.md`).
Алгоритм детерминирован (при одинаковых `connectome.tables` + конфиге повторный запуск даёт
байт-идентичный `.flyg` — проверено на реальных S/M, отчёт задачи 6.3) и целиком управляется
конфигом (`configs/fly/S.toml`, `configs/fly/M.toml`): код не содержит зашитых списков типов или
порогов, только структуру алгоритма.

### 1. Затравки (seeds)

- **Визуальные входы** ("глаза") и **выходы** (DN, моторные команды) — берутся **все** Traced
  нейроны сконфигурированных типов, обе стороны (`inputs.visual_types`/`outputs.dn_types`).
  Имена типов проверяются точным совпадением против `connectome.tables`; несовпавшие — в отчёт
  (`missing_visual_types`/`missing_dn_types`), а не тихий пропуск — если хоть один список
  оказался **пустым после проверки**, сборка падает с ошибкой.
- **Восходящие входы** ("тело") — MaleCNS v1.0 почти никогда не даёт AN-типу функциональное имя
  (docs/research/fly-data.md §5), так что курированного списка нет. Вместо него — **выбор по
  данным** (`subgraph::an_pick`): берём топ-`an_top_n_types` типов AN по суммарному числу
  синапсов их нейронов на (а) сконфигурированные DN-выходы и (б) «прокси-центральные» нейроны —
  прямые постсинаптические партнёры визуальных входов с весом ≥ `θ_path`. (б) — приближение
  «AOTU/центральных скрытых нейронов» из формулировки задачи, не требующее уже посчитанного
  выбора скрытых нейронов (иначе был бы цикл: скрытые нейроны ищутся путями *от* входов, а входы
  включают AN). Список выбранных AN-типов и их баллы — в отчёте; это правило — **С/П**
  (семантическая аналогия/произвольно, не биологическая функция), как и любое другое отображение
  без известной функции типа.

### 2. Скрытые нейроны: путевой поток

Для каждого нейрона `v` считаем `F[v]` — лучший балл пути длины ≤ `k` от любой затравки-входа
до `v`, и `B[v]` — то же самое от `v` до любой затравки-выхода, по рёбрам с весом ≥ `θ_path`:

```
F[h][b] = max(F[h-1][b], max по рёбрам a→b: F[h-1][a] · вес(a,b) / N_in(b))
B[h][a] = max(B[h-1][a], max по рёбрам a→b: вес(a,b) / N_in(b) · B[h-1][b])
```

(`N_in(x)` — полный входящий счёт синапсов `x` во **всём** коннектоме, не только в подграфе; та
же величина, что войдёт в `Z_i` модели, FLY.md §4). Оба монотонно не убывают по числу хопов, так
что лучший балл нейрона-кандидата при общем бюджете `k` хопов — `max по h=0..k: F[h][v]·B[k-h][v]`
(перебор всех разбиений бюджета между «вход→v» и «v→выход» половинами пути). Кандидаты
сортируются по баллу (убывание), при равенстве — по `bodyId` (возрастание, для детерминизма);
оставляем топ `max_hidden`.

### 3. Двусторонняя дополненность

Это **замыкание (fixpoint)**, не один проход по ранжированному «ядру» (исправлено по ревью
раунда 1, F1): у нейрона, добавленного как чей-то гомолог, могут быть свои гомологи, которых
исходное ядро никогда не касалось напрямую (например, добавленный по типу+стороне гомолог может
сам иметь `group`, связывающий его с третьим нейроном) — очередь (worklist) обрабатывает вновь
добавленных, пока не перестанут появляться новые. Правило гомологов: нейроны с тем же `group`
**и тем же типом** (если `group` задан — общий `group` id у нейронов разных типов не делает их
гомологами друг друга, см. ниже), иначе — все нейроны того же типа на противоположной стороне
(`L`↔`R`; для `M`/неизвестной стороны — без пары, естественного зеркала нет). Это может увеличить
итоговое число скрытых нейронов заметно выше `max_hidden` — отчёт показывает и «ядро» (до
дополнения), и итог, и сколько добавлено каждым из двух правил.

### 4. Итоговый подграф

Индуцированный подграф на всех выбранных нейронах: ребро попадает в `.flyg`, если оба конца
выбраны и вес ≥ `θ_edge` (отдельный, обычно более строгий порог, чем `θ_path` — тот используется
только для поиска путей, не для итоговых рёбер). Автапсы уже исключены на уровне
`connectome.tables`.

### Знаки синапсов (`subgraph::signs`)

На уровне **типа**: приоритет — курированный `consensus_nt` (если не `unclear` — уверенность
1.0); иначе — голосование `predicted_nt` нейронов типа, взвешенное их `predicted_nt_confidence`,
делённое на **число проголосовавших нейронов** (не на сумму весов — иначе один-единственный
проголосовавший нейрон всегда даёт «уверенность» 1.0 независимо от того, насколько низкой была
его собственная `predicted_nt_confidence`). ACh → +1, GABA/Glu/гистамин → −1 (знаки
конфигурируемы, для абляций типа «Glu возбуждающий»), дофамин/серотонин/октопамин → 0 по
умолчанию (моноамины вне быстрой передачи). Тирамин как отдельный предсказываемый класс в файле
нейромедиаторов MaleCNS v1.0 не встречается — правило «тирамин → 0» для этих данных пустое.
`unclear`/нет данных или уверенность < `sign_confidence_threshold` → `uncertain = true`, знак 0
(либо, если `use_best_guess_when_uncertain = true` — знак всё равно берётся по победившему классу,
но флаг `uncertain` остаётся выставленным).

### Рецептивные поля (`subgraph::rf`)

Для визуального входа — синапс-взвешенное среднее **эффективных** гекс-координат его
пресинаптических партнёров, по **полному** коннектому, не только по подграфу. «Эффективная»
гекс-координата партнёра — это его собственная `ol_hex1`/`ol_hex2`, если она есть, иначе —
**однохоповая производная**: синапс-взвешенное среднее гекс-координат СВОИХ (партнёра)
гекс-координированных пресинаптических партнёров (не рекурсивно — ровно один хоп мимо прямого
гекс-слоя). Нужно, потому что лишь 15 реальных типов MaleCNS v1.0 несут `assignedOlHex1/2`
напрямую (L1–L5, Mi1/4/9, Tm1/2/4/9/20, C2/C3, T1); многие прямые пресинаптические партнёры
визуальных входов — на слой ниже этого (T4/T5, TmY, Tm5Y, …) и своих гекс-координат не имеют.
Без распространения несколько типов входов (HSE/HSN/H2, почти весь VS, много LC9) держались на
0–2 реальных синапсах опоры (ревью раунда 1, F2); с ним — на сотнях-тысячах синапсов (реальные
числа — в отчёте, таблица по каждой паре тип/сторона).

Перевод гекс → (азимут, элевация) — линейная карта, откалиброванная один раз по диапазону всех
гекс-координированных нейронов во всём коннектоме (одинаковая для S и M): `u = hex1 − hex2` →
величина азимута в диапазоне `[0°, 90°]` (насколько на периферию поля зрения), `v = hex1 + hex2` →
элевация в `[−60°, 60°]`; знак азимута — сторона глаза (`L` → отрицательный, `R` → положительный,
из задачи). Важно: сначала — величина в `[0°, fov]`, **потом** знак стороны; отображение сразу в
`[−fov, fov]` с последующим `abs()` дало бы одинаковую по модулю величину на обоих концах
диапазона гекс-координат, убив тот самый разброс, который проверяется в отчёте.

Нейрон, чья суммарная (прямая + однохоповая) гекс-опора ниже конфигурируемого
`rf.min_hex_support` (по умолчанию 10 синапсов — ревью раунда 1, F2), получает запасной центр
вместо того, чтобы доверять слабому сигналу: равномерно по рангу `bodyId` внутри своей группы
(тип, сторона), поверх реального диапазона азимутов той части группы, что порог прошла (или
всего диапазона стороны, если в группе вообще никто не прошёл порог); каждый такой нейрон помечен
(`is_fallback = true`) и посчитан в отчёте — вместе с гекс-опорой (мин/медиана/макс) и разбросом
азимута/элевации по каждой паре (тип, сторона), не только для LC10a/LC4/LPLC2.

### Пары типов и общие параметры (`subgraph::build`)

`type_pairs` — одна строка на различимую пару (тип-пре, тип-пост), встретившуюся среди итоговых
рёбер, с суммой синапсов **в подграфе**. Пары с суммой ≥ `weak_pair_threshold` получают свой
уникальный `shared_param_id`; более слабые делят один id на каждую комбинацию (знак типа-пре,
superclass типа-пре, superclass типа-пост) — сокращает число обучаемых параметров силы связи
(FLY.md §4/§7.2) без искажения знака или укрупнения категорий сверх необходимого.

### Каналы входов и группы выходов

`input_channels`/`output_groups` — прямое отражение конфига (только визуальные входы для каналов;
AN — без канальной карты, см. выше). Имя типа, которое не резолвится или не попало в подграф —
в отчёт, а не ошибка сборки (остальной подграф всё равно валиден).

## Тесты

`cargo test -p ddai-connectome` — полностью офлайн. Модульные тесты (`src/*.rs`) проверяют
хеширование, разбор `x-goog-hash`, разбор/точечное обновление манифеста, обнаружение испорченного
локального файла (несовпадение размера/md5/sha256) и точность преобразования `double → i64`/
`double → i16`. Интеграционный тест (`tests/build_tables.rs`) строит крошечные Feather-файлы тем
же писателем `arrow` со сжатием LZ4 (тот же кодек, что у настоящих файлов) и прогоняет через них
весь `build-tables`, сверяя каждое поле с посчитанными вручную ожиданиями.

`src/subgraph/*.rs` — модульные тесты на маленьких рукописных `ConnectomeTables` (без Feather):
знаки (курированный/голосующий путь, ties, абляции), рецептивные поля (реальные гекс-данные и обе
ветки запасного пути, монотонность карты азимута), путевой поток и двусторонняя дополненность
(сильный путь проходит, слабый — нет, недостижимый гомолог всё равно подхватывается по `group`),
выбор AN-типов по данным, и сквозной тест всего `build_flyg` (роли, детерминизм повторного
запуска, конфиг с недостающим именем типа — предупреждение в отчёте, а не ошибка, если хоть
что-то резолвится; ошибка, если резолвится вообще ничего).
