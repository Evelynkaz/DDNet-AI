# ddai-oppnet

Задача 3.15 (E-028, D-107). **Предсказатель ввода соперника для окна лага гибрида**: маленькая сеть, которая по тому,
что показывает живой снапшот, и по нашим вводам «в полёте» предсказывает, что соперник нажмёт в ближайшие 8 тиков (направление, прыжок, хук, удар, куда целится).
Гибрид крутит окно лага (тики между снапшотом и первым тиком, на который попадёт наше решение) с предсказанным вводом соперника вместо «держит то, что показывает
снапшот». Всё опционально и выключено по умолчанию (`HybridConfig::window_model`).

Зачем и что вышло — `docs/research/opponent-predictor.md`, `docs/EXPERIMENTS.md` E-028, `docs/DECISIONS.md` D-107; исследование, из которого задача выросла, —
`docs/research/own-nn.md` §1–2.

## Что предсказывается и из чего

**Вход** (`feature.rs`, 305 чисел): 8 последних кадров пары (с шагом 2 тика = каденция решений и 25 Гц живого снапшота; кадр — 29 чисел «глазами соперника»:
его скорость, направление, прицел, состояние хука и на кого он, прыжки, заморозка, давность удара; смещение до нас, расстояние, куда он целится относительно линии на нас;
наши скорость, направление, хук), 16 лучей геометрии вокруг соперника (расстояние до стены и до фриза/смерти по 8 направлениям), наши до 8 вводов в полёте,
длина окна (one-hot 0…8). Только то, что есть в живом снапшоте (`TeeFrame`): **сырых вводов соперника в нём нет** (прыжок, нажатия хука и огня выводятся из состояния).

**Цель** (`HORIZON` = 8 тиков от тика снапшота; тик `k` — ввод, применённый шагом `T + k → T + k + 1`): направление (3 класса), прыжок, хук, **свежее нажатие огня**
(счётчик ушёл на нечётное значение; удар — это переход счётчика, а не уровень), изменение угла прицела против того, что показывает снапшот (Huber).
Кадры, на которых соперник заморожен или мёртв, без метки.

**Сеть** (`net.rs`): `305 → 160 → 128 → 56`, ReLU, **76 792 параметра**. Прямой проход и обратный написаны вручную; веса лежат «входом вперёд» (`w[i * n_out + j]`), слой —
сумма строк, масштабированных входами: каждый выход накапливается в одном и том же порядке при любой векторизации, нулевой вход пропускает свою строку, ничего не слито
и не переставлено (в сборке нет fast-math и `target-cpu`). **Прямой проход побитно одинаков на любой машине** и не выделяет память после `Scratch::new`.
Скалярные произведения обратного прохода — восемь фиксированных накопителей. Тригонометрия — только `ddai-jsmath` (V8), `exp` — только в обучении (не в решении).
Обучение: Adam, косинусный спад скорости, 4 фиксированных шарда градиента на батч (сумма в порядке шардов), **результат не зависит от числа потоков** (тест).

**Решение** (`train::decode_tick_gated`): направление — argmax, прыжок/хук/нажатие — логит > 0, прицел = угол снапшота + изменение. Опциональные «ворота»
(`--gate`, логиты): голова, в которой модель менее уверена, отвечает «держит» (направление и хук — как показывает снапшот, прыжок и нажатие — нет); **прицел не гейтится** (регрессия без уверенности). Без `exp`: решение побитное. Маска голов (`window_heads = "dir,hook"`, `with_heads`) оставляет остальным головам ответ «держит» (для замеров вклада).

## Файлы

| Модуль | Что |
|---|---|
| `frame` | `TeeFrame` (что показывает снапшот о ти), `InputRec` (применённый ввод), `rays` (геометрия) |
| `feature` | вход и цели: `frame_features`, `inflight_features`, `assemble`, `Label`, `label_tick` |
| `net` | `Mlp`: `forward`, `backward`, `Scratch`; порядок суммирования |
| `data`, `blob` | формат набора (`GameRec`: по тику — кадры, применённые вводы, лучи) и контейнер `sha256 ++ zstd(postcard)` (общий с бандлом модели) |
| `bundle` | файл модели: сеть + версия раскладки признаков (чужая раскладка не загрузится); **весов в git нет**, они в `~/aiddnet/data/runs/E-028/` |
| `train` | выборки из партий (`Corpus`), потери, Adam, `train`, офлайн-метрики против «держит» (`evaluate`, `evaluate_gated`) |
| `predictor` | `OppPredictor`: сеть как `ddai_planner::hybrid::window::WindowModel`; кольцо истории кадров; один вызов на решение, без аллокаций |

## Инструменты (все — примеры)

```bash
# данные: партии гибрида против live-v2, на тик — кадры обоих ти, применённые вводы, лучи (до первой заморозки)
cargo run --release -p ddai-env --example opp_record -- --config configs/arena/e028-data-train.toml --out ~/aiddnet/data/runs/E-028/data/train --threads 3
# обучение + офлайн-метрики (точность по головам и тикам против «держит», на val; на test с --test)
cargo run --release -p ddai-oppnet --example opp_train -- --train <dir>... --val <dir>... --out m.oppnet [--test <dir> --gates 0.5,1,2]
# ошибка позиции соперника в конце окна на точной физике (прогноз против «держит» против оракула)
cargo run --release -p ddai-env --example opp_eval -- --config configs/arena/e028-data-test.toml --model m.oppnet [--gate 1]
# события (удар по нам, хук держит нас) и, с --decisions, согласие решений теневых гибридов с оракулом, работа решения на одних и тех же видах
cargo run --release -p ddai-env --example opp_eval -- --config configs/arena/e028-data-test.toml --model m.oppnet --only "joni 3/" --games 40 --decisions
# те же числа на живых клипах (read-only копии), только кадры дуэли (два ти в коробке 1vs1; --no-duel-filter — все)
cargo run --release -p ddai-env --example opp_clips -- --clips <dir> --model m.oppnet --lag 3
# партии арены с работой каждого решения (D-042) и JSONL для docs/research/e028/compare.py
cargo run --release -p ddai-env --example opp_arena -- --config configs/arena/e028-eval-m1-a.toml --jsonl out.jsonl --threads 3
# цена вызова
cargo run --release -p ddai-oppnet --example opp_bench
```

## Подключение к гибриду

`HybridConfig::window_model` (по умолчанию `false`) + `HybridBrain::set_window_model(Box<dyn WindowModel>)`; в конфиге арены — `hybrid = { window_model = "<файл>", window_gate = 0 }`.
Модель вызывается на **каждом** решении от точного мира (и при пустом окне, чтобы история была полной); при включённом ключе окно крутится с вводами, которые она вернула
(`input_from_prediction`: счётчик огня — свой счётчик соперника, нажатие — переход к следующему нечётному, без «призрачных» нажатий). Цена вызова — 16 ти-тиков на часах работы
(измерено: весь вызов 7,8 мкс медиана, 22 мкс p99 на общей ВМ; прямой проход 9,7 мкс), в `work.units` телеметрии. Без модели, без ключа или без окна — ничего не меняется.

## Тесты

`cargo test -p ddai-oppnet` — градиент сети и функции потерь против конечных разностей; разреженный прямой проход равен плотному побитно; обучение детерминировано и не зависит от
числа потоков; сеть выучивает периодического соперника и обгоняет «держит»; **вход тренера и вход предсказателя совпадают побитно** на одном и том же (физическом) прогоне; вызов
без аллокаций; кольцо истории; бандл и контейнер (подмена байта отвергается). В `ddai-env/tests/oppdata.rs`: запись партии на настоящей арене — применённые вводы равны решениям
кукол со сдвигом на лаг, «ввод в полёте» из `WorldView` равен записанному для тех же тиков, метки тренера равны решениям соперника.
