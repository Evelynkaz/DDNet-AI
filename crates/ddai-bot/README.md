# ddai-bot

Задача 4.1. **Живой бот** вокруг мозга: всё, что происходит между «пришёл снапшот» и «ушёл ввод». Запуск — `ddnet-ai play
--brain planner|scripted|hybrid|fly` (или `--bot --brain idle`) против локального сервера DDNet 20.1 (D-043: на публичные
серверы пока нельзя). Бот **никогда не пишет в чат** (D-007: в клиентском API просто нет такого вызова, а кик-разгон — это
сообщение протокола `Cl_Kill`) и **никогда не обходит кики и баны** (D-016/D-037: кик, бан или неизвестная причина — стоп
с кодом выхода 3/4 и сообщением, без переподключения).

Подробный формат (мост к вебу, `relations.json`, тайминг предсказания, замеры) — `docs/formats.md` §21.

## Конвейер одного снапшота (`bot::Bot::on_snapshot`, `orig-bot.md` §4.2)

Снапшоты, пришедшие пачкой, **схлопываются** (`runner`): решается только самый новый, пропущенные считаются
(`collapsed`). Один снапшот — одно решение, 25 Гц.

1. карта загружена и свой id известен (иначе ничего не делаем);
2. игровой тик пошёл назад — `onTickReset` (рестарт карты): чистятся все зависящие от тика состояния;
3. **LiveWorld** (`ddai-world`) обновляется из снапшота со своими «летящими» вводами и снарядами (`SnapshotInput`);
4. таблица игроков (`players`), плоский вид тиев (`tees`), **часы активности и атрибуция** (`activity`);
5. своего ти нет / мёртв — нейтральный ввод; в спектаторах — просьба войти в игру (`Cl_SetTeam(0)`, не чаще раза в 3 с,
   не больше 10 попыток **за весь запуск**, успех счётчик не обнуляет). Если бот уже играл на карте, а теперь он в
   спектаторах, — это сигнал модерации: **не просится обратно, запуск останавливается** (код 3, как при кике);
6. первый кадр жизни: `Brain::reset`, таймеры блуждания, навигатор. Начинается и после **своего** `Sv_KillMsg`
   (после `Cl_Kill` сервер возрождает сразу, пустого снапшота может не быть), смерть считается один раз;
7. **unstick** (`unstick`): константы `maybeUnstick` один в один, но убийство — `Cl_Kill`;
8. режим: `hold` — стоим; хук навигатора (4.2) может взять снапшот на себя; иначе **выбор цели** (`target`);
9. цели нет — **блуждание** (`wander`) через щит; цель есть — **предсказание** до PredTick по ближним тям, **мозг**
   (`decide_in`), затем **постфильтры**: щит (`guard`) для мозгов без своего щита (scripted, fly), **вето хука** и
   **вето молотка** на «пощажённых» (друзья, игнор, вне игры, AFK). Пощажённые тии не попадают в мир мозга (`keep`),
   если не связаны с нами верёвкой, и передаются ему как `LiveContext::spares`;
10. **кодирование ввода** (`input`): счётчик огня, молот по умолчанию, никаких флагов табло.

## Модули

| Модуль | Что |
|---|---|
| `bot` | `Bot` — sans-IO автомат; `BotConfig`, `Mode` (fight/passive/hold/goto-заглушка), `Output` (ввод, `Cl_Kill`, `Cl_SetTeam`), события |
| `runner` | реальное время поверх `ddai_client::Client`: схлопывание, обратные вызовы, мост, коды выхода, отчёт `RunReport` |
| `target` | порт `pickTarget` (§7.1-§7.2): фильтры, таблица очков, sealed/settled, фиксированная цель; `is_spared` |
| `activity` | часы активности/AFK (§7.4), `lastTouch`, `onFreezeOnset`, окно кредита 50 тиков |
| `relations`, `names`, `players` | списки friend/war/ignore/clanWar/clanFriend, **точное** сравнение после нормализации, таблица игроков, соль-хэши для логов |
| `reach` | достижимость: кэш ответов (25 тиков) и бюджет поисков; `FloodRoute` — заливка по воздуху без фриза; `RouteFinder` — хук под 4.2 |
| `unstick` | самоубийство при зависании/фризе: константы §8.6, кулдаун 500 тиков |
| `wander` | блуждание (§8.7) с детерминированным ГСЧ |
| `planning` | `PhysicsWorld`-мост к `ddai-planner`: `sealed_in`, щит, `rope_catches` |
| `seal_worker` | поток для `sealedIn` (0,5-1,5 мс): ответ приходит на следующем снапшоте; в sans-IO тестах поиск синхронный |
| `sent` | «летящие» вводы: `InputSent`/`InputTiming` -> ввод, который сервер применит на тике T (D-023) |
| `input` | `Action` -> `PlayerInput`: счётчик огня (нажатие/отпускание), молот по умолчанию |
| `latency` | p50/p99, доля мозга отдельно от накладных расходов бота (D-042) |
| `brains` | `--brain hybrid\|planner\|scripted\|idle\|fly`, `make_brain` — одна ветка `match` на мозг; hybrid — `HybridConfig::default()` (бюджет 4 мс, потолок 5 мс, адаптивное продление до 15 мс, модель угроз 1vN), без proposer'а (муха не обучена) |
| `hooks` | `Navigator`, `WayBlock`, `Trek`, `RouteFinder` — no-op заглушки под 4.2 |
| `bridge` | мост к веб-юниту: Unix-сокет, только чтение (`docs/formats.md` §21.2) |
| `mapgrid`, `tees` | плоский вид карты (слой игры + front) и тиев снапшота |

## Решения и отличия от TS (D-021)

- **Точное совпадение списков.** `listed()` в TS искала подстроку: короткий ник в friend/war задевал всех с похожим именем.
  Теперь: обрезка, сжатие пробелов, нижний регистр, снятие префикса дубликата `^\(\d+\)` — и сравнение целиком. Списки
  лежат в `~/aiddnet/data/bot/relations.json` (не в git). Повреждённый файл — отказ стартовать, а не «друзей нет».
- **Порядок при равном счёте.** TS брал первого в порядке вставки в `Map`; здесь тии обходятся по возрастанию client id,
  заменяет только строго больший счёт: побеждает наименьший id. Детерминированно и не зависит от порядка входа.
- **`FlagScoreboard` не портирован.** Раз в секунду на один снапшот TS включал флаг «табло открыто» (`bot.ts:4843`).
  Зачем — в коде не сказано; это выглядит как имитация активности для AFK-детектора сервера, поэтому не переносится.
  `player_flags` всегда `PLAYING`; тест проверяет, что флаг табло не уходит ни на одном тике.
- **Лаг — точный, а не оценка.** Вместо `echoLagTicks`/`pingLagTicks` (0..6 тиков по эху прицела или пингу) драйвер
  сообщает тик последнего отправленного ввода (`pred_tick`), а `sent` превращает `InputSent`/`InputTiming` в ввод,
  который сервер применит на каждом тике (поздний ввод сдвигается вперёд на `ceil(опоздание/20 мс)`, как делает сервер
  20.1). Мир предсказывается до `pred_tick`, действие мозга применяется на следующем шаге: `WorldView { lag_ticks: 0 }`.
- **Мозгу — только нужные тии.** Цель + те, кто связан с нами хуком + ближайшие 5 в радиусе 900 px. Остальные
  вырезаются из предсказанного мира (`LiveWorld::predict_local`): поиск на 8+ тях разваливается (ревью 3.5, F2).
- **Пощажённые идут планировщику** через `Brain::set_live_context` (`LiveContext.spares`, `setSpareBystanders`);
  замороженные соседи уже берутся планировщиком из мира. `setThirdTees` не передаётся: в живой конфигурации
  `thirdTeeExposure = 0`, он бы игнорировался.
- **Достижимость.** `findRoute` TS — граф ходьбы/падения/прыжка/хука на 984 строки — это навигация (4.2). Здесь тот же кэш
  (25 тиков, по тайлам «откуда/куда») и тот же бюджет «low-cpu» (один свежий поиск на снапшот, остальные — из кэша или
  оптимистично `true`), а сам поиск — `RouteFinder`; по умолчанию заливка по воздуху без фриза (`throughFreeze: false`,
  `nearTiles: 3`, 20 000 узлов). Это верхняя граница настоящего поиска: цель, запертая стеной или фризом, остаётся
  недостижимой.
- **Не портировано** (DROP по ТЗ и D-021): чат, авточат, LLM, дамми, партнёр, спасение друга, эмоции, дуэль-авто через
  `/accept`. **Вынесено в 4.2/4.3**: goto/seek/trek/home, вейблок (хуки), клипы, команды консоли, память фризов.

## Задержка (D-042)

`Bot::latency()` — кольца по 32 768 значений: `total` (снапшот в потоке бота -> `set_input` вернулся), `brain` (только
`decide_in`), `overhead = total - brain` (цель D-042: p99 <= 0,5 мс), `queue` (поток драйвера -> поток бота) и `wire`
(драйвер: снапшот пришёл -> первый `NETMSG_INPUT` с этим решением ушёл в сокет; включает каденс сессии — один ввод на
предсказанный тик, до 20 мс, — который скоростью бота не сократить). Замеры — в `docs/formats.md` §21.6 и отчёте билда.

Цена `sealedIn` и щита вынесена из накладных расходов: проверка sealed считается лениво (только там, где вердикт
`settled` может измениться — первый кадр заморозки, «добиваемая» цель, свободная цель у фриза) и на отдельном потоке;
щит для мозгов без своего (scripted, fly) относится к доле мозга и пропускается, когда в 12 тайлах нет фриза/смерти;
«sealed»-ответ живёт до 30 тиков, пока тий заморожен на том же тайле. Если решение мозга не успевает к ближайшему вводу
сессии (`next_input_in`), мир предсказывается на тик дальше (§21.1).

Аллокации: путь бота (LiveWorld, таблица игроков, часы, выбор цели, ключи, предсказание, наблюдение, кодирование) **не
аллоцирует** на снапшот в устоявшемся режиме — тест `a_steady_state_snapshot_allocates_nothing_in_the_bots_own_code`
(`allocation-counter`, 7 тиев, 200 снапшотов, 0 аллокаций). Вне этого пути остаются помощники `ddai-planner` (проверка
sealed для замороженных кандидатов, щит, вето хука) и сам мозг.

## Тесты

- модульные — в каждом файле (списки и нормализация, часы AFK, атрибуция, триггеры unstick, счётчик огня, мост, кольца
  задержки, модель летящих вводов, каждый член таблицы очков `pickTarget`);
- `tests/scenarios.rs` — 36 офлайн-сценариев на синтетических снапшотах (выбор цели, режимы, убийства и кулдауны, что
  получает мозг, постфильтры, жизненный цикл, аллокации);
- `tests/e2e_local_server.rs` — `#[ignore]` + `DDAI_E2E=1`: наш `--brain planner` против 1 и против 3 наших
  `--brain scripted` ≥ 2 минут на `Copy Love Box`: без паник и киков, блоки атрибутируются, аудит исходящих сообщений без
  чата, `Cl_Kill` только свои и не чаще кулдауна, веб-читатель получает карту/игроков (метками)/кадры/статус.

```bash
source ~/.cargo/env
cargo test -p ddai-bot
DDAI_E2E=1 DDAI_E2E_BRAINS=planner,hybrid cargo test --release -p ddai-bot --test e2e_local_server -- --ignored --nocapture --test-threads=1
# Играть и показывать на сайте:
ddnet-ai play --server 127.0.0.1:8303 --brain planner --name ddai-bot --duration 600
ddnet-ai web --bot-socket ~/aiddnet/data/bot/live.sock            # вкладка «Игра» показывает живую игру
```
