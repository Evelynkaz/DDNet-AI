# ddai-libm

Задача 5.5a (D-047, D-127). Листовой крейт без зависимостей и без `unsafe`: **переносимые, побитно точные порты математики glibc 2.39**.
Linux и Windows считают одни и те же числа.

## Зачем

Физика `ddai-physics` совпадает с сервером DDNet 20.1 побитно, потому что сервер на Linux зовёт glibc (`sinf`, `cosf`, `atanf`, `atan2f`,
`powf` и в `double` — `atan2`, `log`), а Rust на `linux-gnu` зовёт через `std` ту же glibc (D-004). На Windows `std` идёт в UCRT, у которой
последние биты другие: физика, поиск и предсказание молча разошлись бы с сервером. Крейт `libm` не выход (его `powf` расходится с glibc в 9,7%
проб, D-004), поэтому здесь порты алгоритмов самой glibc, и **все платформы пользуются ими**.

## Что внутри

| Функция | Символ glibc | Алгоритм | Лицензия источника |
|---|---|---|---|
| `sinf`, `cosf` | `sinf`, `cosf` | ARM optimized-routines `sincosf` (многочлен в double, редукция аргумента) | MIT |
| `powf` | `powf` | ARM optimized-routines `powf` (таблицы `log2` и `exp2` в double) | MIT |
| `log` | `log` | ARM optimized-routines `log` (таблица на 128 интервалов) | MIT |
| `pow` | `pow` | ARM optimized-routines `pow` (log и exp повышенной точности) | MIT |
| `atanf`, `atan2f` | `atanf`, `atan2f` | fdlibm (Sun) | разрешающая лицензия Sun |
| `atan2` | `atan2` | IBM Accurate Mathematical Library | LGPL-2.1+, используется под GPL-3 (ниже) |
| `hypotf`, `hypot` | `hypotf`, `hypot` | glibc (поправка Борджеса у `hypot`) | LGPL-2.1+, используется под GPL-3 |

Лицензии и обоснование — в `NOTICE` репозитория и в заголовке каждого файла. Об LGPL: раздел 3 LGPL 2.1 позволяет получателю применить к своей
копии обычную GNU GPL вместо LGPL; DDNet-AI целиком под GPL-3.0-only, файлы `atan2.rs` и `hypot.rs` используются под её условиями с сохранёнными
уведомлениями FSF/IBM и пометкой «Altered».

Использование: `ddai_libm::sinf(x)`, `ddai_libm::pow(x, y)` и т. д. Сигнатуры как у C.

## Какой именно glibc и откуда `mul_add`

Эталон — glibc 2.39 (Ubuntu 24.04) **на x86-64 с FMA3 и AVX2**: на таких CPU (все x86 за последнее десятилетие) загрузчик glibc (`ifunc`) выбирает
варианты `__sinf_fma`, `__powf_fma`, `__log_fma`, `__ieee754_atan2_fma`, `__pow_fma`. В них GCC слил `a + b * c` в fma, а код ARM для `log`/`pow`
идёт по веткам `__FP_FAST_FMA`. От варианта на чистом SSE2 результат отличается в последнем бите у малой доли входов (у `log` — 549 проб из 10⁷),
поэтому порты повторяют **именно слитые операции**: явные `f64::mul_add` ровно в тех местах, где они есть в машинном коде `libm.so.6`
(найдено по дизассемблированию и подтверждено пробами). Правило GCC такое: умножение, результат которого входит только в сложения/вычитания
того же базового блока, сливается с первым из них; умножение за ветвлением (`EADD`/`ESUB` у `atan2`) не сливается — на этом правиле
потрескались бы два места из 11,6 млн проб, пока его не нашли. `f64::mul_add` корректно округляется на любой платформе (аппаратная команда
или `fma` из libc), поэтому Windows даёт те же биты.

Последствие для скорости: без `+fma` в `RUSTFLAGS` (политика репозитория не кладёт `target-cpu` в конфиг, D-001) каждый `mul_add` — вызов `fma`
из libc, и порты медленнее glibc (таблица ниже). С `-C target-feature=+fma` они по скорости на уровне glibc. На результат это не влияет.

## Проверка

`tests/glibc_probe.rs` (только Linux: сравнивает с glibc через `std`, побитно, включая полезную нагрузку и знак NaN):

- `cargo test -p ddai-libm` — набор для CI: списки особых значений (±0, субнормальные, ±inf, NaN всех сортов, степени двойки и соседи,
  пороги каждой ветки) и по 10⁵ проб на функцию;
- `cargo test --release -p ddai-libm --test glibc_probe -- --ignored` — по 10⁷ проб (`LIBM_PROBES=n` меняет число);
- `… -- --ignored exhaustive` — **все 2³² входа** `f32` для `sinf`, `cosf`, `atanf` (3 потока, 2,5 мин на пару sin/cos);
- `… -- --ignored atan2_every_integer_aim_vector` — все целые векторы прицела в окне ±4096 (`LIBM_AIM=n`) для `atan2(int, int)`, как в
  `CCharacterCore::Tick`.

`tests/golden.rs` (**любая платформа**): фиксированная детерминированная последовательность проб (генераторы в `tests/common/mod.rs` используют
только целочисленную арифметику и базовые операции IEEE, без libm), результаты считаются здесь, хэши FNV по блокам по 4096 результатов лежат в
`tests/golden/hashes.txt` и записаны с самой glibc (`cargo test --release -p ddai-libm --test golden -- --ignored regenerate`). Это тест, ради
которого заведена Windows-задача CI: числа с Linux должны совпасть на Windows бит в бит.

Таблицы (`src/tables.rs`) порождает `tools/libm-tables/gen_tables.py` из исходников glibc 2.39 (`~/aiddnet/ref/glibc-2.39`).

## Скорость

`cargo run --release -p ddai-libm --example speed` (нс на вызов, лучшая из 5; пропускная способность — независимые вызовы, задержка — каждый
вызов ждёт предыдущий). Цифры и сравнение со сборкой `+fma` — в записи D-127 (`docs/DECISIONS.md`).
