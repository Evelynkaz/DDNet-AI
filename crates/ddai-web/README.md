# `ddai-web` — веб-сервер бота

axum + WebSocket, только `127.0.0.1` (Caddy — единственная публичная точка, задача 5.3). Вход по
паролю (argon2id), серверные сессии, CSRF/Origin-проверки, заголовки безопасности (задача 5.1) —
подробности в `src/auth/*`, `src/http/login.rs`, `src/headers.rs`.

## Живая карта (задача 5.2a; клиент заменён задачей 5.10, см. «Вкладка «Игра»» ниже)

Вкладка «Игра»: сервер шлёт карту один раз (классифицированную в маленькую палитру «kind» —
`src/live/scene.rs`) и дальше — поток компактных бинарных кадров мира по уже открытому,
аутентифицированному WebSocket. Живого бота ещё нет (задачи 2.3/2.4/4.x), поэтому источник кадров
абстрактный (`crate::live::source::FrameSource`), с одной настоящей реализацией сегодня —
воспроизведение трасс Oracle B (`crate::live::replay::ReplaySource`, задача 1.5).

Архитектура и байтовые форматы — `docs/formats.md`, раздел 14 (после раздела о протоколе DDNet
20.1, задача 2.2b). Коротко:

- `src/live/source.rs` — `FrameSource`, `WorldFrame`/`CharacterState`/`GameEvent`.
- `src/live/scene.rs` — классификация тайлов в 16 «kind» (воздух/стена/фриз/телепорт/…) с
  задокументированным приоритетом game+front+спец-слоёв; сжатие DEFLATE (`flate2`, без
  C-зависимости — тот же выбор, что и у `ddai-map`).
- `src/live/frame.rs` — бинарный формат кадра `live` (версия 1, 12 байт заголовок + 26 байт на
  персонажа); золотая байтовая фикстура + раунд-трип-тесты.
- `src/live/map_resolve.rs` — резолюция реальной `.map`-карты по sha256 **только** внутри
  настроенных `--maps-dir` (никогда не открывает путь из недоверенных метаданных трассы напрямую —
  берётся только имя файла, и байты всё равно перепроверяются по sha256).
- `src/live/replay/` — потоковый ридер trace-b v2 (не грузит файл целиком) + сам источник
  воспроизведения (управление play/pause/speed/seek/next через WS).
- `src/live/hub.rs` — фан-аут на все WS-подключения: `live`-кадры через lossy
  `tokio::sync::broadcast` (дроп при отставании клиента — критерий приёмки «не буферизовать
  безгранично»), остальные сообщения (`map`/`players`/`events`/`replay_status`/`live_error`) —
  через отдельный, менее интенсивный канал.
- `src/http/map.rs` — `GET /api/map/<sha256>` (аутентифицировано; `ETag` + недельный
  `Cache-Control: private, max-age=604800, immutable` — контент неизменен для данного sha256).

**Известное ограничение** (осознанный выбор объёма, не находка): текущее состояние
свитчей/дверей (открыт/закрыт) не транслируется — `MapScene` показывает только «здесь есть
свитч», без динамики; события `HammerHit`/`Teleport` из списка задачи тоже отложены (см. doc
comment в `src/live/replay/mod.rs`) — оба добавляются позже без breaking change формата.

## Вкладка «Игра»: настоящая карта, тии, табло, чат (задача 5.10, D-093)

Страница рисует **настоящую** карту DDNet и тий из скинов DDNet, следит камерой за ботом владельца и показывает табло, HUD и чат. Форматы, маршруты, порядок рисования и список того, чего
нет — `docs/formats.md` §35; решение и причины — D-093; разбор образца — `docs/research/web-redesign.md`.

- **WebGL2** (`assets/ddmap.js`): все группы и слои в порядке клиента (фон до игрового слоя, потом тии и крюки, потом передний план), параллакс и обрезка групп, тайловый слой — один четырёхугольник
  и шейдер с массивом из 256 текстур, квады с цветом на угол и огибающими цвета и позиции, три вида «сущностей» (карта / карта + сущности / только сущности). Нужен WebGL2: без него страница так и пишет. Слабый экран не тормозит страницу: при частоте ниже 22 к/с карта рисуется в меньшем разрешении (до 0,4), надписи остаются чёткими.
- **Сцена** достаётся на сервере в Rust (`ddai-map::scene`, `src/live/visual_scene.rs`) один раз на карту: `GET /api/map/<sha256>/scene` (raw DEFLATE, `ETag`, `immutable`), встроенные картинки — по одной
  `GET /api/map/<sha256>/image/<n>`. Файл карты берётся из `--maps-dir`/`<data-dir>/maps/cache` по пути, который запомнил источник (`MapCache::insert_path`), и пересверяется по sha256.
- **Графика DDNet** — `GET /assets/<путь>` из `--ddnet-data` (`data/` DDNet 20.1; по умолчанию `<data-dir>/../build/ddnet-20.1/build/data`, если есть), закрытый список путей, только после входа
  (`src/http/ddnet_assets.rs`): листы `game.png`, `hud.png`, `emoticons.png`, `extras.png`, наборы сущностей, шрифт, `mapres/<имя>.png`, `skins/<имя>.png`. Имена приходят из недоверенных данных, поэтому это
  простое имя файла, путь канонизируется и обязан остаться внутри каталога. **В git этих файлов нет и не будет (CC BY-SA 3.0)**; на странице и в `NOTICE` указаны авторы DDNet. Без `--ddnet-data` тии плоские, внешние картинки
  карты не рисуются, остальное работает; когда слоёв карты нет совсем, рисуется грубая геометрия из «kind»-сетки.
- **Тии** (`assets/ddtee.js`): тело, ноги, глаза по прицелу, руки, оружие, крюк (цепь и голова), замороженные и ниндзя (скин `x_ninja`), полоса заморозки, снежинки; свои цвета скина — перекраска как в клиенте.
  Бот владельца — золотое кольцо, плашка «БОТ», золотой ник, стрелка у края; камера следует за ним по умолчанию (свободная, «вся карта», выбор игрока, клик по тие).
- **Табло и HUD**: таблица игроков (счёт, имя, клан, пинг; кнопка «Табло» или удержание Tab), список игроков с тиями, карточка бота (состояние, режим, мозг, цель, блоки, смерти, p99 решения, переходы в «Муху» и «Бот»),
  оружие, FPS и пинг, лента «заморожен / разморожен / погиб».
- **Чат: панель только показывает** (`src/live/chat.rs`; поле ввода владельца под ней — отдельный модуль `say.js`, задача 5.11, раздел «Чат: строка владельца» ниже): бот пересылает строки `Sv_Chat` по мосту (`CHAT`, §21.2), веб чистит их как недоверенный ввод (управляющие, направление, нулевая ширина, длина) и держит **кольцо из 200 строк
  в памяти** (на диск и в журнал ничего не попадает), страница пишет текст только через `textContent`. В `game.js` нет ни поля ввода, ни сообщения, которое могло бы писать в чат; бот сам в чат не пишет (D-007, исключения — `/kill`, D-078, и строка владельца, D-094). Отправитель — тег `c<id>-<хэш>`,
  пока бот запущен без `--web-names` (в юните бота он включён, D-093: тогда ник и текст как есть).
- **Облик игроков** приходит сообщением моста `PLAYERINFO` (скин, цвета, страна, счёт, пинг), см. §35.3.
- **Вид сайта** — единая дизайн-система, раздел «Дизайн сайта» ниже (задача 5.14; прежний «DDNet-образец» с шахматным фоном и стеклянными панелями заменён).

Тесты: `cargo test -p ddai-map` (читатель сцены: порядок, роли, картинки, огибающие, враждебные размеры и усечения; на настоящих картах — `--test scene_real_maps`, пропускается без карт, `DDAI_MAPS_DIR` меняет каталог),
`cargo test -p ddai-web --test game_view` (кольцо чата на 200 строк, чистка враждебного текста, облик игроков, сцена и картинки, путь-имя картинки не доходит до страницы, `/assets` по закрытому списку и без выхода из каталога,
скрипты без `innerHTML` и без поля ввода чата в `game.js`, в разметке панели чата только пустой контейнер для `say.js`; состояние бота в сообщении `status`), `live::chat`, `live::visual_scene`, `http::ddnet_assets` (модульные), в боте — `bridge::tests` (кадр `CHAT`, `PLAYERINFO`) и `runner::tests` (теги вместо ников). Браузерный прогон —
`tools/e2e/game-view.spec.ts` (Playwright, поддельный бот на Node `tools/e2e/support/gamebot.mjs`, настоящий `ddnet-ai web` на другом порту; скриншоты `~/aiddnet/data/screenshots/5.10-*.png`, в git их нет).

## Дизайн сайта (задача 5.14)

Один спокойный тёмный стиль на всех вкладках и на входе. Всё лежит в `assets/app.css` (токены и общие компоненты); `game.css`, `launch.css`, `servers.css`, `say.css` только раскладывают свою вкладку и берут те же токены. Внешних шрифтов, CDN и картинок нет (CSP `default-src 'self'; img-src 'self'`): шрифт **Inter** (переменный, SIL OFL 1.1, подмножества латиница и кириллица, около 67 КБ) лежит в `assets/fonts/` и отдаётся
самим сайтом по `/fonts/inter-latin.woff2` и `/fonts/inter-cyrillic.woff2` (`Cache-Control: public, max-age=604800`); лицензия — `assets/fonts/LICENSE-Inter.txt` и `NOTICE`. Если шрифт не загрузился, работает системный стек (`system-ui`, Segoe UI, Roboto). Стрелка списка нарисована градиентами (`data:`-картинки CSP запрещает), иконки — прежние встроенные Lucide.

**Токены** (`:root` в `app.css`):

| Группа | Имена | Смысл |
|---|---|---|
| Поверхности | `--bg`, `--surface`, `--surface-2`, `--surface-3`, `--sunken`, `--line`, `--line-strong` | страница → карточка → приподнятый элемент → поле ввода; границы |
| Текст | `--text`, `--muted`, `--subtle` | на `--surface` контраст 14,7 / 7,1 / 5,0 : 1 (WCAG AA для обычного текста) |
| Акцент | `--accent`, `--accent-hover`, `--accent-active`, `--accent-text`, `--accent-soft`, `--accent-line`, `--focus`, `--bot` | синий «льда DDNet» для действий (белый на нём 5,1 : 1); золото `--bot` — личность бота (метка, «БОТ», ник) |
| Состояния | `--ok`, `--warn`, `--danger`, `--info` (+ `-soft` заливка, `-line` рамка), `--danger-solid` | текст, мягкая заливка и рамка каждого состояния; красная кнопка 5,2 : 1 |
| Размеры | `--sp-1…7` (4, 8, 12, 16, 24, 32, 48 px), `--r-sm/md/lg/pill`, `--sh-1/2`, `--ctl-h`, `--nav-h`, `--dock-h` | шкала отступов, радиусы, тени, высота полей, высота верхней панели / нижнего дока |
| Шрифт | `--font`, `--mono`, `--fs-xs…2xl` | Inter и системный запас; шкала 12 / 13 / 15 / 17 / 22 / 28 px |
| Движение | `--ease`, `--t-fast`, `--t` | 120 и 200 мс; при `prefers-reduced-motion` вся анимация выключается |

Палитры графиков («Муха» — `--fly-*`, «Обучение» — `--tr-*`) остались прежними (их читают `fly.js` и `train.js`, в `fly.js` это шестнадцатеричные строки), поверхности под ними подогнаны под новый `--surface`.

**Компоненты** (классы; разметка и id вкладок не менялись, кроме перечисленного в конце):

- **Кнопки:** `button` — основная (синяя), `button.alt` — вторичная, `button.danger` — опасная (красная), `:disabled`, `button.is-loading` — спиннер на нажатой кнопке (карточка «Запуск»: «Запустить» и «Остановить»). Фокус — кольцо `:focus-visible` (поля — рамка и тень).
- **Группы:** `.btn-group` — сегментированный переключатель (выбранный `.current`: режим и вейблок), `.btn-row` — несколько отдельных действий, `.inline-form` — поле и кнопка в строке.
- **Поля:** `input`, `select` (с градиентной стрелкой), `textarea`, флажки и ползунки с `accent-color`; на телефоне 44 px и 16 px шрифт (браузер не приближает страницу при фокусе).
- **Карточки:** `.card` (+ `h2`), списки «ключ — значение» `.kv`, `.hint` и `.hint.warn`, пустое состояние `.empty-state`, `details > summary` с шевроном, таблицы (`th` — мелкие капитальные подписи, цифры `tabular-nums`).
- **Состояния:** точка `.dot` (`dot-on` зелёная с пульсом, `dot-wait` янтарная, `dot-off` нейтральная: «выключено» не красное, ошибка видна бейджем и текстом), строка «точка + слово» (`.bot-conn`, `.lc-state`, `.gb-conn`) — таблетка, окрашенная точкой; бейджи `.badge` + `badge-ok / -warn / -bad / -info / -idle` (на «Статусе» — «в игре», «на паузе», «не запущен», «показ», «не подключено»), `.sv-badge`, `.tr-badge`, `.tr-state`; плашка источника `.source-badge` (живой бот — зелёная, показ — янтарная пунктирная, нет — нейтральная).
- **Сообщения:** `.result`, `.lc-result`, `.sv-result`, `.say-result`, `.error` — встроенное сообщение под формой; пустое скрыто, с `.ok` или `.bad` — окрашенная плашка с рамкой.
- **Навигация:** на экране от 900 px — верхняя панель с меткой (лицо ти на золоте) и вкладками «значок + название»; уже — нижний док из шести вкладок с подписями под значками. Раскладка по `body[data-view]` (`login`, `status`, `game`, `bot`, `servers`, `fly`, `train`), его ставит `app.js`.
- **Раскладка вкладок:** `.page` (заголовок `.page-head` с плашкой источника справа; колонка до 1180 px), `.page-grid` с двумя колонками `.page-col` от 1024 px («Бот»), для «Мухи» (`#fly-content`) два столбца от 1024 px.

**Правила, которые стоит помнить при правках стилей.** (1) Никакого `backdrop-filter`, `background-attachment: fixed` и анимации `box-shadow`: на сцене «Игры» и на графиках «Мухи» страница и так перерисовывается 25 раз в секунду, а в программном рендере (headless, слабый телефон) эти эффекты съедали кадры и сбивали частоту кадров по WebSocket в `live-map.spec.ts`; пульс точки — кольцо `::after` на `transform` и `opacity`. (2) `html { scrollbar-gutter: stable }` обязателен: графики «Обучения» растут вместе с шириной, и без зарезервированной полосы прокрутки раскладка могла бесконечно «дышать» (полоса то появлялась, то исчезала, и снимок элемента ждал «стабильности» до таймаута). (3) `[hidden] { display: none !important }` одно на всю страницу: теперь любой `display: flex` у элемента с `hidden` ничего не ломает. (4) Фон страницы — `--bg` с одним мягким свечением сверху; рисунков и `url()` в стилях, кроме двух шрифтов, нет (тест `security_headers.rs` это проверяет).

Что изменилось в разметке и скриптах (поведение прежнее): `body[data-view]`; кнопки «Стоп / Играть» и «В наблюдатели / В игру» теперь `.btn-row`, а не `.btn-group` (это отдельные действия, а не переключатель); «Статус» — три плитки (`.stat`); вкладка «Бот» — две колонки; метка в верхней панели; `app.js` красит бейджи «Соединение» и «Бот» на «Статусе» по слову состояния и ставит `body[data-view]`; `launch.js` добавляет `is-loading` нажатой кнопке; `fly.js` рисует подписи графиков шрифтом Inter. Текстовых меток не менялось.

Тесты: `cargo test -p ddai-web --test security_headers` (оба шрифта отдаются как woff2 с заголовками сайта, в `app.css` нет ни одного `url()`, кроме `/fonts/*`, остальные таблицы стилей — без `url()` и `@import`); браузерные прогоны — `tools/e2e/*.spec.ts` (в `training-panel.spec.ts` проверка панели вкладок исправлена с пяти на шесть: вкладку «Серверы» добавила 5.12); снимки всех вкладок — `tools/e2e/support/design-shots.mjs`.

## Запуск

```bash
# Однократно: пароль
cargo run -p ddnet-ai -- web-passwd --data-dir <scratch-dir> --show

# Без живой карты (только вход/статус, задача 5.1):
cargo run -p ddnet-ai -- web --listen 127.0.0.1:7788 --data-dir <scratch-dir>

# С графикой DDNet (вкладка «Игра» с настоящими тайлами и скинами): data/ клиента DDNet 20.1
cargo run -p ddnet-ai -- web --listen 127.0.0.1:7788 --data-dir <scratch-dir> --bot-socket <live.sock> \
    --maps-dir ~/aiddnet/data/maps/cache --ddnet-data ~/aiddnet/build/ddnet-20.1/build/data

# С живой картой — воспроизведение корпуса Oracle B (или одного .trb-файла):
cargo run -p ddnet-ai -- web --listen 127.0.0.1:7788 --data-dir <scratch-dir> \
    --replay ~/aiddnet/data/traces/oracle-b/v1/ \
    --maps-dir ~/aiddnet/data/ddnet-server/maps
```

`--maps-dir` можно указывать несколько раз. Никогда не запускать на проде (`deploy/install.sh` —
отдельный, управляемый процесс, задача 5.3) — только на отдельном loopback-порту со scratch
`--data-dir` для тестирования.

## Живой бот как источник кадров (задача 4.1)

`ddnet-ai web --bot-socket <путь>` (по умолчанию бот слушает `~/aiddnet/data/bot/live.sock`) подключает
`live::bot_source::BotSource`: `FrameSource`, который **только читает** Unix-сокет бота (`docs/formats.md` §21.2) и отдаёт
хабу карту (резолв только из `--maps-dir`/`<data-dir>/maps/cache` по `<имя>_<sha256>.map` с проверкой sha256), игроков
(метки `c<id>-<hash>`, не ники), кадры `DWLF` v1, события (заморозка/разморозка/смерть/возрождение/хват хука выводятся из
соседних кадров) и статус бота (WS-сообщение `{"type":"bot","status":{…}}`, строка «бот …» в HUD вкладки «Игра»).
Конфликтует с `--replay`. Потерянный сокет — повтор раз в секунду. Тесты: `live::bot_source::tests` (скриптовый «бот» на
настоящем сокете, враждебная длина сообщения, вывод событий) и e2e `ddai-bot/tests/e2e_local_server.rs` (настоящий бот).

## Управление ботом с сайта (задача 5.6, D-070)

Статус запуска несёт `preinput`, карточка «Запуск» пишет «ходы соперника от сервера», карточка «Бот» — строку «Ходы от сервера»: режим (`выкл (только счёт)` / `вкл` / `выкл (флажок)`), сколько сообщений пришло, **долю пар «снапшот, соперник», у которых новейшее сообщение впереди снапшота хотя бы на тик** (`known_ahead` выше 0), при «вкл» ещё долю решений, до которых ходы дошли (`decisions_real` из `decisions`, только по цели), и сколько раз персонажу не поверили (`distrusted` из `checked`).
Подсказка честна: помогает, только если сервер присылает ходы заранее (при запасе предсказания соперника по умолчанию, 10 мс, решение почти ничего не узнаёт заранее; вживую ход известен хотя бы на тик вперёд у 7,6% пар на joniTee 08.10, 8,0% на GER 07.10 и ≈ 0,2% в дуэли с человеком), бот только принимает.

**Дожим «ВБ (эксперимент)».** Четвёртое значение списка «Дожим» (`off|target|wb|full`, подпись «ВБ (эксперимент)», между «цель» и «полный»): `--finish wb` задачи 3.18 (D-114). Подсказка честна: для игры на ВБ, не для дуэли; на арене удержанных блоков +3,6 п.п. (36,1% → 39,7%), заранее объявленной планки (+4,0 п.п.) это не берёт; вживую не проверено; качели только в зале ВБ и в роли верхней полки, в остальном это «цель». Для чистой мухи — как у остальных значений `finish_hybrid_only`. Подпись в карточке «Бот» уже была («цель + удержание ВБ»).

### Кнопка «Дуэль» и «тишина машины» (задача 5.16, D-120; «Потоки поиска: 3» с 5.17)

**Кнопка «Дуэль»** на карточке «Запуск» одним нажатием **только заполняет форму**: мозг «Гибрид», «Дожим: полный», «Без самоубийств (дуэль)» — вкл, «Настоящие ходы соперника от сервера» — **выкл** (вживую ход известен заранее в ~0,2–8% случаев, пользы против соперника с запасом по умолчанию нет), «Предсказатель соперника» — выкл, «Умный ВБ» — выкл, «Потоки поиска» — 3 (задача 5.17). Ничего не отправляется, ничего не запускается: владелец проверяет форму и сам нажимает «Запустить». Сервер, длительность, спарринг и «Предсказание соперника» (модель самого гибрида) кнопка не трогает. Кнопка подсвечена (`.current`, `aria-pressed`), пока форма совпадает с пресетом; любая правка вручную снимает подсветку и сообщение «Форма заполнена для дуэли». Под кнопкой раскрывающийся список «Что ставит «Дуэль» и почему»: у каждого значения подсказка с числами и оговорками (дожим: +4,3 ± 2,2 п.п. на 1800 парных играх арены, +7,5 ± 4,1 п.п. на тихой машине, плечо выбрано после просмотра таблицы, соперник в арене один, вживую не проверено; ходы сервера выкл: хотя бы на тик вперёд ход известен у 7,6% пар на joniTee, 8,0% на GER, ≈ 0,2% в дуэли с человеком; тихая машина: 14,2 кандидата на решение под нагрузкой 18–30 против ≈ 27 в арене при часах тихой машины (вживую на тихой машине ещё не измерено)).

**Новых полей запроса у 5.16 нет** (с 5.17 пресет несёт ещё `search_threads: 3`, см. ниже). Пресет — это сочетание полей запроса (`brain`, `finish`, `no_selfkill`, `search_threads`; выключенные `preinput`, `wb_smart` и `window_model` — отсутствие полей), доверенная граница root-помощника не изменилась: булевы значения и закрытые списки, `deny_unknown_fields`. Подпись «полный» теперь «полный (только дуэль 1 на 1)», подсказка называет числа и оговорки и говорит, что в толпе берите «цель» (подтягивание само по себе там ничего не добавляло: 257 против 259 удержанных блоков); если выбран «полный», а «Без самоубийств (дуэль)» выключено, подсказка добавляет «похоже, это не дуэль 1 на 1» и краснеет.

**Тишина машины.** `GET /api/bot/status` получил поле `host`: `{load1, load5, load15, cpus}` из `/proc/loadavg` (читается на каждый запрос, не больше 256 байт; `null`, если файл не читается или это не load average; путь в `WebConfig::loadavg_path`, для тестов). Оно есть и без бота, чтобы владелец видел загрузку до «Запустить». Из STATUS бота сайт передаёт без изменений аддитивное поле `search_window` (формат — `docs/formats.md` §54). В карточке «Состояние» две строки, «Машина: нагрузка» и «Машина: поиск бота» (кандидатов на решение в среднем за 30 с игры, p90 времени решения, число решений), и предупреждение «машина загружена — бот думает хуже», если **нагрузка за минуту выше 6** или **меньше 20 кандидатов на решение** (среднее считается, только если решений в окне не меньше 25). Та же строка (нагрузка и, пока бот играет, поиск) стоит под кнопкой «Дуэль». Суждение — одна чистая функция `LaunchCard.quietness(host, search_window, brain)` (порог кандидатов судится только у гибрида; у другого мозга число показывается без суждения) в `launch.js`, её же вызывает `app.js`. Оговорки в подсказке на странице: порог 20 взят из дуэли 1 на 1, в толпе число может быть другим (не измерено); ничего никуда не отправляется.

Тесты: `cargo test -p ddai-web --lib http::bot` (разбор `loadavg`, чтение файла), `--test bot_control` (`host` и сквозная передача `search_window`), `--test launcher` (запрос пресета состоит из старых полей, поле `preset` отвергается, каждое присваиваемое `body.<поле>` в `launch.js` — известное помощнику), `cargo test -p ddnet-ai --test launch_apply` (помощник пишет слова дуэли), Playwright `tools/e2e/launch-options.spec.ts` через `tools/e2e/options-e2e.sh` (пресет, строки «Машина» на подставленных ответах STATUS, настоящий `search_window`).

## Вкладка «Серверы»: список, избранное, прокси (задача 5.12, D-099)

Как у конкурента: владелец выбирает **любой** сервер DDNet для бота, ведёт избранное и свои прокси, для каждого сервера выбирает «напрямую» или через прокси. Подтверждение администратора сервера записывается (`consent_at`). Формат файлов и маршрутов — `docs/formats.md` §36, решение и правила, которые остаются (кик/бан закрывает сервер до «Открыть снова», бот сам не меняет прокси и IP, один бот на сервер) — D-099, установка — `deploy/README.md`.

**У веба по-прежнему нет сети.** Список — кэш, который пишет отдельный юнит (`ddnet-ai servers-cache`); сайт просит обновление, переписывая `launch/servers-refresh`. «Проверить» прокси — маленький запрос `launch/proxycheck-request.json`, ответ читается из `launch/proxycheck-result.json`. Избранное — `launch/favourites.json`, профили — `secrets/<имя>-proxy.toml` (0600): оба каталога уже были в `ReadWritePaths`, юнит веба не менялся.

- `src/serverbrowser/` — `mod.rs` (общие типы с `ddnet-ai`: `BlockedFile`, `ProxyCheckRequest/Result`, `RateGate`), `cache.rs` (чтение кэша тем же строгим разбором, что писал), `favourites.rs` (запись под замком, каждый результат проверяется целиком `ddai_client::favourites`, нечитаемый файл не перезаписывается), `proxies.rs` (профили: публичный IP-литерал, формат бота, `managed_by`, пароль только записывается, ручной файл не трогается).
- `src/http/servers.rs` — маршруты (`GET /api/servers`, `/api/favourites`, `/api/proxies`; `POST /api/servers/refresh`, `/api/favourites/{add,update,remove,reopen}`, `/api/proxies/{save,remove,check}`). Каждый POST: сессия, строгий Origin, CSRF, JSON и свой лимит на **каждую** попытку. «Открыть снова» пишет только `reopened_at` и только для сервера, закрытого сейчас (закрытие знает помощник: `/run/ddnet-ai/blocked.json`). В журнале — тег сессии и вид действия, никогда адрес, имя или значение прокси.
- `GET`/`POST /api/bot/launch` предлагает и принимает избранное (закрытое — `409 blocked_after_ban`); помощник проверяет заново.
- Страница: `assets/servers.js` (`ServersPanel.mount(корень, api, {play})` из `app.js`; три панели «Список» / «Избранное» / «Прокси»; всё через `textContent`), `assets/servers.css` (всё под `.servers-view`), вкладка в `index.html`. «Играть здесь» открывает вкладку «Бот» с этим сервером в карточке «Запуск» (`LaunchCard.preselect`).
- Конфиг `WebConfig`: `servers_dir` (`<data-dir>/servers`), `favourite_rules` (`Rules::current()`: без loopback), `refresh_min_gap`, `proxycheck_min_gap`, `proxycheck_max_per_minute`, `servers_edits_per_minute`.

Проверка: `cargo test -p ddai-web serverbrowser` (модульные: профили и вредные поля, запись избранного, кэш) и `cargo test -p ddai-web --test servers` (14 тестов маршрутов: 401/403/415 и «ничего не записано» на каждом маршруте, лимиты, вредные адреса/имена/ники/поля прокси, согласие, **бан → закрыто → правка прокси не открывает → «Открыть снова»**, пароль ни в одном ответе и журнале, ручной файл прокси не трогается, проверка, обновление). Браузером — `tools/e2e/servers.spec.ts` (`tools/e2e/servers-e2e.sh`, частный сервер на 127.0.0.1:8463; публичные серверы не затрагиваются).

## Чат: строка владельца идёт в игровой чат (задача 4.9, D-094)

Единственный чат бота — запасной `/kill` (D-078) и то, что владелец набрал здесь (D-094; D-007 для всего автоматического в силе: ни автоответов, ни LLM, ни периодических сообщений, ни приказов из игрового чата).

- `src/http/say.rs` — `POST /api/bot/say`, тело `{"team":bool?,"text":"…"}`. Origin (строгий) -> сессия -> CSRF -> JSON (`authorize_post`, как другие POST, D-070); текст судит `OwnerText::normalise` (те же правила, что у бота; значения `OwnerText` у сайта нет: его делает только диспетчер бота с `OwnerChannel`): не пусто, ≤ 255 байт, без управляющих и невидимых символов и переводов строки, не строка-ловушка 20.1 (**строка, начинающаяся с `/`, с задачи 4.9b принимается**: серверная команда, набранная владельцем, идёт тем же путём; пробелы DDNet по краям обрезаются); на бот уходит обрезанный текст; **свой лимит** (`WebConfig::say_burst` 2 запроса за `say_burst_window` 3 с и `say_max_per_minute` 10; слот берёт только прошедшая проверку строка, опечатка слота не стоит). Бот проверяет ещё раз и сам ограничивает частоту (3 с между строками, 10 в минуту, очередь 3, вне игры — отказ). Ответ `{"ok","text","reason"}`: 200; 400 `invalid_text` (`detail`: `empty` / `too_long` / `control` / `reserved`; `command` убран в 4.9b) или `bad_request`; 409 `not_in_game` или `chat_disabled` (у бота включён `--no-owner-chat`); 429 `rate_limited` / `queue_full`; 503 `bot_unavailable` / `demo_only`; 504; 502. `POST /api/bot/command` команду `say` **не принимает** (400 `use_say_route`).
- Текст строки не пишется нигде: в журнале сайта метка сессии, сторона чата, длина и исход; в ответе его нет.
- `assets/say.js` + `assets/say.css` — поле ввода (`SayCard`), свои файлы, всё под `.say-card`, тексты через `textContent`. С задачи 5.11 стоит на вкладке «Игра» под панелью чата (`embedded: true`, ниже); других мест отправки чата нет.
- Проверка: `cargo test -p ddai-web --test say` (14 тестов: без сессии / без CSRF / с чужим Origin / не JSON — отказ и ничего не доходит до бота; строка доходит до поддельного бота как `Say` с обрезанным текстом; невалидные строки не доходят и не расходуют лимит; третья быстрая — 429 от сайта; отказы бота и их статусы; общий маршрут `say` не берёт; ассеты отдаются; 4.9b: строка с `/` в начале доходит до бота как набрана, а `\u{200B}/kill`, перевод строки внутри команды и слишком длинная команда отказываются по обычным причинам). Сквозная проверка с настоящим сервером и ботом — `crates/ddnet-ai/tests/e2e_owner_chat.rs` (`DDAI_E2E=1 cargo test -p ddnet-ai --test e2e_owner_chat -- --ignored --nocapture --test-threads=1`: частный сервер на 127.0.0.1:8413 / econ 8414, останавливается сам); серверные команды — `crates/ddnet-ai/tests/e2e_owner_commands.rs` (127.0.0.1:8473 / econ 8474: `/emote`, `/info` исполнены сервером и не разосланы как чат, `/kill` владельца — строка владельца, `/spec` и `/pause` ставят бота на паузу, `STATUS` говорит `paused`, повтор снимает её, бот не останавливается).

### Где стоит поле ввода (задача 5.11)

Поле ввода стоит на вкладке **«Игра», прямо под списком сообщений панели чата** (`<div id="game-say-mount">` внутри `.chat-card` в `index.html`; `app.js` зовёт `SayCard.mount(el("game-say-mount"), api, { embedded: true })` рядом с `LaunchCard`, `api` — тот же помощник с сессией и CSRF-токеном). В облике 5.10: полупрозрачное тёмное поле, как у списка сообщений, кнопка «Сказать», «Командный чат», счётчик `n / 255`, под полем строка «/spec и /pause ставят бота на паузу; повторите команду — продолжит» (4.9b: строка с `/` в начале — серверная команда; `/spec` и `/pause` ставят бота на паузу на сервере, бот при этом не останавливается и сам стоит (`STATUS.paused`, сайт пишет «на паузе»: слово `bot_state: paused` и строка карточки «Бот») — паузу снимает повтор команды; `.say-note` в `say.css`); на телефоне шрифт поля 16 px (браузер не приближает страницу при фокусе), всё в ширину экрана. Enter в поле отправляет (обычная отправка формы). Отказы показываются под полем: страница сама (пусто, длинно, невидимые символы), сайт (лимит, сессия, «показ, а не бот»), бот (`not_in_game`, `rate_limited`, `queue_full`); принятая строка стирается, отказанная остаётся для повтора.

- **`chat_disabled`** (бот запущен с `--no-owner-chat` или `owner_chat = false`): поле блокируется (поле, «Командный чат», кнопка) и под ним остаётся причина, пока вкладку «Игра» не откроют снова (`SayCard.onShown()` из `showTab`): флаг меняется только перезапуском бота, спрашивать его на каждую строку незачем. Узнать это заранее нельзя: `STATUS` моста поля `owner_chat` не несёт, поэтому состояние появляется после первой же отказанной строки.
- **Подсказка над панелью** — «Бот сам в чат не пишет; здесь можно написать от его имени».
- **Вкладка «Бот»**: карточку с полем **заменили указателем** («Поле ввода в игровой чат теперь на вкладке «Игра»», кнопка «К чату ▸», `#bot-to-chat`). Второе поле не оставили: два одинаковых поля делят один лимит сайта (2 за 3 с, 10 в минуту) и одно состояние `chat_disabled`, а отказ под полем, которого владелец сейчас не видит, сбивает с толку; писать удобнее там, где видна игра и куда придёт ответ сервера. Указатель нужен тем, кто помнит старое место.
- Свои строки появляются в панели так же, как чужие, когда сервер вернёт их (`Sv_Chat`): эха на странице нет сознательно (строка, которую бот не сказал, не должна выглядеть сказанной).
- Проверка страницы: `tests/say.rs::the_chat_inputs_assets_are_served_and_the_page_mounts_them` (контейнер на вкладке «Игра», старого `say-mount` нет), `tests/game_view.rs` (разметка панели чата — только пустой контейнер под списком; `game.js` по-прежнему не шлёт чат); Playwright — `tools/e2e/game-view.spec.ts` (последние четыре теста: поле под панелью, Enter и кнопка, строка доходит до поддельного бота `gamebot.mjs` на сокете управления и возвращается в панели, отказы под полем, `chat_disabled` блокирует и снимается при возврате на вкладку, телефон 390×844, состояние на «Статусе»).

## Состояние бота на вкладке «Статус» (задача 5.11)

WS-сообщение `{"type":"status","uptime_s":N,"bot_state":"…"}` раз в секунду. `bot_state` раньше всегда был `"idle"`; теперь его берёт `ws.rs::bot_state_word` из живого моста: `in_game` (свежий `STATUS`, `connected` не `false` — у старого бота поля нет, он считается в игре), `connecting` (свежий `STATUS` с `connected:false`: бот запущен, но не в игре), `stopped` (нет моста, нет `STATUS` или он старше `STATUS_STALE`, 3 с; источник «нет») и `demo` (на сайте показ мухи, не бот). Страница переводит слова в «в игре» / «запущен, не в игре» / «не запущен» / «показ (не настоящая игра)» (`BOT_STATE_TEXT` в `app.js`), незнакомое слово выводит как есть. Проверка: модульный `ws::tests::the_bot_state_follows_the_live_status` (все ветви и граница 3 с), `tests/game_view.rs::the_status_message_tells_the_real_state_of_the_bot` (поддельный мост: `stopped` → `connecting` → `in_game`, старый `STATUS` без `connected`, замолчавший бот → `stopped`), `tests/websocket.rs` (сайт без моста — `stopped`).

### «Потоки поиска» на карточке «Запуск» (задача 5.17, D-125)

Выбор «Потоки поиска»: «1 (по умолчанию)», 2, 3, 4 — сколько потоков оценивают кандидатов гибрида (`ddnet-ai play --search-threads`). Поле запроса `search_threads` — **JSON-целое из закрытого списка {1, 2, 3, 4}** (`ddai_web::launch::SearchThreads`, разбор отвергает 0, 5 и выше, отрицательное, дробное, строку, `auto`, булево и массив; `deny_unknown_fields` прежний). Сайт шлёт поле **только при значении выше 1**: без него запрос побайтно прежний. Путь: помощник всегда пишет `BOT_SEARCH_THREADS="1".."4"` (одна из четырёх статических строк), юнит передаёт `--search-threads ${BOT_SEARCH_THREADS}`; формат — `docs/formats.md` §57.

Для чистой мухи (она не ищет) выбор скрыт и не отправляется; запрос с `search_threads` 2–4 для неё сайт и помощник отклоняют кодом `search_threads_hybrid_only`, `1` проходит как «нет поля».

Подсказка к каждому значению честна: числа замера 4.13 с тихой машины (кандидатов на решение, медиана одного прогона на значение: 24–25 / 29 / 38 / 44 при 1 / 2 / 3 / 4 потоках), p99 времени решения не хуже, помощник занимает около 5% ядра, пул конечен (≈ 55–62 кандидата); «только на тихой машине: под нагрузкой больше потоков отнимает процессор у сборок и может не помочь»; тихая — условие исследования (`perf-4.13.md`, раздел 6): нагрузка < 2 и не меньше 4 свободных ядер; «больше кандидатов не значит больше побед» (силу от числа потоков не измеряли). Кнопка «Дуэль» ставит 3; пункт «Потоки поиска: 3» есть и в списке «Что ставит «Дуэль» и почему».

**Под нагрузкой.** Если нагрузка хоста выше порога 6 (тот же, что у «тишины машины») и выбрано больше одного потока, подсказка добавляет «Машина загружена: потоки поиска сверх 1 отнимают процессор у сборок и могут не помочь — выберите 1» и краснеет; ничего не блокируется, «Дуэль» по-прежнему ставит 3. **Порог кандидатов следует за потоками:** 20 из 5.16 откалиброван для одного потока, поэтому `LaunchCard.quietness(host, search_window, brain, threads)` берёт порог по STATUS `search_threads`: 20 / 24 / 31 / 36 при 1 / 2 / 3 / 4 потоках (20, умноженное на отношение медиан 4.13: 24–25 → 29 → 38 → 44, округлено); неизвестное число (бот старой сборки, запущенный вручную 8 потоков) оставляет 20. Рядом с числом кандидатов страница пишет «потоков поиска: N» (только у гибрида). Пороги для N > 1 выведены масштабированием одного прогона на значение и вживую не проверены.

Статус помощника несёт `search_threads` (карточка «Запуск» пишет «потоки поиска: N» при N > 1), STATUS бота — `search_threads` (аддитивное; карточка «Бот», строка «Потоки поиска»: число; `—` для бота старой сборки, неопределённого значения и мозга, который не гибрид).

Тесты: `cargo test -p ddai-web --lib launch` (закрытый список на разборе, отказы), `--test launcher` (запрос, статус, ключи `launch.js`, пресет с `search_threads: 3`), `cargo test -p ddnet-ai --test launch_apply --test deploy_units` (настоящий помощник пишет слова, отказы, юнит и установщик), `cargo test -p ddai-bot --lib bridge` (поле STATUS), Playwright `tools/e2e/launch-options.spec.ts` через `tools/e2e/options-e2e.sh` (выбор, подсказки, скрытие для мухи, пресет, настоящий запуск с 3 потоками и затем с 1).

### «Исправления дуэли» на карточке «Запуск» (задача 5.18, D-129)

Выбор «Исправления дуэли»: «выкл (по умолчанию)», «добивание», «стоячая цель и добивание» — исправления слабостей дуэли 3.23 (`ddnet-ai play --duel-fixes`, D-121; действуют только в распознанной дуэли). Поле запроса `duel_fixes` — **строка из закрытого списка из трёх слов** `off`, `finish`, `static,finish` (`ddai_web::launch::DuelFixes`; разбор отвергает всё остальное: `counter`, `all`, `static`, другой порядок, регистр, пробелы, пустую строку, число, булево, массив; `deny_unknown_fields` прежний). `counter` в список не входит: он no-go (в арене поднимает таймауты). Сайт шлёт поле **только при значении не `off`**; нет поля = `off`, и запрос побайтно прежний. Помощник всегда пишет `BOT_DUEL_FIXES="off"|"finish"|"static,finish"` (одна из трёх статических строк), юнит передаёт `--duel-fixes ${BOT_DUEL_FIXES}`. Формат — `docs/formats.md` §59.

Для чистой мухи выбор скрыт и не отправляется; запрос с `finish` или `static,finish` для неё сайт и помощник отклоняют кодом `duel_fixes_hybrid_only`, `off` проходит как «нет поля».

Подсказки честные: числа D-121 (добивание — сценарии 57,7% → 90,4% удержания, нулевой ввод 34% → 15%, дуэль против `live-v2` +1,7 ± 2,0 п.п., p 0,13; стоячая цель — большой эффект в сценарии, но планку по букве не взяла и в арене сочетание вместе −0,7 ± 3,3 п.п., p 0,77), «работает только в распознанной дуэли; вживую не проверено», «силу вживую не измерить: сравнивайте плечи по журналу». **Пресет «Дуэль» их не включает** и ставит «выкл» (в подсказке и в списке «Что ставит «Дуэль»» сказано, что это до живого сравнения плеч); запрос пресета остаётся прежним. Статус помощника несёт `duel_fixes` (карточка «Запуск»: «исправления дуэли: …» при значении не `off`), STATUS бота — `duel_fixes` (карточка «Бот», строка «Исправления дуэли»; `—` для старого бота, чистой мухи и списка с неизвестным словом).

Тесты: `cargo test -p ddai-web --lib launch` (закрытый список на разборе, отказы), `--test launcher` (запрос, статус, ключи `launch.js`, пресет без `duel_fixes`), `cargo test -p ddnet-ai --test launch_apply --test deploy_units` (настоящий помощник пишет слова, отказы и подмена окружения, юнит и установщик), `cargo test -p ddai-bot --lib` (`bridge`, `brains::duel_fixes_name`), Playwright `tools/e2e/launch-options.spec.ts` через `tools/e2e/options-e2e.sh` (выбор, подсказки, скрытие для мухи, пресет, строка «Бот», настоящий запуск с `static,finish` и затем с `off`).
