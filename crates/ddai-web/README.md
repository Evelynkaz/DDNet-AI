# `ddai-web` — веб-сервер бота

axum + WebSocket, только `127.0.0.1` (Caddy — единственная публичная точка, задача 5.3). Вход по
паролю (argon2id), серверные сессии, CSRF/Origin-проверки, заголовки безопасности (задача 5.1) —
подробности в `src/auth/*`, `src/http/login.rs`, `src/headers.rs`.

## Живая карта (задача 5.2a)

Вкладка «Игра»: сервер шлёт карту один раз (классифицированную в маленькую палитру «kind» —
`src/live/scene.rs`) и дальше — поток компактных бинарных кадров мира по уже открытому,
аутентифицированному WebSocket. Живого бота ещё нет (задачи 2.3/2.4/4.x), поэтому источник кадров
абстрактный (`crate::live::source::FrameSource`), с одной настоящей реализацией сегодня —
воспроизведение трасс Oracle B (`crate::live::replay::ReplaySource`, задача 1.5).

Архитектура и байтовые форматы — `docs/formats.md`, раздел 14 (после раздела о протоколе DDNet
20.1, задача 2.2b). Коротко:

- `src/live/source.rs` — `FrameSource`, `WorldFrame`/`CharacterState`/`GameEvent`.
- `src/live/scene.rs` — классификация тайлов в 16 «kind» (воздух/стена/фриз/телепорт/…) с
  задокументированным приоритетом game+front+спец-слоёв; сжатие DEFLATE (`flate2`, без
  C-зависимости — тот же выбор, что и у `ddai-map`).
- `src/live/frame.rs` — бинарный формат кадра `live` (версия 1, 12 байт заголовок + 26 байт на
  персонажа); золотая байтовая фикстура + раунд-трип-тесты.
- `src/live/map_resolve.rs` — резолюция реальной `.map`-карты по sha256 **только** внутри
  настроенных `--maps-dir` (никогда не открывает путь из недоверенных метаданных трассы напрямую —
  берётся только имя файла, и байты всё равно перепроверяются по sha256).
- `src/live/replay/` — потоковый ридер trace-b v2 (не грузит файл целиком) + сам источник
  воспроизведения (управление play/pause/speed/seek/next через WS).
- `src/live/hub.rs` — фан-аут на все WS-подключения: `live`-кадры через lossy
  `tokio::sync::broadcast` (дроп при отставании клиента — критерий приёмки «не буферизовать
  безгранично»), остальные сообщения (`map`/`players`/`events`/`replay_status`/`live_error`) —
  через отдельный, менее интенсивный канал.
- `src/http/map.rs` — `GET /api/map/<sha256>` (аутентифицировано; `ETag` + недельный
  `Cache-Control: private, max-age=604800, immutable` — контент неизменен для данного sha256).

**Известное ограничение** (осознанный выбор объёма, не находка): текущее состояние
свитчей/дверей (открыт/закрыт) не транслируется — `MapScene` показывает только «здесь есть
свитч», без динамики; события `HammerHit`/`Teleport` из списка задачи тоже отложены (см. doc
comment в `src/live/replay/mod.rs`) — оба добавляются позже без breaking change формата.

## Запуск

```bash
# Однократно: пароль
cargo run -p ddnet-ai -- web-passwd --data-dir <scratch-dir> --show

# Без живой карты (только вход/статус, задача 5.1):
cargo run -p ddnet-ai -- web --listen 127.0.0.1:7788 --data-dir <scratch-dir>

# С живой картой — воспроизведение корпуса Oracle B (или одного .trb-файла):
cargo run -p ddnet-ai -- web --listen 127.0.0.1:7788 --data-dir <scratch-dir> \
    --replay ~/aiddnet/data/traces/oracle-b/v1/ \
    --maps-dir ~/aiddnet/data/ddnet-server/maps
```

`--maps-dir` можно указывать несколько раз. Никогда не запускать на проде (`deploy/install.sh` —
отдельный, управляемый процесс, задача 5.3) — только на отдельном loopback-порту со scratch
`--data-dir` для тестирования.

## Тесты

```bash
cargo test -p ddai-web                                  # юнит + интеграционные (без реального корпуса)
cargo test -p ddai-web --test replay_real_corpus -- --ignored   # сверка с реальным корпусом Oracle B
                                                                   # (нужен ~/aiddnet/data/traces/oracle-b/v1/)
```

`tools/e2e/live-map.spec.ts` (Playwright, реальный браузер) — см. `tools/e2e/README.md`.

## Живой бот как источник кадров (задача 4.1)

`ddnet-ai web --bot-socket <путь>` (по умолчанию бот слушает `~/aiddnet/data/bot/live.sock`) подключает
`live::bot_source::BotSource`: `FrameSource`, который **только читает** Unix-сокет бота (`docs/formats.md` §21.2) и отдаёт
хабу карту (резолв только из `--maps-dir`/`<data-dir>/maps/cache` по `<имя>_<sha256>.map` с проверкой sha256), игроков
(метки `c<id>-<hash>`, не ники), кадры `DWLF` v1, события (заморозка/разморозка/смерть/возрождение/хват хука выводятся из
соседних кадров) и статус бота (WS-сообщение `{"type":"bot","status":{…}}`, строка «бот …» в HUD вкладки «Игра»).
Конфликтует с `--replay`. Потерянный сокет — повтор раз в секунду. Тесты: `live::bot_source::tests` (скриптовый «бот» на
настоящем сокете, враждебная длина сообщения, вывод событий) и e2e `ddai-bot/tests/e2e_local_server.rs` (настоящий бот).

## Управление ботом с сайта (задача 5.6, D-070)

Вкладка «Бот» (только после входа): **состояние** (в игре / не в игре / бот не запущен, сервер, карта, режим, мозг, метка цели, вейблок, блоки, смерти, клипы, задержка решения, облик), **команды** (режим, стоп/ход, вейблок,
смена мозга, kill с показом кулдауна, клип с предупреждением, что заметка попадёт в делимый клип, `goto x y`, наблюдатель / в игру) и **редактор списков** (друзья, война, игнор, клан-друзья, клан-война: добавить / убрать, видно свёрнутую форму;
точное совпадение после нормализации, D-021). Формат и маршруты — `docs/formats.md` §26.

- `src/control/client.rs` — клиент сокета управления бота (`<data-dir>/bot/control.sock`, `--control-socket`): одно соединение на запрос, ограничены время и размер ответа; только `connect`.
- `src/control/relations.rs` — `relations.json` (`<data-dir>/bot/relations.json`, `--relations`, `0600`): правка под замком, атомарная запись, нечитаемый файл не перезаписывается; тот же код, что у бота (`ddai-botctl`).
- `src/http/bot.rs` — `GET /api/bot/status`, `POST /api/bot/command`, `GET`/`POST /api/bot/relations`. Все — за сессией; POST — строгий Origin (`origin::is_strict_same_origin`), CSRF, JSON. Имена не логируются (в журнале — метка сессии, тег команды, счётчики).
- Сайт **не может**: писать в чат, подключать бота куда-либо, менять allowlist и флаг `ready` (такого слова в словаре команд нет, `live-servers.toml` он не трогает).

Проверка: `cargo test -p ddai-web --test bot_control` (20 тестов: без сессии / без CSRF / с чужим Origin — отказ и ничего не доходит до бота; команда доходит до поддельного бота на настоящем сокете и ответ виден; правка списков туда-обратно через файл; имена и заметки
не в журнале; бот не запущен / враждебный сокет) и Playwright `tools/e2e/bot-control.spec.ts`. Тестировать только на отдельном порту со своим `--data-dir`, не на проде.

## Вкладка «Муха» (задача 7.4)

Что делает сеть на коннектоме, пока играет (FLY.md §10): тепловые полосы активности групп нейронов (по нейропилю и типу, последние
секунды, подписи слева, число справа), полярный график «глаза» с каналами (переключатели каналов, белая линия — прицел), столбики
выходов DN по головам действий и полоса всех DN, декодированное действие (вероятности направления, прыжок / хук / огонь, угол
прицела), малые временные ряды (частота по семействам, вероятности действий, время решения; у гибрида — доля сыгранных предложений
мухи), имя и хэш весов, таблица тем же текстом. Русский, только после входа, телефон и десктоп; палитра — токены `--fly-*` в
`app.css` (семейства, семь каналов глаза, расходящаяся пара для z-оценок, одноцветная рампа частот), проверена валидатором палитры
на тёмной поверхности; рисование — на `<canvas>` (CSP запрещает встроенные стили), текст — только `textContent`.

- `assets/fly.js` — панель (`window.FlyPanel`), `assets/index.html` / `app.css` — разметка; `app.js` лишь переключает вкладку и
  раздаёт сообщения (`fly_meta`, бинарные кадры `DFLY` отличаются от `DWLF` по первым байтам). Вкладка подписывается при показе и
  отписывается при уходе; на телефоне по умолчанию 6 кадров/с, на десктопе 12.
- `src/ws.rs` — `{"type":"fly","hz":N}` (зажим `max_fly_hz`, 15), ответ `fly_meta`, бинарные кадры с ограничением частоты на соединение.
- `src/live/hub.rs` — `subscribe_fly()` (счёт зрителей под замком, сигнал спроса источнику только при смене), `latest_fly_meta()`.
- `src/live/bot_source.rs` — пишет в мост единственное сообщение: подписку на поток мухи, пока кто-то смотрит (и после
  переподключения); принимает `FLYMETA`/`FLY`, проверяя их (`src/live/fly.rs`: магия, версия, длина по счётчикам, ≤ 64 КиБ).
- Формат — `docs/formats.md` §27. Тесты: `tests/fly_panel.rs` (без сессии и с чужим Origin — отказ; подписка доходит до поддельного
  бота и снимается при `hz: 0` и при закрытии страницы; два зрителя; кадры байт в байт и по порядку; потолок частоты; порченые кадры
  не доходят до браузера и дают одно сообщение; без бота — `null`; страница и `/fly.js` с заголовками сайта и без `innerHTML`),
  модульные тесты хаба и `live::fly`, Playwright `tools/e2e/fly-panel.spec.ts` (офлайн-источник `fly watch` + настоящий `ddnet-ai web`,
  скриншоты десктоп и телефон в `~/aiddnet/data/screenshots/7.4-*.png`, в git их нет).

## Показ: демо мухи за живым ботом (задача 5.7, D-075)

`ddnet-ai web --bot-socket <live.sock> --demo-socket <fly-demo.sock>`: пока живой бот не запущен, «Игра» и «Муха» показывают офлайн-демо (`ddnet-ai fly watch`, муха играет
арену `clb-left`), под плашкой «Показ: муха на арене (не настоящая игра)» (карта, арена, веса); когда мост бота поднимается, сайт сам переключается на него («Живой бот»), когда
пропадает, возвращается к демо. Формат и правила — `docs/formats.md` §28.

- `src/live/mux.rs` — `MuxSource`: оба источника (`BotSource` на двух сокетах) работают всё время; показывается живой, если его соединение пригодно (`SourceEvent::Link`, после
  правильного `HELLO`), иначе демо, иначе ничего. События неактивного источника не идут в хаб, состояние (карта, состав, слой мухи, описание демо) запоминается и отдаётся
  при переключении; `STATUS` демо никогда не становится статусом бота (из него собирается описание демо: арена и имя весов). Запрос зрителей демо получает, только пока бот не пригоден. Возврат к демо после обрыва — через 2,5 с, переход на бота мгновенный.
- `src/live/hub.rs` — кадры несут поколение источника (`TaggedFrame`), `src/ws.rs` пересылает только кадры поколения последнего `source`; `Active` сбрасывает всё, что хаб помнил о прежнем источнике; `viewer()` считает открытые WS-соединения (бит подписки «сайт открыт», по которому демо ставит игру на паузу).
- `src/ws.rs` — сообщение `{"type":"source","kind":"live"|"demo"|"none","info":…}` первым после `hello` и при каждой смене.
- `src/http/bot.rs` — `GET /api/bot/status` с полями `source` и `demo_configured` (статус всегда только живого бота); `POST /api/bot/command` при показанном демо и отсутствующем `control.sock` — `503 demo_only`
  (после Origin, сессии и CSRF, ничего не уходит; бот без моста остаётся управляемым); правка списков работает, «перечитать» боту не шлётся.
- Страница: плашка на трёх вкладках, сброс нарисованного при смене источника, камера на мухе у демо, кнопки команд выключены у демо (`assets/app.js`, `SourceBadge`).

Тесты: `live::mux::tests` (приоритет и переключение на поддельных источниках, статус демо не статус бота, ошибки, запрос зрителей), `live::bot_source::tests` (`Link`, биты подписки), `live::hub::tests`,
`tests/demo_fallback.rs` (два поддельных моста на настоящих сокетах, настоящий сервер: переключение туда и обратно, команды отказываются и ничего не доходит до `control.sock`, подписка демо,
проверка кадров демо), Playwright `tools/e2e/demo-fallback.spec.ts` (настоящие `fly watch` и `web`, поддельный живой бот; скриншоты `~/aiddnet/data/screenshots/5.7-*.png`, в git их нет).
