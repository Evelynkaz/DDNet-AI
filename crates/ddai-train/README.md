# ddai-train — имитационное обучение мухи (задача 8.2)

Обучение мухи (`ddai-fly`, подграф S) и её контролей MLP/GRU (`ddai-controls`) «блокировать»: **BC + DAgger от
планировщика-учителя** (D-014, D-017) плюс **имитация людей** (D-040). Один и тот же цикл обучения, лосс, оптимизатор,
расписание и метрики для всех трёх моделей — контроли «обучены одинаково».

## Конвейер

```
арена (ddai-env) ──LabellingBrain──► teacher-датасет (postcard+zstd, manifest)  ─┐
                    планировщик размечает посещённые состояния                    ├─► Corpus ─► окна TBPTT ─► Trainer
демки людей (ddai-dataset, D-040) ──human.rs──► последовательности с весами ──────┘             (Adam, clip, cosine)
                                                                                                        │
                            DAgger: модель играет в арене → учитель размечает → данные копятся ◄────────┘
```

| Модуль | Что внутри |
|---|---|
| `types`, `store` | записи датасета учителя (`Episode`/`TeacherStep`), чанки postcard + zstd, манифест с sha256, дозапись по раундам; **ключ задания и маркер завершённого раунда** (сбор, прерванный между заданиями, при возобновлении добирает только недостающие задания) |
| `collect` | **`collect_scenario`** — разметка проб сценариев техник (T1…): субъект играет сценарий, остальные тики — скрипты сценария, в датасет идут эпизоды `scn:T*` (`only_success` оставляет только решённые учителем пробы). `LabellingBrain`: учитель (`ddai_planner::teacher::TeacherPlanner`, фиксированные итерации) размечает каждое решение; играет учитель, актёр или их смесь (`beta`); всплески случайных действий (`noise_prob`, DART). Метка — всегда чистое действие учителя |
| `human` | демки людей → непрерывные ряды решений одного игрока; веса: уверенность реплея, не заморожен, навык, активный/простой, вес техники (WH, T1–T15), **вес датасета и вес карты** (семейство Copy Love Box ×3, D-057). Карты ChillBlock5 (holdout арены) в обучение не идут; `exclude_map_substrings` выключает целые семейства карт. **Память (8.2b):** потолок `max_samples_per_demo` — демка вносит не больше стольких решений (куски по `segment_len` шагов отбираются детерминированным хэшем, куски с техникой — в `tagged_keep_boost` раз охотнее), `max_others` — не больше стольких соседей на шаг; одна демка в 3,3 ч иначе даёт 19 млн решений |
| `teacher_data` | эпизоды учителя → последовательности; замороженные шаги — только контекст; вал-разбиение по сиду игры |
| `seq` | окна TBPTT (32–64 решения, «прогрев» без лосса), выборка якорей пропорционально весу, зеркальная аугментация (у **всех трёх** моделей: муха на реальном S лишь приблизительно зеркально-симметрична, поэтому зеркальное окно для неё — новые данные) |
| `learner` | `Learner` для мухи (`FlyLearner`), MLP и GRU (`ControlLearner`): один плоский вектор параметров |
| `trainer` | в конце каждой фазы — калибровка порогов решений jump/hook/fire на **чётных** окнах `teacher-val` и `dagger-val` (пишутся в чекпоинт; отчёт по этим наборам — по нечётным, ревью F9); **собственный хук** (`[train.own_hook]`): `mode = "dropout"` (скрыть состояние хука у решения с вероятностью p, только при обучении), `"mask_hook_head"` (голова хука видит наблюдение без собственного состояния хука, остальные головы — полное: два прохода, чекпоинт хранит `HookView::MaskedForHookHead`), `switch_weight` (множитель лосса хука на решениях старта и отпускания); Adam с lr на параметр, clip нормы, warm-up + cosine, детерминизм по `(seed, шаг, окно)` при любом числе потоков, возобновление (`state.bin`), каталог запуска (`config.toml`, `metrics.jsonl`, `status.json`, `checkpoints/`) |
| `metrics` | по каждой голове: точность против мажоритарного базиса, сбалансированная точность, AUROC, ошибка прицела, частота нажатий против учителя; **хук отдельно по собственному состоянию** (начать / отпустить); пороги решений подбираются по частоте нажатий учителя (`rate_matched_threshold`) |
| `play_stats` | хук в игре по собранным эпизодам DAgger: частота старта (`P(hook ∣ свой хук не выпущен)`) и отпускания (`P(не хук ∣ выпущен)`) у ученика против учителя на тех же состояниях |
| `runner` | эксперимент целиком: BC → раунды DAgger → оценка в арене после каждой фазы (с долей **засчитанных побед**); корпус учителя растёт по раундам (не перечитывается); **выбор чекпоинта** по засчитанным победам на обучающих аренах → `checkpoints/selected.bundle` (holdout в выборе запрещён); `config.toml` пишется при каждом (пере)старте, прежние версии — `config-before-N.toml`, возобновление при изменённой конфигурации отказывает без `--allow-config-change` (F8); предупреждение, если в раунде уже лежат задания другой длины шума/сида (NIT 4) |
| `bank` (8.5a) | **банк стартов «соперника только что заморозили»**: запись — не снимок мира, а рецепт игры (арена, сид, раскладка + журнал решений блокирующего до момента фриза); скриптовый соперник детерминирован, поэтому повтор журнала воспроизводит игру тик в тик (тест: хэши решений обоих игроков равны исходным). В момент фриза место отдаётся мухе (`ReplayThenBrain`); последние 50 тиков до передачи муха уже «смотрит» (решает, но играет журнал) — прогрев рекуррентного состояния. Каждая запись помечена по игре с момента фриза: `idle_held` (блок держится при блокирующем, который ничего не делает), `scripted_held`, **`victim_escapes_under_idle`** (жертва выбирается при `idle`, отслеживается и после падения блокирующего) и `idle_blocker_out`; классы **V** (жертва уходит) / **B** (падает только `idle`) / **H** (`idle` держит блок; метка пилота «убегаемый» = V + B, на 38–70% B — поправка ревью, E-022); делится по сиду на обучающую и проверочную части (1 : 3). Файл — postcard + zstd + sha256, **версия 2** (правило игры — JSON-текстом, версия 1 читается; тест с фиксированными байтами) |
| `heldblock` (8.5a) | исход игры, доигранной после фриза (`Rules::after_ticks` = 250 тиков, наблюдатель арены пишет, кто «вне», каждый тик): **удержанный блок** = жертва ни разу не освободилась за окно, а муха не была вне; награда (`RewardConfig`): удержан +1, свой фриз −1, иначе 0; полные игры: засчитанный первый фриз +0,3, лежит ещё и держится +1, проигрыш −1, ничья/таймаут −0,5; **шейпинг потенциальный** (`Phi` = запас удержания жертвы; `shaped_return(γ, Cutoff::{Pay, NoPayout, Bootstrap})`: сумма телескопируется в `Φ(конец) − Φ(начало)`, а обрыв окна не терминал — инвариантны только `NoPayout` и бутстреп; пилот платил `Φ` на обрыве); жертва отслеживается и после падения мухи. Заглушка до задачи 3.10: когда в `GameReport` появятся `held_block`/`escape_tick`/`victim_out_ticks`, подменяется `EpisodeOutcome::from_records` |
| `es` (8.5a) | **OpenAI-ES**: антитетические пары, общие эпизоды у всех членов поколения (common random numbers), ранговое преобразование, Adam с шагом, пропорциональным σ группы, L2-якорь к стартовому чекпоинту; шум — функция `(сид, поколение, пара)`, поэтому прогон детерминирован при любом числе потоков и возобновляется (`state.bin`); метрики для вкладки «Обучение» без правок сайта; `eval` (доля удержаний по классам, первый фриз с ДИ Уилсона, пофайлово для парного McNemar; `spec` — на каких эпизодах считано: `compare` отказывает при несовпадении), `space` (группы параметров), `noise`, `stats` |

| `hook_study` | разбор «почему хук был около случайности»: один фактор на ветку |

## Команды

```bash
ddnet-ai train collect --config configs/train/round0-v1.toml      # разметка игр планировщиком
ddnet-ai train run     --config configs/train/e005-fly.toml       # BC + DAgger (возобновляется)
ddnet-ai train eval    --config <cfg> --bundle <run>/checkpoints/final.bundle [--calibrate]  # --calibrate: отчёт при подобранных порогах
ddnet-ai train inspect --bundle <bundle>                          # калибровка, веса декодера, усиления энкодера
ddnet-ai train info    <teacher-dataset> --verify
ddnet-ai train stats   <dagger-dataset>                           # по раундам: частоты ученика/учителя, старт и отпускание хука
ddnet-ai train hook-play --actor fly:<bundle> --arenas clb-left,pit --games 100   # хук в замкнутом цикле: старт/отпускание против учителя
ddnet-ai train set-thresholds --kind fly --bundle <b> --out <b2> --hook 0.4   # те же веса с другими порогами (A/B в арене)
ddnet-ai train hook-study --flyg <S.flyg> --train-map <map> --other-map <map> --factorial --seed 1   # 2×2×2 разбор причин (F6)
ddnet-ai arena run --config configs/arena/e008-eval.toml --brain fly:<bundle> --out <dir>
ddnet-ai arena run --config configs/arena/e008-proposer.toml --out <dir>    # гибрид с разными предлагателями (hybrid:fly:/hybrid:mlp:)
```

Длинные прогоны — в `screen`, логи в `~/aiddnet/data/logs/8.2/` (E-005) и `~/aiddnet/data/logs/8.2b/` (E-008), запуски — в `~/aiddnet/data/runs/E-005/` и `~/aiddnet/data/runs/E-008/`. Очередь запусков E-008 — `tools/e008/run_queue.sh` (файл очереди, 2 потока, возобновляемо, оценка после каждого запуска `tools/e008/eval_run.sh`).

## Детерминизм и тесты

Метки детерминированы по сиду (тест `tests/collect.rs`: игра, которую играет учитель, — та же игра, что у
`PlannerBrain`, решение в решение; 1 и 3 потока дают одинаковые эпизоды). Шаг обучения не зависит от числа потоков,
возобновлённый прогон заканчивается ровно там же, где непрерывный (`tests/trainer.rs`). Полный мини-эксперимент
(данные → BC → раунд DAgger → каталог запуска → возобновление) — `tests/runner.rs`; там же запуск, «убитый» между заданиями сбора
раунда, на возобновлении добирает только недостающее задание. `tests/fly_mirror.rs` — зеркальные окна у мухи на реальном S. Тяжёлые
прогоны в `cargo test` не входят.

## Задача 8.5a: дообучение мухи на результат (ES), банк «после фриза»

Мотив и конвейер — `docs/research/fly-training-methods.md`, постановка — `docs/research/fly-es.md`, итоги — E-021/E-022 в `docs/EXPERIMENTS.md`
и D-098. Имитация упёрлась: арена кончала игру на первом фризе, поэтому после фриза у мухи не было ни данных, ни награды, ни замера, а в
энкодере не было состояния цели (`ddai-fly`, «Задача 8.5a»).

```bash
ddnet-ai train upgrade-bundle --bundle <b> --opponent-state configs/fly/S-opponent-state.toml --out <b2>   # те же решения, новые входы с нулями
ddnet-ai train es bank --out <bank> --arenas clb-left,pit,platform --blocker scripted=200 --blocker fly:<b>=200 --blocker planner=100 [--extend]
ddnet-ai train es eval --config configs/train/e022-es-s2.toml --brain idle|scripted|planner|fly:<b> --out <json>   # доля удержаний, первый фриз, ДИ
ddnet-ai train es compare <a.json> <b.json>                      # парно по партиям, точный McNemar (главная — на V)
ddnet-ai train es retag --bank <v1> --out <v2>                   # метки V/B/H (игра idle и scripted с момента фриза), формат версии 2
ddnet-ai train es breakdown --config <cfg> --bank <v2> --starts 700 <eval.json…>   # удержание и свои фризы по классам V/B/H, парно к первому файлу
ddnet-ai train es scan --config <cfg>                            # как σ каждой группы двигает отдачу (замер для выбора σ)
ddnet-ai train es run --config configs/train/e022-es-s2.toml     # сам ES (возобновляется; --allow-config-change)
```

Каталог запуска тот же, что у BC: `config.toml` (при каждом старте; прежний — `config-before-N.toml`, возобновление при изменённом конфиге отказывает,
как `record_config`; удлинить `generations` можно), `metrics.jsonl` (`train` с `loss.total` = минус средняя отдача и `grad_norm`, `arena` с долей засчитанного
первого фриза и ДИ — их рисует вкладка «Обучение»; свои: `es` на поколение, `es_eval` с долей удержаний и первым фризом на обучающих залах и holdout),
`status.json`, `state.bin` (пишется сразу после оценки: лучший счёт не теряется при убийстве), `init.sha256` (стартовый чекпоинт закреплён: подмена при возобновлении отказана), `checkpoints/{last,selected,final,step-N}.bundle`. `selected` — по обучающим залам (удержание на V проверочной части банка + первый фриз − свой фриз), holdout в выборе не участвует; пустые усиления дальностных корзин (не-пространственные каналы) из поиска исключены. Вкладка не рисует долю удержаний (нужна небольшая добавка в `ddai-web`, вне этой задачи).

Тесты: `tests/es_tiny.rs` (крошечная муха, синтетический `pit`; банк воспроизводит исходные игры тик в тик, метка `idle_held` совпадает с игрой idle, шейпинг
телескопируется на настоящих эпизодах, два поколения побитно равны на 1 и 3 потоках, остановка и продолжение = непрерывный прогон, смена конфига
отказана), `tests/opp_identity.rs` (`#[ignore]`: хэши 24 игр лучшей мухи E-008 побитно равны записанным до изменения — со старым и с обновлённым чекпоинтом),
юнит-тесты рангов, антитетического шума, оценки градиента на линейной цели, Adam, McNemar, награды.

## Задача 8.5b: рекуррентный PPO на удержанном блоке (`ppo`), curriculum от демонстраций планировщика

Постановка и замеры — `docs/research/fly-ppo.md`, итоги — E-027 в `docs/EXPERIMENTS.md`, решение — D-106, форматы — `docs/formats.md` §40. Продолжает 8.5a (банк «после фриза», награда, оценка): ES дал no-go, а PPO
даёт пошаговое распределение заслуг на готовом батчевом BPTT.

```bash
ddnet-ai train ppo run --config configs/train/e023-ppo-s2.toml       # PPO от чекпоинта E-008 (возобновляется; --allow-config-change)
ddnet-ai train ppo demos --config configs/train/e023-ppo-cur4-s2.toml # демонстрации планировщика для curriculum (run делает это сам, если файла нет)
ddnet-ai train ppo probe --config <cfg> --brain idle|fly:<b> --offsets 0,8,20,44   # что держит бандл после передачи от демонстрации на каждом смещении
ddnet-ai train es eval --config configs/train/e023-eval.toml --brain fly:<bundle> …   # итоговая оценка и парное сравнение — те же, что у ES (8.5a)
```

| Модуль (`ppo/`) | Что внутри |
|---|---|
| `actor` | `PpoActor` — муха как `Brain` для арены: выбирает действие из политики (`Sample`, логиты ÷ температура, пороги бандла — часть политики) или детерминированно (`Argmax`, побитно как `ActionSelection::Argmax`); пишет решения и **состояние мембран** на начале окон прогрева (R2D2) |
| `rollout` | один эпизод: старт банка (воспроизведение исходной игры, передача мухе на тике фриза), старт curriculum (воспроизведение демонстрации до тика передачи) или полная игра; жертва после передачи — scripted, планировщик, `fly:<бандл>` или прошлое «я» |
| `reward` | потенциальный шейпинг `γΦ(s′) − Φ(s)` с `Φ(терминал) = 0` (телескопируется: тесты), терминал — удержанный блок / свой фриз / исход игры, штраф за «выдернул жертву хуком», GAE |
| `critic` | привилегированный MLP на точном состоянии (+ BFS-поля карты); в бандл и в бой не попадает |
| `learner` | PPO на батчевом BPTT: окна с сохранённым состоянием, клип, энтропия, KL-якорь к стартовой политике (`KL(ref ‖ cur)` точно, коэффициент подстраивается к цели), BC-добавка на окнах учителя, разогрев критика; Adam с увеличенным шагом для весов новых каналов; суммы в фиксированном порядке — результат не зависит от числа потоков |
| `curriculum` | обратный curriculum: демонстрация = решения планировщика с тика фриза (только удержавшие блок); муха берёт управление на тике `фриз + смещение`, смещение уменьшается, когда она держит блок достаточно часто |
| `config`, `mod` | конфиг прогона, отказ возобновлять с изменённым конфигом, цикл (rollout → update → DAgger-раунд → оценка), метрики, `state.bin` |

Усиление открытия: `bc.teacher_data.opening_boost` (×) для шагов первых `opening_ticks` тиков после фриза в раундах `opening_rounds` — хват жертвы хуком в первых решениях (80% у планировщика) иначе 3% меток. Метрики `open_hook_v`/`open_fire_v` — доля хука/огня в первых 4 решениях мухи на V-стартах.

Планировщик размечает посещённые мухой состояния (DAgger: `bank_collect::collect_starts` в цикле, раунд 100) — метки идут в то же BC-слагаемое. Поведение «мягких голов» (энтропия ≈ 2,9 нат на решение у BC-мухи) вынудило ввести **температуру** политики
(логиты ÷ T, по умолчанию 0,3): при T = 1 выборка играет заметно хуже детерминированной игры, при T ≤ 0,3 — близко к ней.

Тесты: юнит — политика (градиенты log-prob/энтропии/KL по логитам и сэмплер), критик (градиент, обучение простой функции, BFS), награда (телескопирование, GAE), решение PPO (градиент потери конечными разностями, клип), конфиг (отказ
возобновлять), curriculum (уровень, журнал воспроизведения); интеграционные на крошечной мухе и `pit` (`ppo::tests`): актёр в `Argmax` играет побитно как бандл (оба вида), сохранённые состояния воспроизводят логиты актёра в батчевых
окнах, градиент батчевого BPTT (оба вида) равен конечным разностям по параметрам всех групп, в том числе по новым каналам, возврат эпизода равен возврату 8.5a, прогон детерминирован на 1 и 3 потоках, возобновляется и отказывает при смене
конфига (с BC-слагаемым, curriculum и DAgger); `tests/ppo_identity.rs` (`#[ignore]`): 24 игры лучшей мухи E-008 через `PpoActor` в `Argmax` — хэши решений равны золотым 8.5a.

## Задача 8.6: хук мухи — измерения и BC с контролем (`hook_eval`, `critical`, `probe`, `metrics`, `trainer`)

Записка — `docs/research/fly-hook-intent.md`, итоги — E-029 и D-109, форматы — `docs/formats.md` §43.

```bash
ddnet-ai train upgrade-hook --bundle <b> --out <b2>                       # голова намерения, играет побитно как b
ddnet-ai train set-thresholds --kind fly --bundle <b> --out <b2> --hook-hi 0.62 --hook-lo 0.633   # декодирование с гистерезисом
ddnet-ai train es hook-eval --config configs/train/e029-eval.toml --brain fly:<b>|planner --starts 700 --out <json>   # хук после фриза по состоянию, первое нажатие, прицел на броске
ddnet-ai train es critical --config <cfg> --fly fly:<b> --direction forward|reverse --class V --set train-all|train-val|holdout --out <json>   # критические решения
ddnet-ai train probe-hook --config configs/train/e029-bc-legacy.toml --fly s2=<b> [--state-fly s2=<b>]   # информационные зонды
ddnet-ai train run --config configs/train/e029-bc-{legacy,intent}.toml    # BC с контрольной рукой
```

`hook_eval` — запись решений после фриза вокруг любого мозга (`RecordingBrain`); `critical` — `SwapBrain`: повтор игры, в решениях плана (целое решение, окно, одна компонента) играет действие альтернативы (сохранённое — метка планировщика на состоянии мухи, или «живое»); `probe` — малый MLP на признаках (вход энкодера, привилегированное состояние, производные, состояние сети) против настоящих мух по защёлке. В `metrics`: `hook_by_latch`, `aim_throw`, `rate_matched_hook_decode`; в `trainer`: `hook_calibration`, проверка весов опасностей; в `teacher_data`/`seq`: защёлка шага (`SeqStep::latch`, сыгранная кнопка прошлого шага) и `aim_mask`.
