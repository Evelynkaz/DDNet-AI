# ddai-train — имитационное обучение мухи (задача 8.2)

Обучение мухи (`ddai-fly`, подграф S) и её контролей MLP/GRU (`ddai-controls`) «блокировать»: **BC + DAgger от
планировщика-учителя** (D-014, D-017) плюс **имитация людей** (D-040). Один и тот же цикл обучения, лосс, оптимизатор,
расписание и метрики для всех трёх моделей — контроли «обучены одинаково».

## Конвейер

```
арена (ddai-env) ──LabellingBrain──► teacher-датасет (postcard+zstd, manifest)  ─┐
                    планировщик размечает посещённые состояния                    ├─► Corpus ─► окна TBPTT ─► Trainer
демки людей (ddai-dataset, D-040) ──human.rs──► последовательности с весами ──────┘             (Adam, clip, cosine)
                                                                                                        │
                            DAgger: модель играет в арене → учитель размечает → данные копятся ◄────────┘
```

| Модуль | Что внутри |
|---|---|
| `types`, `store` | записи датасета учителя (`Episode`/`TeacherStep`), чанки postcard + zstd, манифест с sha256, дозапись по раундам; **ключ задания и маркер завершённого раунда** (сбор, прерванный между заданиями, при возобновлении добирает только недостающие задания) |
| `collect` | **`collect_scenario`** — разметка проб сценариев техник (T1…): субъект играет сценарий, остальные тики — скрипты сценария, в датасет идут эпизоды `scn:T*` (`only_success` оставляет только решённые учителем пробы). `LabellingBrain`: учитель (`ddai_planner::teacher::TeacherPlanner`, фиксированные итерации) размечает каждое решение; играет учитель, актёр или их смесь (`beta`); всплески случайных действий (`noise_prob`, DART). Метка — всегда чистое действие учителя |
| `human` | демки людей → непрерывные ряды решений одного игрока; веса: уверенность реплея, не заморожен, навык, активный/простой, вес техники (WH, T1–T15), **вес датасета и вес карты** (семейство Copy Love Box ×3, D-057). Карты ChillBlock5 (holdout арены) в обучение не идут; `exclude_map_substrings` выключает целые семейства карт. **Память (8.2b):** потолок `max_samples_per_demo` — демка вносит не больше стольких решений (куски по `segment_len` шагов отбираются детерминированным хэшем, куски с техникой — в `tagged_keep_boost` раз охотнее), `max_others` — не больше стольких соседей на шаг; одна демка в 3,3 ч иначе даёт 19 млн решений |
| `teacher_data` | эпизоды учителя → последовательности; замороженные шаги — только контекст; вал-разбиение по сиду игры |
| `seq` | окна TBPTT (32–64 решения, «прогрев» без лосса), выборка якорей пропорционально весу, зеркальная аугментация (у **всех трёх** моделей: муха на реальном S лишь приблизительно зеркально-симметрична, поэтому зеркальное окно для неё — новые данные) |
| `learner` | `Learner` для мухи (`FlyLearner`), MLP и GRU (`ControlLearner`): один плоский вектор параметров |
| `trainer` | в конце каждой фазы — калибровка порогов решений jump/hook/fire на **чётных** окнах `teacher-val` и `dagger-val` (пишутся в чекпоинт; отчёт по этим наборам — по нечётным, ревью F9); **собственный хук** (`[train.own_hook]`): `mode = "dropout"` (скрыть состояние хука у решения с вероятностью p, только при обучении), `"mask_hook_head"` (голова хука видит наблюдение без собственного состояния хука, остальные головы — полное: два прохода, чекпоинт хранит `HookView::MaskedForHookHead`), `switch_weight` (множитель лосса хука на решениях старта и отпускания); Adam с lr на параметр, clip нормы, warm-up + cosine, детерминизм по `(seed, шаг, окно)` при любом числе потоков, возобновление (`state.bin`), каталог запуска (`config.toml`, `metrics.jsonl`, `status.json`, `checkpoints/`) |
| `metrics` | по каждой голове: точность против мажоритарного базиса, сбалансированная точность, AUROC, ошибка прицела, частота нажатий против учителя; **хук отдельно по собственному состоянию** (начать / отпустить); пороги решений подбираются по частоте нажатий учителя (`rate_matched_threshold`) |
| `play_stats` | хук в игре по собранным эпизодам DAgger: частота старта (`P(hook ∣ свой хук не выпущен)`) и отпускания (`P(не хук ∣ выпущен)`) у ученика против учителя на тех же состояниях |
| `runner` | эксперимент целиком: BC → раунды DAgger → оценка в арене после каждой фазы (с долей **засчитанных побед**); корпус учителя растёт по раундам (не перечитывается); **выбор чекпоинта** по засчитанным победам на обучающих аренах → `checkpoints/selected.bundle` (holdout в выборе запрещён); `config.toml` пишется при каждом (пере)старте, прежние версии — `config-before-N.toml`, возобновление при изменённой конфигурации отказывает без `--allow-config-change` (F8); предупреждение, если в раунде уже лежат задания другой длины шума/сида (NIT 4) |
| `hook_study` | разбор «почему хук был около случайности»: один фактор на ветку |

## Команды

```bash
ddnet-ai train collect --config configs/train/round0-v1.toml      # разметка игр планировщиком
ddnet-ai train run     --config configs/train/e005-fly.toml       # BC + DAgger (возобновляется)
ddnet-ai train eval    --config <cfg> --bundle <run>/checkpoints/final.bundle [--calibrate]  # --calibrate: отчёт при подобранных порогах
ddnet-ai train inspect --bundle <bundle>                          # калибровка, веса декодера, усиления энкодера
ddnet-ai train info    <teacher-dataset> --verify
ddnet-ai train stats   <dagger-dataset>                           # по раундам: частоты ученика/учителя, старт и отпускание хука
ddnet-ai train hook-play --actor fly:<bundle> --arenas clb-left,pit --games 100   # хук в замкнутом цикле: старт/отпускание против учителя
ddnet-ai train set-thresholds --kind fly --bundle <b> --out <b2> --hook 0.4   # те же веса с другими порогами (A/B в арене)
ddnet-ai train hook-study --flyg <S.flyg> --train-map <map> --other-map <map> --factorial --seed 1   # 2×2×2 разбор причин (F6)
ddnet-ai arena run --config configs/arena/e008-eval.toml --brain fly:<bundle> --out <dir>
ddnet-ai arena run --config configs/arena/e008-proposer.toml --out <dir>    # гибрид с разными предлагателями (hybrid:fly:/hybrid:mlp:)
```

Длинные прогоны — в `screen`, логи в `~/aiddnet/data/logs/8.2/` (E-005) и `~/aiddnet/data/logs/8.2b/` (E-008), запуски — в `~/aiddnet/data/runs/E-005/` и `~/aiddnet/data/runs/E-008/`. Очередь запусков E-008 — `tools/e008/run_queue.sh` (файл очереди, 2 потока, возобновляемо, оценка после каждого запуска `tools/e008/eval_run.sh`).

## Детерминизм и тесты

Метки детерминированы по сиду (тест `tests/collect.rs`: игра, которую играет учитель, — та же игра, что у
`PlannerBrain`, решение в решение; 1 и 3 потока дают одинаковые эпизоды). Шаг обучения не зависит от числа потоков,
возобновлённый прогон заканчивается ровно там же, где непрерывный (`tests/trainer.rs`). Полный мини-эксперимент
(данные → BC → раунд DAgger → каталог запуска → возобновление) — `tests/runner.rs`; там же запуск, «убитый» между заданиями сбора
раунда, на возобновлении добирает только недостающее задание. `tests/fly_mirror.rs` — зеркальные окна у мухи на реальном S. Тяжёлые
прогоны в `cargo test` не входят.

## Конфиги E-005 (`configs/train/`)

- `round0-v1.toml` — базовый датасет учителя (1,92 млн решений); `round0-dev.toml`, `smoke-collect.toml` — малые наборы для отладки.
- `e005-{fly,mlp-s,gru-s,mlp-w,gru-w}.toml` — BC + 5 раундов DAgger; `e005-fly-noclb.toml`, `e005-mlp-w-noclb.toml` — без демок семейства `Copy*`
  (D-061); `*-s2`, `*-s3` — другой сид обучения.
- `abl-*.toml` — абляции мухи (600 шагов BC): `base` (7.3 как есть), `dg` (+ веса дальностных корзин), `restcal` (калибровка по покою), `hilr` (lr коннектома ×6),
  `dg-hilr`, `alpha4`/`alpha6` (`α_init`), `dg8-alpha4` (8 корзин), `mlps`/`mlpw` (контроли); результаты — E-005.
- Оценка: `configs/arena/e005-eval.toml` + `tools/e005/{eval_all.sh,run_all.sh,make_tables.py,offline_eval.sh}`.

Метрики по голове (`metrics.rs`) включают top-2 по направлению и совместную точность (направление + jump + hook): для мухи как генератора кандидатов гибрида
(D-041) важнее, лежит ли метка среди кандидатов, чем точное совпадение argmax.

## Конфиги E-008 (`configs/train/e008-*.toml`, генератор `tools/e008/gen_configs.py`)

- Фаза 1 — **арены собственного хука** на данных E-005: `e008-p1-{mlpw,fly}-{base,drop,maskhook,switch}-s{1,2,…}` (β > 0 во всех раундах: 0,5 / 0,4 / 0,3 / 0,2 / 0,15;
  3 арены для выбора чекпоинта: `clb-left`, `pit`, `platform`).
- Фаза 2 — **данные** (поверх лучшей арены): `d1` — владелец v2 + ChillerDragon block-06 и «extra» (Copy ×3, ChillBlock5 исключён, потолки на демку), `d2` — `d1` + учитель на 1vN и
  сценариях техник (`round1-v2.toml`; задания-сценарии в каждом раунде DAgger), `cb5` — `d2` + демки людей на ChillBlock5 (с потолком и пониженным весом; оценка только на CLB-залах).
- Данные учителя: `round1-v2.toml` (`ddnet-ai train collect`): 1v2/1v3 на обучающих аренах и решённые планировщиком сценарии (T1, T3, T4, T6, T7, T9, T10, T11, T12, T13, T17, T14).
- Оценка: `configs/arena/e008-eval.toml` (те же условия и сид, что строки E-005), `configs/arena/e008-proposer.toml` (гибрид 4 мс, часы работы со старым курсом `step_ms = 0.0022`; `tools/e008/gen_proposer_config.py --step-ms 0.0022`), `e008-proposer-confirm.toml` (тот же состав, курс по умолчанию) и `e008-why.toml` (зонды: бюджет и число предложений K; `gen_why_config.py`).
- Инструменты E-008 (`tools/e008/`): `gen_configs.py` (конфиги обучения), `run_queue.sh` + `eval_run.sh` (очередь обучения и оценка), `run_proposer.sh` (ячейки сравнения предлагателей), `play_threshold.{py,sh}` (подбор порога хука по частоте старта в игре; тест `test_play_threshold.py`), `eval_vs_planner.sh` (F2), `tables.py`, `proposer_tables.py` (McNemar по парам игр), `source_shares.py`, `rank_runs.py` (выбор «лучшего» по обучающим условиям). Результаты — `docs/EXPERIMENTS.md` E-008.
