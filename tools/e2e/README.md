# E2E: реальный браузер для `ddai-web` (задачи 5.1, 5.3)

`web-login.spec.ts` (задача 5.1) — проверка в headless Chromium (Playwright) против локального,
только что запущенного процесса: вход по паролю → статус показывает «подключено» (WebSocket) →
выход → снова форма входа. Один прогон на десктопном viewport, один на телефонном (360×740).
Скриншоты сохраняются в `~/aiddnet/data/screenshots/5.1-*.png`.

`web-login-https.spec.ts` (задача 5.3) — тот же сценарий, но по-настоящему: через реальный
Caddy/HTTPS (`https://89-58-7-133.sslip.io`, настоящий сертификат Let's Encrypt), паролем из
`~/aiddnet/data/secrets/web-password.txt` (читается в момент прогона, никогда не печатается).
Скриншоты — `~/aiddnet/data/screenshots/5.3-*.png`. Без переменной `DDAI_E2E_BASE_URL` тест
пропускается (`test.skip`), так что обычный `npx playwright test` без окружения не пытается
стучаться в интернет и остаётся зелёным (см. "Как запустить" ниже).

`live-map.spec.ts` (задача 5.2a) — живая карта: вход → вкладка «Игра» → карта нарисована и игроки
двигаются (пиксельный дифф двух скриншотов канваса через 1 с) → следование за игроком держит
камеру 3 с → пауза/возобновление воспроизведения → десктоп/телефон скриншоты. Плюс два отдельных
теста-замера: p50/p95 времени кадра рендер-цикла при CPU×4 на телефонном вьюпорте (карта
`BlmapChill` — самая большая локальная, 8 синтетических персонажей поверх её настоящей геометрии,
т.к. в реальном корпусе Oracle B ни на одной настоящей карте не бывает больше 4 персонажей в одном
сценарии) и трафик WS на 25 Гц/10 Гц («эконом»). Нужен `~/aiddnet/data/ddnet-server/maps/
BlmapChill.map` на диске (задача 2.1) — без него тест пропускается (`test.skip`), не падает.
Скриншоты — `~/aiddnet/data/screenshots/5.2a-*.png`.

`bot-control.spec.ts` (задача 5.6) — вкладка «Бот»: панель состояния, команды и редактор списков, против настоящего `ddnet-ai web` на случайном порту в временном `--data-dir` и **поддельного бота на Node** (сокет управления `control.sock` и мост `live.sock`); настоящего бота и игрового сервера нет.
Проверяет: статус из моста, кулдаун kill, команду → запрос на сокете → ответ на экране, добавление / удаление имени (предпросмотр свёрнутой формы, файл `relations.json`), разметку в имени как текст, POST без CSRF из настоящего браузера → 403, телефонный вьюпорт. Скриншоты — `~/aiddnet/data/screenshots/5.6-*.png`.

`fly-panel.spec.ts` (задача 7.4) — вкладка «Муха»: настоящий `ddnet-ai fly watch` (обученная муха E-005 играет арену `clb-left`, без игрового сервера) и настоящий `ddnet-ai web --bot-socket` на случайном порту во временном `--data-dir`. Проверяет: «муха работает», имя и хэш весов, что все рисунки нарисованы (непрозрачные пиксели канвасов), 33 группы / 100 DN / 7 каналов в последнем кадре, что картинка движется, переключатель канала, таблицу, что при уходе с вкладки кадры перестают приходить (подписка снимается) и возвращаются при возврате, телефонный вьюпорт без горизонтальной прокрутки. Без bundle и графа на диске пропускается. Скриншоты — `~/aiddnet/data/screenshots/7.4-desktop.png`, `7.4-phone.png`. Запуск: `npx playwright test fly-panel.spec.ts` (переменные `DDAI_FLY_BUNDLE`, `DDAI_FLY_ARENA` меняют bundle и арену).

`demo-fallback.spec.ts` (задача 5.7) — демо за живым ботом: настоящие `ddnet-ai fly watch --pause-idle` (муха E-005 на арене `clb-left`, свой сокет) и `ddnet-ai web --bot-socket … --demo-socket …` на случайном порту во временном `--data-dir`, плюс **поддельный живой бот на Node** (мост и сокет управления, поднимается и гасится тестом). Проверяет: без бота «Игра» рисует арену с мухой под плашкой «Показ: муха на арене (не настоящая игра)» (карта, арена, веса), камера на мухе, игроки названы слотами; «Бот» говорит «бот не запущен», команды выключены, команда в обход страницы получает `503 demo_only` и ничего не доходит до бота; «Муха» работает на демо; бот поднимается — плашка «Живой бот», его карта и кадры, статус «В игре», команда доходит; бот уходит — снова демо; демо не играет, пока не открыт ни один браузер (CPU процесса по `/proc`); десктоп и телефон (360x740, без горизонтальной прокрутки). Без bundle, графа, карты Copy Love Box и `target/debug/ddnet-ai` пропускается. Скриншоты — `~/aiddnet/data/screenshots/5.7-*.png`. Запуск: `npx playwright test demo-fallback.spec.ts`.

Ни один из этих тестов не входит в CI (см. constraints задач 5.1/5.3/5.2a) — запускать руками после
изменений в `ddai-web` или в развёртывании (`deploy/`).

## Как запустить

```bash
# 1. Собрать бота (нужен target/debug/ddnet-ai) — только для web-login.spec.ts (локального)
cargo build -p ddnet-ai

# 2. Один раз поставить зависимости и headless-shell Chromium
cd tools/e2e
npm install
npx playwright install --only-shell chromium
# на новой машине могут не хватать системных библиотек (шрифты, mesa, libasound…),
# тогда один раз: sudo npx playwright install-deps chromium

# 3a. Локальный прогон (5.1) — сам поднимает `ddnet-ai web-passwd` и
#     `ddnet-ai web --listen 127.0.0.1:0` во временный каталог данных (не трогает
#     ~/aiddnet/data/secrets) и гасит процесс после прогона. Единственный, что запускает
#     обычный `npx playwright test` без переменных окружения:
npx playwright test web-login.spec.ts

# 3b. Против настоящего HTTPS-развёртывания (5.3) — нужен уже поднятый Caddy+ddnet-ai-web
#     (deploy/install.sh) и сгенерированный пароль (ddnet-ai web-passwd):
DDAI_E2E_BASE_URL=https://89-58-7-133.sslip.io npx playwright test web-login-https.spec.ts

# 3d. Управление ботом (5.6) — как 3a, плюс поддельный бот внутри теста:
npx playwright test bot-control.spec.ts

# 3c. Живая карта (5.2a) — сам собирает пример-генератор синтетической трассы
#     (cargo build -p ddai-web --features test-util --example make_test_trace) и поднимает
#     ddnet-ai web --replay/--maps-dir во временные каталоги:
npx playwright test live-map.spec.ts
```

## Soak: час игры живого бота на локальном сервере (задача 4.4)

Не браузерный и не Playwright: `soak.sh` (запуск), `soak.py` (стенд: бот, три скриптовых бота с приходами и уходами, отдельный веб-юнит на порту 7790 с
WebSocket-зрителем, консоль, перезапуск сервера, смена карты, журнал каждые 15 с) и `soak_analyze.py` (приёмка по журналу; `--selftest` проверяет на
синтетических прогонах, что каждый критерий **может** не пройти). Только `127.0.0.1`; боевой веб на 7788 и `~/aiddnet/bin` не трогаются. Журнал и итог —
`~/aiddnet/data/logs/4.4/<время>-<метка>/`. Критерии, цифры и вердикт — `docs/EXPERIMENTS.md`, E-009; юнит бота — `deploy/README.md`.

```bash
tools/e2e/soak.sh --selftest                                  # анализ умеет падать
tools/e2e/soak.sh --build --label A-wbauto                    # 60 мин, ВБ авто, бот дочерним процессом, консоль
tools/e2e/soak.sh --label B-wboff-unit --wb off --unit        # 60 мин, ВБ выкл., через deploy/systemd/ddnet-ai-bot.service (консоли нет)
tools/e2e/soak.sh --label rehearsal --duration 300            # репетиция: тот же сценарий, сжатый
tools/e2e/soak.sh --analyze ~/aiddnet/data/logs/4.4/<прогон>  # пересчитать приёмку по готовому журналу
```

Бот в обоих режимах работает в **частном каталоге данных** `<прогон>/botdata` (свои `live.sock`, `control.sock`, `relations.json`, память, клипы); боевой `~/aiddnet/data/bot`
не используется, не переносится и не удаляется, а в конце прогона стенд сверяет, что он не изменился (список, права, размеры, mtime). Перезапуск сервера на 20% прогона, смена карты на 63-70%;
память судится от базы на 25-й минуте (после заполнения колец задержек) и требует ≥ 35 минут прогона.

Сервер `ddnet-local.service` на время прогона занят целиком (стенд отказывается стартовать, если на нём уже кто-то есть); в конце карта возвращается на
`Copy Love Box` и читается обратно (`sv_map`).
