# E2E: реальный браузер для `ddai-web` (задачи 5.1, 5.3)

`web-login.spec.ts` (задача 5.1) — проверка в headless Chromium (Playwright) против локального,
только что запущенного процесса: вход по паролю → статус показывает «подключено» (WebSocket) и «Бот: не запущен» (бота нет; с 5.11 состояние берётся из моста) →
выход → снова форма входа. Один прогон на десктопном viewport, один на телефонном (360×740).
Скриншоты сохраняются в `~/aiddnet/data/screenshots/5.1-*.png`.

`web-login-https.spec.ts` (задача 5.3) — тот же сценарий, но по-настоящему: через реальный
Caddy/HTTPS (`https://89-58-7-133.sslip.io`, настоящий сертификат Let's Encrypt), паролем из
`~/aiddnet/data/secrets/web-password.txt` (читается в момент прогона, никогда не печатается).
Скриншоты — `~/aiddnet/data/screenshots/5.3-*.png`. Без переменной `DDAI_E2E_BASE_URL` тест
пропускается (`test.skip`), так что обычный `npx playwright test` без окружения не пытается
стучаться в интернет и остаётся зелёным (см. "Как запустить" ниже).

`live-map.spec.ts` (задача 5.2a) — живая карта: вход → вкладка «Игра» → карта нарисована и игроки
двигаются (пиксельный дифф двух скриншотов канваса через 1 с) → следование за игроком держит
камеру 3 с → пауза/возобновление воспроизведения → десктоп/телефон скриншоты. Плюс два отдельных
теста-замера: p50/p95 времени кадра рендер-цикла при CPU×4 на телефонном вьюпорте (карта
`BlmapChill` — самая большая локальная, 8 синтетических персонажей поверх её настоящей геометрии,
т.к. в реальном корпусе Oracle B ни на одной настоящей карте не бывает больше 4 персонажей в одном
сценарии) и трафик WS на 25 Гц/10 Гц («эконом»). Нужен `~/aiddnet/data/ddnet-server/maps/
BlmapChill.map` на диске (задача 2.1) — без него тест пропускается (`test.skip`), не падает.
Скриншоты — `~/aiddnet/data/screenshots/5.2a-*.png`.

`bot-control.spec.ts` (задача 5.6) — вкладка «Бот»: панель состояния, команды и редактор списков, против настоящего `ddnet-ai web` на случайном порту в временном `--data-dir` и **поддельного бота на Node** (сокет управления `control.sock` и мост `live.sock`); настоящего бота и игрового сервера нет.
Проверяет: статус из моста, кулдаун kill, команду → запрос на сокете → ответ на экране, добавление / удаление имени (предпросмотр свёрнутой формы, файл `relations.json`), разметку в имени как текст, POST без CSRF из настоящего браузера → 403, телефонный вьюпорт. Скриншоты — `~/aiddnet/data/screenshots/5.6-*.png`.

`fly-panel.spec.ts` (задача 7.4) — вкладка «Муха»: настоящий `ddnet-ai fly watch` (обученная муха E-005 играет арену `clb-left`, без игрового сервера) и настоящий `ddnet-ai web --bot-socket` на случайном порту во временном `--data-dir`. Запуск: `npx playwright test fly-panel.spec.ts` (переменные `DDAI_FLY_BUNDLE`, `DDAI_FLY_ARENA` меняют bundle и арену).

`demo-fallback.spec.ts` (задача 5.7) — демо за живым ботом: настоящие `ddnet-ai fly watch --pause-idle` (муха E-005 на арене `clb-left`, свой сокет) и `ddnet-ai web --bot-socket … --demo-socket …` на случайном порту во временном `--data-dir`, плюс **поддельный живой бот на Node** (мост и сокет управления, поднимается и гасится тестом). Задача 5.11 (последние четыре теста того же файла): поле ввода чата владельца под панелью чата «Игры» (D-094). `support/gamebot.mjs` теперь поднимает и сокет управления (`controlSock`, его даёт `stack.mjs`): поддельный бот принимает `say`, через 0,4 с «повторяет» строку в игровой чат от имени бота, а `bot.sayMode` (`ok` / `not_in_game` / `rate_limited` / `queue_full` / `chat_disabled`) выбирает отказ; `bot.connected` меняет `connected` в `STATUS`. Тесты: Enter и кнопка, строка и «Командный чат» доходят до сокета управления, строка возвращается в панели как текст, `/kill` отвергается страницей и не доходит до бота, каждый отказ виден под полем, `chat_disabled` блокирует поле до возврата на вкладку, телефон 390×844 (шрифт поля ≥ 16 px, всё в ширину экрана), «Статус» показывает «в игре» / «запущен, не в игре». Сайт сам ограничивает строки владельца (2 за 3 с, 10 в минуту), поэтому тесты шлют их с паузой 3,2 с и не больше восьми за прогон. Скриншоты — `~/aiddnet/data/screenshots/5.11-*.png`.

`ipfilter_probe.sh` (задача 2.6b, D-091) — не браузерный тест: проверяет на **самом systemd** этой машины, что делают `IPAddressAllow=`/`IPAddressDeny=` юнита бота (одноразовый юнит `ddai-ipprobe.service` в `/run/systemd/system`, три эхо-сервера на `127.0.0.2`/`127.0.0.3`/`::1`, настоящий нейтральный DNS-запрос на `1.1.1.1:53`; нужен `sudo`). Семь сценариев (юнит как есть, добавленный deny без сброса, сброс allow, сброс deny, **drop-in режима `relay = "public"`**, он же одной строкой, ошибочный `Allow=any`) с ожидаемыми `OPEN`/`BLOCKED`/`SENT`; при любом расхождении выходит с кодом 1, в конце удаляет юнит. Таблица результатов — `docs/formats.md` §33.9. Запуск: `tools/e2e/ipfilter_probe.sh`.

Ни один из этих тестов не входит в CI (см. constraints задач 5.1/5.3/5.2a) — запускать руками после
изменений в `ddai-web` или в развёртывании (`deploy/`).

## Как запустить

```bash
# 1. Собрать бота (нужен target/debug/ddnet-ai) — только для web-login.spec.ts (локального)
cargo build -p ddnet-ai

# 2. Один раз поставить зависимости и headless-shell Chromium
cd tools/e2e
npm install
npx playwright install --only-shell chromium
# на новой машине могут не хватать системных библиотек (шрифты, mesa, libasound…),
# тогда один раз: sudo npx playwright install-deps chromium

# 3a. Локальный прогон (5.1) — сам поднимает `ddnet-ai web-passwd` и
#     `ddnet-ai web --listen 127.0.0.1:0` во временный каталог данных (не трогает
#     ~/aiddnet/data/secrets) и гасит процесс после прогона. Единственный, что запускает
#     обычный `npx playwright test` без переменных окружения:
npx playwright test web-login.spec.ts

# 3b. Против настоящего HTTPS-развёртывания (5.3) — нужен уже поднятый Caddy+ddnet-ai-web
#     (deploy/install.sh) и сгенерированный пароль (ddnet-ai web-passwd):
DDAI_E2E_BASE_URL=https://89-58-7-133.sslip.io npx playwright test web-login-https.spec.ts

# 3d. Управление ботом (5.6) — как 3a, плюс поддельный бот внутри теста:
npx playwright test bot-control.spec.ts

# 3c. Живая карта (5.2a) — сам собирает пример-генератор синтетической трассы
#     (cargo build -p ddai-web --features test-util --example make_test_trace) и поднимает
#     ddnet-ai web --replay/--maps-dir во временные каталоги:
npx playwright test live-map.spec.ts
```

## Soak: час игры живого бота на локальном сервере (задача 4.4)

Не браузерный и не Playwright: `soak.sh` (запуск), `soak.py` (стенд: бот, три скриптовых бота с приходами и уходами, отдельный веб-юнит на порту 7790 с
WebSocket-зрителем, консоль, перезапуск сервера, смена карты, журнал каждые 15 с) и `soak_analyze.py` (приёмка по журналу; `--selftest` проверяет на
синтетических прогонах, что каждый критерий **может** не пройти). Только `127.0.0.1`; боевой веб на 7788 и `~/aiddnet/bin` не трогаются. Журнал и итог —
`~/aiddnet/data/logs/4.4/<время>-<метка>/`. Критерии, цифры и вердикт — `docs/EXPERIMENTS.md`, E-009; юнит бота — `deploy/README.md`.

```bash
tools/e2e/soak.sh --selftest                                  # анализ умеет падать
tools/e2e/soak.sh --build --label A-wbauto                    # 60 мин, ВБ авто, бот дочерним процессом, консоль
tools/e2e/soak.sh --label B-wboff-unit --wb off --unit        # 60 мин, ВБ выкл., через deploy/systemd/ddnet-ai-bot.service (консоли нет)
tools/e2e/soak.sh --label rehearsal --duration 300            # репетиция: тот же сценарий, сжатый
tools/e2e/soak.sh --analyze ~/aiddnet/data/logs/4.4/<прогон>  # пересчитать приёмку по готовому журналу
```

Бот в обоих режимах работает в **частном каталоге данных** `<прогон>/botdata` (свои `live.sock`, `control.sock`, `relations.json`, память, клипы); боевой `~/aiddnet/data/bot`
не используется, не переносится и не удаляется, а в конце прогона стенд сверяет, что он не изменился (список, права, размеры, mtime). Перезапуск сервера на 20% прогона, смена карты на 63-70%;
память судится от базы на 25-й минуте (после заполнения колец задержек) и требует ≥ 35 минут прогона.

**Режим `--real-data` (задача 4.5, репетиция перед первой живой сессией).** Бот идёт через **неизменённый** боевой юнит (drop-in подменяет только путь бинарника и по желанию добавляет `--fly-bundle`),
с `--data-dir ~/aiddnet/data`: настоящие `data/bot/{live.sock,control.sock,clips,memory,last-report.json}`, а боевой веб-юнит читает его мост. Стенд ничего там не переносит, не удаляет и не правит:
до прогона он снимает список каталога и sha256 `relations.json` (копия лежит в каталоге прогона, если файл есть), после прогона проверяет, что ни одна из прежних записей не пропала и не сменила права и что
списки владельца те же (файла не было и он появился пустым из-за правки сайтом — тоже «те же»). Свой веб стенд поднимает как раньше (порт 7790, зритель по WebSocket), а боевой веб только измеряется (`pweb` в журнале, без критериев).
**Задача 4.6:** `--kill-protection N` ставит на время прогона `sv_kill_protection N` на локальном сервере (после перезапуска сервера ставит заново: econ действует до перезапуска; в конце возвращает прежнее и читает обратно), и жизни дольше N минут начинают отбрасывать `Cl_Kill`, так что запасной `/kill` (D-078) работает; проверка живости засчитывает `Cl_Kill`, за которым `/kill` начал новую жизнь, а «0 чата» теперь «0 чата, кроме разрешённого `/kill`». e2e запасного пути: `DDAI_E2E=1 cargo test -p ddai-bot --test e2e_kill_fallback -- --ignored --nocapture --test-threads=1` (ставит `sv_kill_protection 1`, возвращает 20 и читает обратно).
Анализ судит и **живость**: после каждого `Cl_Kill` в течение 50 тиков должна начаться новая жизнь, три и больше `Cl_Kill` без эффекта подряд — провал (сервер молча отбрасывает `Cl_Kill` у жизни старше `sv_kill_protection` минут: бот 93 минуты просидел замороженным, E-011 §3). Для прогона ≥ 5,5 часов анализ судит ещё и **наклон анонимной памяти за последние 5 часов** (Тейл-Сен, пересчёт на 7 суток < 50 МиБ).

```bash
tools/e2e/soak.sh --selftest                                                                   # и помощники --real-data, и анализ умеют падать
tools/e2e/soak.sh --label rehearsal-6h --real-data --duration 21600 --out ~/aiddnet/data/logs/4.5
tools/e2e/soak.sh --label rehearsal-fly --real-data --duration 1500 --fly-bundle ~/aiddnet/data/runs/E-005/e005-fly/checkpoints/final.bundle --out ~/aiddnet/data/logs/4.5
# сайт, пока бот играет (пароль владельца читается из ~/aiddnet/data/secrets, нигде не печатается):
DDAI_E2E_BASE_URL=https://89-58-7-133.sslip.io npx playwright test rehearsal.spec.ts -g "Бот"
DDAI_E2E_BASE_URL=https://89-58-7-133.sslip.io DDAI_REHEARSAL_FLY=1 DDAI_REHEARSAL_HOLD_S=600 npx playwright test rehearsal.spec.ts -g "Муха"
```

`rehearsal.spec.ts` (4.5): вкладка «Бот» на **настоящем сайте** (статус «В игре», карта, режим; `mode passive`/`fight`, `wb off`/`auto`, один `clip` с безобидной заметкой; синтетическое имя-тег в друзья и обратно, `relations.json` как был) и вкладка «Муха»
(живые кадры при боте с `--fly-bundle`, доля сыгранных предложений). Скриншоты — `~/aiddnet/data/screenshots/4.5-*.png`. Без `DDAI_E2E_BASE_URL` пропускается.

Помощники 4.5: `web_twin.py start|stop` — «близнец» боевого веб-юнита (те же песочница и пути, свежее монтирование `data/bot`, порт 7791, свой пароль; боевой юнит не трогается; проверка записи списков, когда боевой юнит подозревается в устаревшем монтировании),
`kill_protection_probe.py` — воспроизведение на локальном сервере того, что `Cl_Kill` не действует после `sv_kill_protection` минут жизни (E-011 §3; значение возвращается).

Сервер `ddnet-local.service` на время прогона занят целиком (стенд отказывается стартовать, если на нём уже кто-то есть); в конце карта возвращается на
`Copy Love Box` и читается обратно (`sv_map`).

`launcher.spec.ts` (задача 5.9, D-089) — запуск бота с сайта на **настоящих** юнитах (`ddnet-ai-launch.path` → `ddnet-ai-launch.service` → бот и спарринг), **только локальный сервер**. Нужен тестовый веб-экземпляр на другом порту (не боевой 7788): копия веб-юнита с теми же ограничениями, рецепт — `deploy/README.md`, «Проверка на этой машине». Тест входит, на вкладке «Бот» выбирает «Гибрид + муха», 15 мин, 2 спарринга, нажимает «Запустить», ждёт «В игре», проверяет через systemd и `/proc`, что бот запущен с `--brain hybrid --fly-bundle … --duration 900`, спарринг 1 и 2 активны, а 3 нет, смотрит «Живой бот» на «Игре», нажимает «Остановить» и проверяет, что всё остановлено; телефон 360x740 без горизонтальной прокрутки. Публичный сервер он не выбирает никогда. Без переменных пропускается. Запуск: `DDAI_LAUNCH_E2E_URL=http://127.0.0.1:7789 DDAI_LAUNCH_E2E_PASSWORD_FILE=<файл с паролем тестового экземпляра> npx playwright test launcher.spec.ts`.
