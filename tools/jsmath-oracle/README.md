# jsmath-oracle — доказательство паритета `ddai-jsmath` с реальным V8

Задача 3.1a. Два маленьких Node-скрипта (stdlib только, без npm-зависимостей — коммитятся, это
часть доказательства, а не одноразовый скрэтч) плюс обёртка `run.sh`, дающие Rust-стороне
(`crates/ddai-jsmath/tests/oracle.rs`) реальные ответы V8 (Node 24.21.0, `/usr/local/bin/node`) на
пробы, которые генерирует сам Rust-тест.

## Файлы

| Файл | Назначение |
|---|---|
| `probe.mjs` | Универсальный раннер: манифест (`{functions:[{name,op,arity,ret,count},...]}`) + бинарные `<name>.in.f64` (входы, little-endian f64, по строкам) → бинарные `<name>.out.{f64,i32,u32}` (реальные ответы V8). Покрывает все 25 «скалярных» функций из задачи (semantics + fdlibm + `pow` + `opp_seed_next`) плюс n-арные `hypot`/`max`/`min`. |
| `rng_probe.mjs` | Гоняет настоящий `Rng` из `tools/ts-reference/src/nn/rng.ts` (до задачи 5.4 — `src/nn/rng.ts`; импортирует файл как есть — Node 24 умеет запускать `.ts` напрямую через type-stripping, см. `docs/research/orig-plan.md` §2.4) по фиксированному чередующемуся паттерну вызовов (`nextU32`/`nextFloat`/`nextGaussian`, `i % 5`), чтобы упражнять и «свежий», и «взятый из spare» путь `nextGaussian`. |
| `run.sh` | Собирает и гоняет `cargo test --release --test oracle -- --ignored full_oracle_vs_real_v8` (≥ 10⁶ проб на функцию) + `tests/perf.rs`'s `perf_report`; с `--fixture` — ещё и `regenerate_golden_fixture` (переписывает `crates/ddai-jsmath/tests/fixtures/golden.bin`/`.sha256`). |

## Почему раздельно от Rust-стороны

Проверяемый инвариант («что оракул должен доказать») — вся генерация проб (какие числа гонять,
сколько, по какой стратегии: случайные биты / диапазоны бота / adversarial-точки) живёт **в
Rust** (`crates/ddai-jsmath/tests/oracle.rs`), одним и тем же кодом что для полного прогона (≥ 10⁶),
что для маленькой золотой фикстуры, что для сравнения с самим собой при перегенерации фикстуры —
так «фикстура была сгенерирована тем же скриптом, что её проверяет» (требование задачи) верно
буквально, не по договорённости. Node-скрипты здесь — чистые «оракулы»: берут готовые числа,
считают то же самое выражение на `Math.*`, отдают биты назад. Ничего не генерируют и не решают
сами.

## Запуск

```bash
cd tools/jsmath-oracle
./run.sh              # полный прогон (≥ 1e6 проб/функция) + перф-отчёт
./run.sh --fixture    # + переписать золотую фикстуру (после смены генератора проб / rng.ts)

# Точечно:
cd ../../crates/ddai-jsmath
cargo test                                                    # golden fixture (без Node, это CI)
JSMATH_PROBES=100000 cargo test --release --test oracle -- --ignored full_oracle_vs_real_v8 --nocapture
JSMATH_NODE=/usr/local/bin/node cargo test --release --test oracle -- --ignored --nocapture
```

`JSMATH_PROBES` — сколько проб на функцию гонять в полном прогоне (по умолчанию 1 000 000).
`JSMATH_NODE` — путь к `node`, если не тот, что первый в `PATH` (по умолчанию просто `node`).
`JSMATH_SCRATCH_DIR` — куда писать временные файлы проб/результатов (по умолчанию — системный
временный каталог, `{full-run,fixture-gen}` внутри; F7-фикс после ревью: раньше был захардкожен
путь одного конкретного деплоя, `~/aiddnet/data/research/jsmath-scratch/` — теперь тесты работают
на любой машине без правок; на этом сервере всё равно можно явно указать эту переменную, если
удобнее держать скрэтч по проектному соглашению, см. `docs/PLAN.md`); не коммитится в любом
случае.

## Результат последнего полного прогона

Node v24.21.0, V8 13.6.233.17-node.53 (`node -p process.versions.v8` на этой машине).

- 25 функций (`round trunc floor ceil abs sign sqrt max2 min2 hypot2 rem imul to_int32 to_uint32
  shl shr ushr sin cos tanh atan exp log atan2 pow opp_seed_next`) — по 10⁶ проб каждая —
  **0 расхождений**, каждая.
- 18 доп. n-арных вариантов `hypot_n`/`max_n`/`min_n` (n ∈ {0,1,3,4,5,8}) — по 20 000 проб каждая
  — **0 расхождений**.
- `Rng` — 10⁵ сидов × 1000 бросков (чередование `nextU32`/`nextFloat`/`nextGaussian`, упражняет
  и «свежий», и «взятый из spare» путь Гаусса) против настоящего `tools/ts-reference/src/nn/rng.ts` — **0
  расхождений**.
- `tests/pow_literal_args.rs` (находка ревью F1) — `pow(2.0,·)`, `pow(4.0,·)`, `pow(0.5,·)`,
  `pow(8.0,·)`, `pow(·,-1.0)`, константа буквально в месте вызова (не аргументом), по 10⁶ проб
  каждый — **0 расхождений**.
- Полная актуальная разбивка перф-замера и подробности по каждой из этих цифр — README крейта
  (`crates/ddai-jsmath/README.md`, разделы «Доказательство» и «Замер производительности»); эта
  таблица не дублируется здесь, чтобы не расходиться при обновлении одного из двух файлов
  (ревью round 1, F4: раньше обе ссылались на «см. BUILD REPORT», который не коммитится).
